# 视频 ROI 裁剪规则

ROI（感兴趣区域）指视频中需要保留的画面。本文规定裁剪行为；工具实现、媒体检查和人工查看情况分别记录，不能相互替代。

## 1. 处理范围（默认）

默认处理 `data/videos/` 下的 **所有源视频**。保留已有划分，test 产物继续遵守既有隔离与使用约束；ROI 处理完成不构成开发比较或模型测评的授权。

## 2. 规则

### 2.1 画面范围

每个视频使用一个固定裁剪范围，覆盖视频全过程。裁剪后的画面应保留试样、上下夹具，以及判断断裂过程所需的信息。

- **固定框：** 宽高比为 3:4，不能超出原画面。框的宽和高均为正的偶数像素。
- **选框：** 检查整个视频，确保画面能保留回弹、滑移、脱夹和碎片等相关变化。不要只看一帧就确定范围。
- **固定框放不下时：** 先调整或扩大裁剪框；仍放不下所需信息时，改用全画面补边。
- **全画面补边：** 保留原画面，不拉伸或缩放。将画面居中并补黑边，形成能容纳原画面的最小 3:4 画布。画布的宽和高均为偶数像素。

记录最终裁剪框和源视频分辨率。如果选框因比例或像素要求发生调整，须展示调整后的范围供审核。本文不规定动态 ROI。

### 2.2 审核画面

标签默认预填现有标注信息，用户可在 ROI 界面直接修改；只有主动保存时才写入独立的 ROI 审查记录，源标注表不更改。审查记录绑定视频和 ROI 输出身份，身份变化后须重新核对，失效记录不得误套到其他视频或输出。无需逐项重新选择或强制确认标签。标签含义见[断裂标签说明](label.md)。

已有裁剪结果核对身份后优先原样保留。用户可直接查看裁剪画面，有问题再调整范围；无需为每个视频点击通过，也不要求填写逐项审核结果或观看区间。

- **画面检查重点：** 对照原视频查看裁剪范围，关注试样、夹具、断裂、回弹及飞散等信息是否保留。
- **原视频看不清：** 保留可见信息并记录已知限制，不强行得出确定结论，也不因此丢弃视频。
- **状态记录：** 媒体处理完成与人工查看情况分别记录。未人工复核的结果不得写成已审核；用户发现的问题须记录，调整后保留新旧结果的对应关系。

### 2.3 预览视频

浏览视频的开头、中间和结尾，重点检查断裂、回弹、脱夹和碎片飞散等过程。预览应支持拖动、连续播放和查看相邻帧。

有可靠的断裂帧号、时间点或时间范围时，可用来定位。没有这些信息时，通过人工浏览审核，无需补造时间。帧号与时间的换算及时间范围的含义见[断裂标签说明](label.md#9-断裂时间范围)。

查看画面时可按需记录位置和问题，不强制填写。预先生成的预览点只能帮助定位，不能证明所有关键过程都已看过。

### 2.4 生成与验收

输出视频应保留源视频的完整时长和帧顺序，不主动抽帧、插帧或变速。输出方向须正确，裁剪坐标与画面方向一致，分辨率符合裁剪框或补边画布。

验收时检查：

1. 视频能正常解码；方向、分辨率正确，帧数与源视频一致。
2. 帧率和时长与源视频的差异在下列范围内：
   - **标称帧率：** 差值不超过 `max(1e-6 × max(源帧率, 输出帧率), 1e-9 fps)`。
   - **时长：** 差值不超过 `max(0.02 秒, 1/max(源帧率, 1 fps) + 0.005 秒)`。
3. 提供实际裁剪画面供按需查看，重点关注局部裂纹、层间变化和快速运动；人工查看不作为逐视频确认的强制步骤。

沿用历史结果时，若源视频与输出文件的摘要均与冻结记录一致，且冻结记录中的源与输出帧数、时长及标称帧率相符，可依据该记录核对标称帧率。当前探测工具给出的帧率估计差异须单独记录，不能将不同估计值视为满足上述数值容差；此方式也不包含逐帧时间戳比较。

帧数、帧率和时长通过检查，不代表逐帧时间戳完全相同，也不代表画面细节无损。如果帧率、方向或时间属性无法可靠核实，应标记为待核实，不能用默认值代替。

## 3. 输入

- **源视频：** 默认读取 `data/videos/`。每个视频须有唯一 ID，记录路径、SHA-256、分辨率、帧率、帧数、时长和方向。无法可靠获取的属性须注明。
- **标签与辅助资料：** 现有标注信息用于预填标签；已有的 ROI 决定、断裂帧号或时间可辅助选框和查看。新视频缺少这些资料时仍可进行 ROI 处理。
- **可选已有裁剪结果：** 可提供已裁剪的视频，以及来源、裁剪决定和输出记录。确认来源与当前源视频一致、裁剪文件摘要与旧记录相符后，直接保留该裁剪结果；不因记录框与新裁剪命令的精确坐标处理不同而自动重裁。须如实记录旧结果的实际范围；无法可靠还原时保留原记录并注明不确定性，不能把记录框冒称为实际生效框。

所有视频使用同一入口，工具根据是否已有裁剪决定处理：

| 情况 | 处理方式 |
| --- | --- |
| 已有裁剪结果的来源和输出身份可核对 | 直接沿用并提供画面查看；保留旧参数及实际范围信息，不自动标为已人工复核。 |
| 只有已有决定，且与当前视频一致、裁剪框合法 | 加载决定继续处理。路径变化时，用文件摘要和媒体属性核对身份。 |
| 没有该视频的决定 | 正常进入选框，保存范围后继续生成，无需填写标签审核表。可以从全画面开始选框。 |
| 当前视频与旧决定或旧输出的来源身份不一致 | 按当前视频选框或生成新结果，不能直接套用旧输出，也不能只替换摘要。 |
| 暂时无法选框或处理 | 保留进度及待处理原因。 |
| 视频缺失、无法读取，或 ID 冲突无法解决 | 停止该视频的生成，并在汇总中说明原因。 |

已有决定和待选框的视频应在同一工作列表中显示各自状态。

## 4. 输出

### 4.1 输出路径

建议保存到 `data/roi/`，与原视频和原标注分开。最终目录组织由实现说明确定。处理或重试时，不覆盖原视频、原标注或身份不一致的已完成输出。

### 4.2 输出内容

1. **ROI 视频：** 每个完成的视频输出一份完整的裁剪视频或全画面补边视频。
2. **裁剪参数：** 记录视频 ID、源视频尺寸、处理方式、实际生效范围，以及上、下、左、右各裁去的像素数。保留已有结果时区分原记录框和实际范围；无法确认的值明确注明，不能编造。全画面补边时，四个方向的裁剪量均为 0；另记录各方向的补边像素数和输出尺寸。
3. **处理清单和汇总：** 列出每个视频的处理状态和原因，如已沿用、已生成、待选框、待核实或失败，并统计完成和未完成的数量。存在未完成的媒体处理项时，不能报告全量完成；人工查看情况单独记录。

为追溯结果，清单还需记录：

- 源视频路径、摘要、媒体属性和已有划分。
- 规则版本、沿用或生成方式、已知限制，以及已有的人工查看记录或问题。
- 主动保存的独立 ROI 审查记录，以及其绑定的视频和输出身份。
- 输出路径、摘要、编码配置和验收结果。

保留已完成工作和未完成清单，临时文件不能当作验收结果。输入、裁剪决定、编码或查看规则变化时，重新判断受影响的结果是否有效，并保留追溯记录。

**失效条件：** 标签定义、画面比例或几何策略、视频时间处理、编码验收或审核规则发生实质变化时，重新审查对应内容。本文被新 ROI 规则完整取代后作废，并明确替代关系。
