# 视频 ROI 裁剪规则

**状态：待用户审查的规则稿。** 本文规定视频 ROI 的处理逻辑与验收边界，不表示相应工具已经实现或真实视频已经通过验收。

ROI（Region of Interest，感兴趣区域）是画面中需要保留的试样及相关观察范围。ROI 处理的目标是在减少无关背景的同时，保留判断断裂状态、断裂模式、断裂位置、异常情况和断裂现象所需的画面证据。

## 1. 处理对象与范围

ROI 对完整源视频进行空间裁剪或补边，每个源视频使用一个固定画面范围，覆盖整段视频。处理不切除时间片段，不改变帧的先后顺序，也不负责生成子视频或确定子视频标签。

输入清单中的所有源视频均纳入处理，不按 train、val 或 test 筛选。已有数据划分随源视频保留，ROI 不重新划分数据；测试集产物继续遵守原有隔离和访问约束，完成 ROI 处理不表示可将其用于开发比较或模型测评。

原视频和原标注保留。ROI 审核记录描述画面处理及证据保留情况，不直接改写源视频标签；标签名称与判断含义以[断裂标签说明](label.md)为准。

## 2. 输入要求与统一处理流程

输入至少包括可读取的源视频及其唯一视频 ID。源视频清单应记录文件路径、文件内容摘要（SHA-256）、分辨率、帧率、帧数、时长及方向信息；无法可靠获取的属性须明确记录，不能编造默认值代替。

ROI 决定和标签、事件帧号、事件时间等辅助资料均可随视频提供。**没有已有 ROI 决定是正常输入情况，不能因此报错终止。** 标签和时间资料用于辅助检查，有无这些资料不改变选框、审核和输出校验的规则。

所有视频使用同一入口和流程，用户无需选择不同处理模式来区分决定是否已存在。工具逐条核对输入并进入对应步骤：

| 输入情况 | 处理规则 |
| --- | --- |
| 有与源视频身份一致、几何合法且审核仍有效的 ROI 决定 | 加载决定，按其记录继续处理。文件路径改变本身不等于视频内容改变，仍须依据内容摘要及媒体属性核对。 |
| 没有 ROI 决定，或决定集合中缺少该视频 | 进入选框与审核，允许选择固定框或保留全画面；保存决定后继续处理。 |
| 决定绑定的源视频内容、分辨率或方向不一致，或审核依据已失效 | 标记待复核，展示已有信息供参考；重新核对并确认决定后继续处理，不能只替换摘要使其通过。 |
| 当前无法完成人工选框或审核 | 保存为待处理项，说明缺少的操作并保留进度；不能当作裁剪成功，也不能仅因缺少决定而崩溃。 |
| 源视频缺失、无法读取，或视频 ID 存在无法消解的冲突 | 记录实际输入问题，停止该条目的媒体生成；汇总中明确列出。 |

缺少决定时，可以先展示全画面作为选框起点，但不能自动将其认定为已经批准的 `no_crop`。如果输入中同时包含已有决定和待选框视频，应在一个工作列表中呈现各自状态，无需用户重新组织输入。

## 3. 画面范围与几何规则

### 3.1 固定裁剪框

固定框使用精确 **3:4（宽:高）** 比例。有效像素框必须位于源画面内，宽高为正的偶数像素，并保存实际生效的像素坐标及对应源分辨率。界面选择值经过比例或像素对齐调整后，须展示最终生效范围供审核。

框的大小以保留证据为先，应覆盖全过程中所需的试样、上下夹具及其相对运动范围，包括断后回弹、滑移、脱夹和碎片等相关变化。不能只在某一帧上框住试样，就认定整段视频可用。

固定框无法容纳所需证据时，先调整或扩大框；在源画面边界内仍无法满足时，改用保留全画面并补边。本文不规定随时间移动的动态 ROI。

### 3.2 保留全画面并补边

`no_crop` 保留原画面的完整可见内容，居中补黑边至可容纳源画面的最小偶数像素、精确 3:4 画布，不拉伸或缩放原画面。

补边不能补回源视频中原本没有拍到的内容，也不能代替画面审核。固定裁剪和全画面补边均须通过相同的证据保留检查。

## 4. 审核怎样保留五类标签的证据

审核要比较源画面与拟保留画面，并在生成后核对实际输出。审核对象包括上下夹具、完整试样、相对位置及断裂过程，但不能要求每条视频的所有判断都必须明确成立。

| 判断对象 | 需要检查的画面 |
| --- | --- |
| 断裂状态 | 开始阶段的连通或分离、首次可见分离及断后两端；不能因出画或遮挡而制造“未断裂”的印象。 |
| 断裂模式 | 断前塑性变形、局部形态及相关部位或阶段；不能只保留断后形态却沿用依赖断前过程的确定结论。 |
| 断裂位置 | 断裂发生时及前后的试样、上下夹具和夹持边界关系；断后回弹或滑落不能替代断裂时的位置证据。 |
| 异常情况 | 判断未夹紧所需的相对滑移、原拍摄问题以及爆炸性断裂的碎裂和飞散范围。 |
| 断裂现象 | 判断伸长、颈缩、开裂、界面分离和断后脱夹所需的局部细节、过程及夹具关系；异常和现象逐项检查。 |

各项审核记录使用以下含义，并附必要说明：

| 审核结果 | 含义 |
| --- | --- |
| 可判断 | 已检查，保留画面足以支持该项判断；不表示某个异常或现象一定出现，也可以支持“未出现”。 |
| 证据不足 | 已检查，但无法可靠判断；须注明源视频本身不足、ROI 处理造成损失，或原因尚待核实。 |
| 不适用 | 根据标签规则，该项无需作对应类别判断。例如未断裂或未夹紧时，模式、位置按规则为“无”。须记录依据，不能用来跳过难判项目。 |
| 未检查 | 该项尚未审核；不能当作“否”“无”或已通过。 |

源视频原本存在证据不足时，ROI 应保留其可用信息并记录限制，不能为了得到确定标签而丢弃视频或强行通过。若证据不足由裁剪或编码造成，应调整画面范围或处理设置后重审；不能把处理造成的损失写成源视频的“视频异常”，也不能直接修改原标签来适配输出。

审核完成要求是：适用项已检查，已知证据限制有明确来源，且未发现尚未解决的 ROI 证据损失。原视频本身无法确定的项目可以保留该限制；原因尚待核实或仍未检查的项目保持待复核。ROI 审核通过只说明画面处理符合上述要求，不证明源标签一定正确，也不自动确认后续子视频的标签。

## 5. 预览与时间信息

预览应覆盖开头、过程中的代表位置和结尾，并允许连续浏览、拖动定位及检查相邻帧。有可靠的事件帧号、时间点或范围时，用其辅助定位断裂前后及相关变化；只有范围时，不把范围中点当作精确断裂时刻。

没有可靠时间资料时，仍可通过浏览视频完成选框和审核，无需人为补造事件时间。帧号与时间的换算须使用对应视频的实测信息；变帧率视频按单一帧率换算的时间只能视为估算。

审核应覆盖可能改变判断的运动、断裂、回弹、脱夹或飞散过程。稀疏预览点只能辅助定位，不能证明已覆盖所有关键现象。记录实际检查的时间点或区间及必要备注，不能将自动生成的预览点直接视为已观看证明。

## 6. 视频生成与输出验收

ROI 输出保留完整源视频的时间范围和帧序，不主动抽帧、插帧或变速。画面方向须正确，坐标解释与实际输出方向一致；输出分辨率符合最终固定框或补边画布。

建议的初始编码配置为 H.264、`preset=fast`、`CRF=23`、`yuv420p`，去除音频并设置方形像素。该配置需要通过真实视频的细节与时序检查后，才能作为经过验收的默认配置；重新编码不能称为像素无损，去音频后的 ROI 产物只承担视觉输入用途。

输出验收包括：

- 视频可解码，分辨率及方向正确，帧数与源视频一致。
- 标称帧率与源视频按相对容差 `1e-6`、绝对容差 `1e-9 fps` 比较：两者差值不超过 `max(1e-6 × max(源标称帧率, 输出标称帧率), 1e-9 fps)`；时长差值不超过 `max(0.02 秒, 1/max(源标称帧率, 1 fps) + 0.005 秒)`。
- 实际输出通过第 4 节的证据保留检查，尤其关注局部裂纹、层间变化和快速运动；不能只验收几何与媒体属性。

媒体属性符合要求不能单独证明逐帧时间戳相同、细节无损或所有关键现象都可辨认。源视频的帧率、方向或时间属性无法可靠核实时，该条目保持待核实，不用名义默认值使其通过。

## 7. 输出记录与异常边界

每个视频的结果应能追溯到源视频和生效的 ROI 决定。输出包括 ROI 视频、决定记录及处理清单，并汇总成功、待审核、待核实和失败条目。文件组织可由工具确定，但至少保留以下信息：

- 视频 ID、源文件路径与摘要、源媒体属性，以及已有划分标识。
- 处理方式、生效像素框或补边参数、规则版本、审核结果与证据限制、实际检查位置和备注。
- 输出文件路径与摘要、编码配置、媒体属性检查和画面审核结果。

缺少 ROI 决定属于待准备状态；视频缺失、解码失败、身份冲突或生成失败属于需要明确说明的实际问题。工具应保留已完成工作和未完成清单，不能静默遗漏条目，也不能在仍有未完成项时报告全量完成。完整结果必须覆盖输入清单中的每个视频 ID，并说明每条的处理状态。

生成中的临时文件不能冒充已验收结果；失败重试不能覆盖原视频、原标注或身份不一致的已完成输出。输入内容、决定、编码设置或审核规则发生变化时，应重新判定受影响结果是否仍有效，保留可追溯记录后再处理。

## 8. 规则有效性

本规则在用户审查确认后作为 ROI 行为依据；具体命令名称、参数和存储格式由实现说明定义，不改变本文的画面保留与审核要求。

**失效条件：**标签定义、画面比例与几何策略、视频时间处理方式、编码验收要求或证据审核规则发生实质变化时，对应章节须重新审查；本文件被新的 ROI 规则完整取代后作废，届时须明确其替代关系，避免同时使用冲突规则。
