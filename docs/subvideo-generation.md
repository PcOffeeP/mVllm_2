# 本轮子视频生成规则

本轮从已有 ROI 视频生成开发集候选片段，供人工标注和后续数据发布。本文记录已确认的规则；帧对应检查和时间范围选窗正在落实，不能据此认定新规则已完成批量生成或验证。已完成的 813 个片段属于[旧窗口加严初裁](subvideo-initial-results.md)。整体迁移按[迁移审查大纲](migration-review-outline.md)推进。

## 1. 输入、输出与处理范围

| 输入 | 当前位置及用途 |
| --- | --- |
| 源视频与标注 | `data/videos/`、`data/annotation-table-full.csv`；提供视频身份、断裂帧或时间范围及源级标签。 |
| ROI 结果 | `data/roi/videos/`、`data/roi/manifest.json`；提供裁剪输入、来源与输出摘要、ROI 范围和处理记录。 |
| 固定划分 | `data/splits/three-fold/` 的七个成员 JSON；片段继承源视频的三折归属，不重新划分。 |

只生成开发集片段，测试集媒体不参与本轮生成。完整视频处理在训练机执行，运行前核对机器状态、环境和输入身份。

每轮显式指定新的输出目录，保留片段视频、来源与帧区间、三折归属、生成规则和摘要，以及跳过或失败原因。本轮沿用简洁的输出形式：

```text
<本轮输出目录>/
├── manifest.json              # 来源、窗口、结果身份和审核状态
├── summary.json               # 生成数量、窗口分布及跳过原因
└── videos/<候选ID>.mp4         # 候选片段
```

新结果使用独立目录，不覆盖源视频、ROI 或已有初裁。标注和结构化记录进入 Git，视频与运行锁留在 Git 外。实际入口与恢复方式见[生成工具说明](../script/subvideo_pilot/README.md)；新增帧对应记录的具体字段随实现核对。

## 2. 精确断裂帧与时间范围分别选窗

有精确断裂帧的视频继续使用原标注帧，不扩展成时间段。`断裂帧_前` 是最后一帧仍连通的画面，`断裂帧_后` 是第一帧已分离的画面，并作为事件锚点；帧号从 0 开始。标注时间可以辅助定位，不能用标称帧率重新推算并替换已确认的帧号。

只有断裂时间范围的视频，使用已有下界和上界，不取中点冒充精确时刻：

| 窗口 | 有精确断裂帧 | 只有完整时间范围 |
| --- | --- | --- |
| 断裂前 | 整个片段不晚于精确事件前 0.5 秒结束。 | 整个片段不晚于范围下界前 0.5 秒结束。 |
| 包含断裂 | 包含事件锚点及判断所需的前后画面。 | 覆盖整个断裂时间范围及判断所需画面。 |
| 断裂后 | 整个片段不早于精确事件后 0.5 秒开始。 | 整个片段不早于范围上界后 0.5 秒开始。 |

范围上下界的画面含义按[标签说明](label.md#9-断裂时间范围)执行。用户已确认范围两侧各留 0.5 秒保护间隔；断后源素材余量从上界后 0.5 秒开始检查。边界换算为包含或排除哪些帧仍须在实现中核对，通过实际帧对应检查后才生成。只有单侧边界或无法可靠定位的记录保留原因，不补造缺失时间。

用户已确认：新一轮精确断裂时刻窗口先沿用旧规则，尝试 2、3、5、10、20 秒目标时长，事件前后各留 0.5 秒保护间隔，并沿用旧的各类窗口数量上限。只有画面对应检查通过后才生成。时间范围窗口仍按表中的上下界及两侧 0.5 秒保护间隔选取；实际片段受素材长度、帧对齐和窗口规则限制，不保证每个源视频生成所有时长。

事件后窗口还必须满足：**跳过保护间隔后，至少有 2 秒可用源素材**，素材末端不能只凭容器声明时长判断。这与每个片段的时长不同；用户已确认短于 2 秒的片段可以保留，当前不新增“每片至少 2 秒”的限制。

## 3. 用两段独立重放验证画面对应

本轮不再把约 0.033 毫秒的固定帧率时间格误差作为通用拒绝条件。自动生成候选时，需要验证原视频、现有 ROI 和子视频之间的完整帧对应，记录标注帧在片段中的位置。

| 核查段 | 通过条件 |
| --- | --- |
| 源视频 → 现有 ROI | 核对文件与决定身份，再按记录的固定裁剪或补边方式从源视频重放。重放文件须与现有 ROI 文件精确一致，全部解码帧的画面及时间对应也须精确一致。 |
| ROI → 子视频 | 按确认后的帧区间裁剪；再用独立取帧方式（`select`，区别于裁剪使用的 `trim`）重放同一区间，核对结果文件及全部解码帧的画面、时间和顺序一致。 |

任一段重放失败或不一致，都列为待核实，不自动通过；不以图像相似度或相同帧数兜底。片段起止帧、事件锚点或范围边界、播放时间与源视频的对应关系写入记录，不能直接把原秒数套到新的时间轴。

严格重放代码已通过合成测试和独立代码核查；真实训练机批次尚未运行，不能把这些检查写成当前媒体已通过。只有取得两段实际重放证据的候选，才记录为帧对应验证通过；最终标签仍需人工看片确认。

## 4. 三个特殊视频暂不生成子视频

`video_0002`、`video_0015`、`video_0050` 单独保留，后续再讨论使用整段还是生成片段。本轮不据旧时间记录自动裁剪，也不自动改写它们的当前标签。

其他异常、无法确定或规则暂不支持的来源，同样保留源记录和处理原因。来源无法按已确认规则可靠选窗时暂不生成；生成候选不表示已经准入训练或评价。

## 5. 候选标签、审核与发布

源视频标签只作参考，片段最终标签依据片段画面填写本轮五类标签。窗口名称及旧几何辅助标签不等于最终标签；所有拟发布片段都须人工审核，未审核片段不进入正式发布。

时间、帧号和范围用于选窗与追溯，当前不构建时间预测训练任务，也不评价模型预测时间标签的表现。媒体可读、完整解码或结构检查通过，分别记录其覆盖范围，不能替代画面审核、模型采样检查或模型效果评价。

发布先覆盖开发集三折训练／验证数据，并保留片段、源视频、标签、审查决定和媒体摘要的对应关系。具体发布接口按后续迁移工作落实；候选不会自动晋级为发布数据。

**失效条件：** 标注含义、固定划分、源或 ROI 身份、窗口边界、帧对应判据或发布准入发生变化时，更新本文与受影响记录，并重新核对对应结果。历史初裁只用于说明当时规则及结果，不替代新一轮验收。
