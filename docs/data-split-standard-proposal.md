# 新五类标签的数据划分标准：供确认的讨论稿

**本稿讨论如何为新五类标签确定划分标准，尚未确定需要重划，更未批准实施。当前已确认的基线仍是保留既有开发集 89 个源视频、测试集 21 个源视频及现有三折清单。** 若用户希望调整，应先决定测试集边界，再确认覆盖目标、不可行时的处理和实施范围。

依据是[分布核查](data-split-distribution-audit.md)：在现存旧元数据下，旧稀有池、分层测试配额与三折块大小可检查一致；新标签却增加了独立的异常与现象字段，旧混合 `type` 不能直接代表新五类任务。现有清单的部分标签在 test 或验证中无正例，需要说明可评价范围。这些观察支持讨论适用标准，不能据此断言旧划分不合格。

**状态：2026-11-07 备选设计，待用户确认。** 本次未创建或执行重划脚本、未输出候选分配、未处理视频、未修改训练或评价接口，也未运行模型。方案确认与实施授权分开；本文不授权使用 test 运行评价。

## 1. 目标与必须保留的边界

本稿希望让后续划分具备可核对的来源、明确的防泄漏边界，以及与实际可用独立源数量相符的标签覆盖。划分质量不应只看总人数接近某个比例：对稀有多标签、未知值、同源片段和已有测试历史，必须说明如何处理以及哪些能力无法评价。

当前范围依据[标签说明](label.md)、[facts.yaml](facts.yaml) DF-018/DF-019 和[迁移大纲](migration-review-outline.md)：

- 模型判别任务为断裂状态、断裂模式、断裂位置、异常情况、断裂现象五类；异常与现象逐子字段处理。
- 断裂时间类标注可以用于子视频生成，当前不为模型时间预测构建训练集，也不评价时间预测。它们不进入本稿拟议的模型标签均衡目标；具体窗口规则仍待确认。
- 既有测试集有历史使用记录，不能表述为从未使用过的独立测试集。重命名、重新打乱或移动旧视频均不能消除已有暴露。
- 保护原始视频、标注和既有清单。本稿不覆盖或改写它们；未来调整也应保留可追溯的原版本，具体封存格式待确认。

## 2. 首先决定是否允许改变测试集

这项选择会改变数据流和结果可比较性，必须先由用户决定。既有“保留划分”继续有效，下面的备选不是对它的自动替代。

| 选项 | 可以获得什么 | 代价与限制 | 决策状态 |
| --- | --- | --- | --- |
| A. 全部沿用现有清单，补充分布和不可评价项报告 | 保持数据成员和既有开发过程的可追溯性，无需重新分配 | 稀有异常等仍缺少验证或测试正例；不能承诺全面评价 | 当前基线；是否作为新任务最终安排仍需确认 |
| B. 固定现有 21 个 test，仅在 89 个开发源中调整 train/val | 保留测试成员，允许针对新任务改善开发集的多标签覆盖 | 无法补足 test 缺少的正例；验证成员变化使旧开发结果不能直接比较；仅 1 或 2 个独立正例仍不足覆盖三折 | 可讨论，未选择；改变开发集也需确认及实施授权 |
| C. 对全部 110 个源重新设计 test 和开发折 | 有机会在全体独立来源上优化新任务覆盖 | 改变已确认测试边界；既往训练／调参暴露可能随源移动，需逐源记录；旧结果的直接可比较性降低，重划仍无法消除独立正例不足 | 重大待决，不预设采用 |

若保留现有材料却无法满足最终独立测试目标，还可另行讨论收集新增、未暴露的来源作为未来评价材料。这不属于当前实施范围，也不能承诺新增材料必然足够；需另定采集、隔离与使用规则。

即使采用 A，旧模型结果也不能直接视为新标签效果；标签、Prompt、输入处理和评分口径变化都影响比较。采用 B 或 C 时，必须把成员变化与其他变化一起记录，避免把数据集变化造成的差异归因于模型。

## 3. 候选标准如何组织

以下是供确认的规则结构，不是已生效的契约。先区分拟作为硬约束的完整性／防泄漏条件，再讨论在小数据条件下尽力优化的分布目标。不能让“比例更好看”覆盖来源冲突，也不能为了完成配额把不确定改成确定标签。

### 3.1 源级绑定与防泄漏

建议以真实来源组为划分单位，先建立源视频 ID、文件内容身份及来源关系的绑定，再展开到子片段。相同源视频的裁剪、ROI 变体、采样帧和后续训练样本继承同一成员归属；同源派生产物不能跨某一折的 train/val 或跨开发/test。交叉验证中普通开发源可以在不同折分别承担训练或验证，但同一折内必须互斥。

不同 ID 的重复或近似素材、同一试样或同一次试验的多路拍摄，可能需要合并为更高层的来源组。**来源组边界、近似判定方法及冲突处置均待确认**；目前 ID 不交叉不能证明这些检查已通过。素材身份不符或跨分区关联应先形成冲突记录，明确涉及的 ID、原归属、证据与候选处理，再由用户确认移动、隔离、排除或补证；不能默认移动 test 来修复。

模拟数据也应记录原始资产、参数、参考视频及其来源关系。如果模拟生成参考了测试素材，不能仅因文件哈希不同就自动放入训练集。哪些参考关系构成禁止使用的泄漏、哪些仅需披露，应在引入模拟数据前确认。

### 3.2 新五类标签与未知值分开处理

| 对象 | 候选处理 | 仍需确认的决定 |
| --- | --- | --- |
| 状态、模式、位置单选字段 | 分别统计各原值及可评价样本数；审查关键组合，不将旧 `type` 一对一迁为新模式 | 三个字段是否共同作为分层目标、优先级及允许比例偏差 |
| 异常与现象多标签 | 每个子字段分别统计“是／否／无法判断／空白”，兼顾正例独立来源数和关键共现 | 哪些子字段必须覆盖、最低正例数和共现约束；是否接受无法覆盖的分区 |
| `无` | 作为规则下的不适用值独立保留，检查其固定组合；不能当成未知或负例的通用替代 | 是否参与分层优化、哪些指标分母排除不适用值 |
| `无法确定`／`无法判断` | 保留证据不足的身份，单独记录分布；不能为配额改标 | 是否进入训练、以何任务学习、在评价中作为目标或仅报告、是否约束其比例 |
| `无法判读` 标注状态 | 与各字段的已知／未知情况分开看，不能整行自动映射成同一种标签 | 整条或分字段纳入、隔离或排除的条件 |
| 空白／未完成 | 与判读后的未知分离，先列为输入问题 | 是否暂缓进入候选池及补全的责任与证据 |

源视频可能同时具有多个异常和现象。若把全部字段组合成一个大类别，小数据可能产生大量单例，无法同时维持各分区覆盖；若只平衡一个字段，其他任务又可能失衡。候选做法是分别报告各标签边际分布，选择有评价意义的关键共现作为附加目标；具体目标集合与权重必须由用户确认，不能由旧算法默认决定。

标签组合与[标签说明](label.md)矛盾时，先记录原值和触发规则，回到证据核查，不自动修标。源标签与子片段标签不同也不一定冲突：片段按自身可见证据复核，不能把源级的“发生断裂”或某现象“是”无条件复制到所有窗口。

### 3.3 稀有标签覆盖与不可行性

旧规则以混合 `type` 的总数不超过 2 定义稀有池，并永久只训练。新任务下不能默认沿用同一阈值或永久训练政策。候选稀有判据可依据独立来源组的正例数、每个候选分区能否形成有效分母，以及未知比例来讨论；阈值、按字段还是按共现组合识别稀有、是否允许固定训练池，全部待确认。

一个条件性算术例说明为什么不能先硬定全面覆盖：**若**要求一个测试集和三个互斥验证折各至少有 1 个正例，且这四部分使用互不相同的源组，至少需要 4 个不同正例源组。当前 `异常_未夹紧` 全体仅 1 个、`异常_爆炸性断裂` 仅 2 个正例源视频；来源合组后独立数还可能更少。这样的要求必然不可行。此例仅解释数量约束，**不是已确认的最低阈值**。

同一源切出更多片段不能增加独立正例源数；片段的现象还需自身证据支持。重复采样也不能把验证或测试的独立正例数变多。是否可以报告片段级结果，需同时报告来源数和相关性限制，不能以片段条数掩盖来源不足。

| 不可行时的备选 | 可解决的问题 | 必须接受的限制 |
| --- | --- | --- |
| 保持来源互斥，允许某标签在某些分区缺项 | 不制造跨分区重复 | 相应正例指标报告不可估计或不适用；具体表示和汇总规则待确认 |
| 仅在部分开发验证安排中评估稀有标签 | 在已确认权限内利用少数正例 | 不能声称每折或测试都验证了该能力；如何汇总和防止调参过度待确认 |
| 某些稀有来源只用于训练 | 给训练保留可见案例 | 缺少独立正例评价证据，不能宣称能力已验证；不能默认旧六个 ID 永久适用 |
| 另行收集独立来源，延后相应结论 | 有机会增加真正独立的证据 | 增加采集成本和周期，当前不能据此宣布覆盖完成 |

这些选项不能自动互相替换。发现目标不可行时，应输出缺口与候选让步，由用户决定；不得悄悄改变比例、复用源组、合并“无”和未知，或删除难样本使指标变好。

### 3.4 分布目标与重现性

若授权设计新的成员分配，可把分区规模、状态／模式／位置的边际分布、异常／现象正例覆盖、未知比例和关键共现分别列为目标，先检查硬约束可行性，再比较目标偏差。**本稿不指定优化算法、目标权重、测试比例、折数、容差或随机种子。** 旧文件的 0.2、3 折、seed 42 与 `ceil` 切块属于历史身份，不自动成为新标准。

建议未来每次候选保留以下审计材料，具体格式和落点待确认：

- 输入 CSV、源视频清单、来源组、标签规则与原划分的哈希，以及代码提交与必要运行环境。
- 明确版本的划分规则、所有阈值／权重／优先级、种子、排序和随机过程；记录不可行及人工例外，不只记录最终 ID。
- 每份清单的成员、计数、方法、规则版本、父版本和哈希，并将这些文件与同一运行的输入快照绑定。
- 每个被移动、隔离、排除的来源及原因，尤其曾进入训练／验证／测试的历史身份；记录未知的暴露情况。

本次发现旧 JSON 与当前旧代码 `_split_payload` 的部分元数据格式不一致，且未证实旧清单和旧元数据属于同一运行。这说明仅有 `seed: 42` 不足以证明重现性。未来既要验证相同输入与配置可重复产生相同输出，也要保留把实际输出绑定到实际输入的证据。

## 4. 如何判断候选是否可用

以下是候选验收结构；其中需要数值或业务取舍的项目必须在实现前确认。

| 检查层次 | 应提供的证据 | 边界 |
| --- | --- | --- |
| 输入与集合完整性 | 无重复成员、计数一致、适用输入完整覆盖；纳入／隔离／排除清单各有解释 | 排除策略待确认，不能用静默丢行满足覆盖 |
| 来源互斥与泄漏 | 每折 train/val、开发/test 无来源组交叉；同源派生归属一致；模拟参考关系及跨 ID 疑点有处置记录 | 仅 ID 互斥或哈希不同不能代替全部素材级检查 |
| 多标签分布 | 每分区每标签的原值、已知正负例、未知、不适用、独立来源组数；关键共现与目标偏差 | 最低数、比例容差、权重和缺项汇总口径均待定 |
| 旧新差异 | 成员迁移表、测试暴露历史、原结果可比较性说明 | 新清单不能称为消除了旧测试污染 |
| 重现与记录 | 输入与输出哈希、规则版本及同一运行绑定；重复执行的差异检查 | 静态检查与真实运行分别报告 |
| 片段生成后的复核 | 继承源归属，核验片段自身标签、独立源数与最终可评价分母 | 源级标准通过不保证片段标签正确，也不保证模型效果 |

标准讨论、候选清单完整性、片段复核、真实训练与模型效果是不同证据阶段。没有真实预测、指标和日志时，不得据划分均衡宣布模型性能改善。

## 5. 决策与实施的顺序

下列是获授权后的候选迁移步骤，当前没有启动：

1. 用户先决定沿用 A、固定 test 后讨论 B，还是允许讨论 C；若不改变决定，则继续既有基线。明确是否允许任何来源成员移动及测试历史的报告方式。
2. 确认来源组边界、新五类目标、未知／不适用／无法判读用途、稀有判据、不可行处理、分区规模与折数。与[整体模型测评设计](design-test.md)同步分母和可评价范围。
3. 在输入身份与实施授权具备后，再实现获准的检查或候选生成工具。先封存基线和输入绑定，保留旧入口；不在本文阶段编写脚本或试分配。
4. 候选产生后，提供完整成员、分布、来源冲突和与基线的差异，由用户审阅重大例外及是否接受；不以目标函数得分自动批准。
5. 仅在发布／接入授权具备后冻结所选版本，调整下游引用并验证。若授权范围不含测试使用，则继续隔离 test。
6. 在获准的 ROI 和子视频生成完成后，对实际片段重新做来源归属、视觉标签和覆盖核查。随后按单独授权开展训练和评价，不能用源级分布代替该阶段证据。

## 6. 用户需要确认的具体选择

| 待决事项 | 决策会改变什么 |
| --- | --- |
| 是否维持全部既有清单，或仅调整开发折，或允许涉及 test 的完整重划 | 数据成员边界、历史可比较性与测试使用约束 |
| 来源组按原视频、试样／试验、多路拍摄还是其他关系绑定；重复与近似如何处置 | 独立样本数、防泄漏条件及冲突条目的移动／隔离权限 |
| 分区规模、测试比例、折数与各标签目标优先级／权重 | 覆盖与分布之间的取舍，是否需要改变旧三折形式 |
| 未知、不适用、无法判读、空白的训练与评价用途 | 候选池成员、分层目标、指标分母和报告范围 |
| 稀有阈值、最低独立正例数、是否保留固定训练池 | 哪些能力具备独立评价证据，哪些只能作为训练或待补充材料 |
| 数量不足时允许哪些缺项、指标如何标记与汇总、是否另行采集 | 不可行目标的让步及结论边界 |
| 规则版本、快照绑定、审计输出及候选审批方式 | 后续实现接口、可追溯性与发布验收方式 |
| 实施范围及测试使用时机、候选准入、频率 | 方案确认后实际允许执行的动作；当前不预设开放 test |

这些项目尚未确认，本稿中的候选规则不能被下游当作生效配置。当前可直接使用的是[分布核查](data-split-distribution-audit.md)中的输入快照、完整清单与有限范围内的观察结论。

**失效条件：** 新标注、源视频身份、既有划分、已确认标签规则或测试使用边界改变时，应重核本文所依据的数量、可行性与选项代价；用户确认正式标准后，以明确版本的确认稿为准，本文保留为讨论记录，不自动成为操作文档。
