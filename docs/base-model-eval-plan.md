# 基座模型（base model）测评方案

**状态：2026-11-13 方案稿 v5，未经实施验证。** v2–v5 变更：v2 新增 §8.1 跑通判据（区分 run 完整性与格式合法率），补充五类字段的事实源指引；v3 字段计数 13→11，依据 score.py 的 SINGLES/MULTIS/FIELDS 常量；v4 补入画幅分档必报维度（引用输入契约 §4.6）；v5 修正 §6 引言计数与不确定值口径。

## 1. 目的

1. 下限锚点：没有 base 分数，「微调有效」不成立；base 必须与微调模型在同一批片段上配对比较。
2. 链路验证：当前没有任何训练产物，base 是唯一能端到端验证「抽帧→prompt→解析→评分」链路的被测对象。
3. 先验探测：base 在无画面时仍答对某些标签，说明该类别靠文字先验就能刷分，微调后的「提升」不可信。

## 2. 被测对象与身份

每条请求记录六项身份：基础权重标识、加载方式、prompt 版本、抽帧配置、解码配置、运行机器。六项写入 `model_id`、`prompt_id`、`input_id` 与运行记录，缺任一项不进入跨模型比较。

下表 6 项由用户决定，本文不填取值、不写倾向、不给推荐。

| 待决项 | 为什么必须由用户决定 |
| --- | --- |
| 基础模型选型 | 待定。选型决定能力上限，也决定与后续微调模型的可比性；换权重算出的 base 分数不能互相替代。 |
| 加载方式（transformers / 服务化） | 待定。加载方式决定 base 能否与后续微调模型走同一条推理路径，直接影响可比性与可复现性。 |
| 运行机器（本机 M4 无 GPU / 训练机） | 待定。运行机器决定能否跑全量，也决定结果是否与训练机环境一致。 |
| 单请求帧数上限 | 待定。帧数直接改变模型看到的证据量；与微调时配置不一致，配对比较失效。 |
| 分辨率上限 | 待定。分辨率同样改变可见证据量；与微调时配置不一致，配对比较失效。 |
| 是否携带 temporal ids | 待定。是否携带影响时序信息的注入方式，与 3b 顺序对照的解释直接相关。 |

## 3. 三层结构

| 层 | 内容 | 与微调模型的关系 | 前置依赖 |
| --- | --- | --- | --- |
| 层 1 主任务评分 | 五类 11 个叶字段（5 个顶层键）端到端 | 必须与微调模型完全同一套：同契约、同 prompt、同抽帧、同解码、同评分器，一个字都不改 | 人工审核 B1（314 条固定 test 候选中已审完的部分） |
| 层 2 链路健康度 | 格式合法率、抽取失败率、请求失败／超时／未处理率、组合冲突率 | 同一套输入；只作工程指标用，不计入能力指标 | 不依赖人工真值，链路打通即可跑 |
| 层 3 视觉／时序诊断 | 3a 无画面对照 → 3b 顺序对照（A→B / B→A）→ 3c 遮挡与正负配对 | 可换 prompt，但必须同候选、同抽帧规则、同身份记录方式 | 见第 7 节：3a 依赖抽帧链路，3b 依赖人工确认的样本，3c 依赖遮挡与正负素材 |

「五类 11 个叶字段」的具体清单不在本文复制（3 个单值 + 3 项异常 + 5 项现象 = 11 个叶字段，共 5 个顶层键；不是「13 项」，13 项指评分模块测试数）。口径依 `docs/design-test.md` 第 3 节与 DF-030（`docs/facts.yaml`）；本文不充当第二份口径表。

字段名与允许取值的**机器可读唯一事实源**是 `script/five_label_eval/score.py` 的 `SINGLES`（13–17 行）、`MULTIS`（18–19 行）、`FIELDS`（20 行）常量。特别注意：单值三类的不确定值写作「无法确定」，多项两类的取值写作「是」「否」「无法判断」（由同文件 `allowed()` 第 113 行给出），两者不可互换；评分器不做归一化，写错即 `invalid`。写 prompt 或契约时必须以该常量为准，不得按本文或设计文档手抄。

## 4. 实验矩阵与 run 组织

| run | 内容 | 主要产出 |
| --- | --- | --- |
| A | base + 主 prompt + 正常画面 | 层 1 + 层 2 |
| B | base + 主 prompt + 无画面 | 层 3a：承认信息不足／仍报具体标签／猜中原标签 |
| C | base + 诊断 prompt + 顺序版 | 层 3b：单题正确率 + 配对全对率 |

跑的顺序是 A → B → C。A 未跑通不谈 B。

### 4.1 run 隔离的技术约束（来自现有评分器代码事实）

- 一个 `predictions.jsonl` 只允许一个 `(run_id, model_id, prompt_id)` 三元组。主评分与诊断必须分文件，这正好强制两者不混算。
- 每条记录必填 `candidate_id`、`clip_sha256`、`run_id`、`model_id`、`prompt_id`、`input_id`、`request_id`，后五项为非空字符串；`raw_output` 键必须存在（可为 `null`）；`status` 限于 `success`、`request_failed`、`timeout`、`unprocessed`。
- 每个 `candidate_id` 每批只允许一条记录。重试或对照另起批次，同批不得多条。
- 未出现的预测记录按「未处理」计。

## 5. 一致性规则

- 主任务 11 个叶字段（5 个顶层键）：base 与所有微调模型完全一致，共用一份冻结的契约、prompt 与抽帧配置。
- 诊断题：不必与主任务同一套 prompt，但必须同候选、同抽帧规则、同身份记录方式。
- 报告：诊断结果不与主评分混算，单独 run、单独一节。

## 6. 指标与报告口径

以下前四条已由用户确认，本文直接沿用，不重开讨论；第 5 条为引用型补充，口径以输入契约为准。

1. 片段级与来源级双主并列，禁止合成总分；稀有来源 `n_sources < 3` 只报个案，且永远报 `n_sources`；只审了部分片段的源标 `partial`，不进来源级宏平均。
2. 工程准入线（失败率、超时率、格式合法率、未处理率）与能力指标只做描述；本轮不设能力阈值，第一批真实结果出来后再定。
3. 诊断题走独立请求 + 限定选项 + 子集非空匹配，报告附命中率与过度报出率。
4. 视觉／时序结果本轮只报告不筛选，红灯条件写成明文，例如「遮住关键区域后正确数不降」或「顺序题正确率≈50%」，命中即标记该模型结果不可解释。
5. **画幅分档必报**：候选片段实际尺寸跨 60×80 至 924×1232。按 `docs/eval-input-contract.md` §4.6 定义的三档（宽 ≤200 / 200–400 / >400）分别报告来源数、片段数、各标签的不确定比例（单值三类按「无法确定」、多选叶项按「无法判断」分别统计）与失败数；**同一标签不得跨档合并成一个数字**。三档定义与字段以该契约文档为准，本文不另立口径。

### 6.1 **base 阶段的主指标是失败率，不是准确率**

base 很可能大面积格式不合规或拒答。此时准确率低是格式失败造成的，不是「答错」。报告必须把 `request_failed`、`timeout`、`unprocessed`、`extraction_failed` 与「答错」并列呈现，否则会得出「基座能力接近 0」的假结论。

## 7. 依赖与排期

- 层 2 不依赖人工审核，链路打通即可跑。
- 层 1 硬依赖人工审核 B1：314 条固定 test 候选审完。
- 层 3a 依赖层 2 的抽帧链路；3b 依赖人工确认的 A（连通）／B（分离）样本；3c 依赖遮挡与正负素材的制作。
- 契约与 prompt 由后续「输入契约」工作产出并冻结后再跑。本方案只定测试结构，不含契约内容。

## 8. 验收标准

- [ ] 每个 run 有独立的 predictions 文件，且身份三元组唯一。
- [ ] 每条记录字段齐全，`raw_output` 键存在。
- [ ] 报告同时给出片段级与来源级，且不含合成总分。
- [ ] 失败与答错分列，`request_failed`／`timeout`／`unprocessed`／`extraction_failed` 计数明确。
- [ ] 未处理数量与分母明确。
- [ ] 诊断 run 单独成节。
- [ ] run A 是否通过按 §8.1 的 (a) 类判据判定，未使用格式合法率作为门槛

### 8.1 什么算跑通

「跑通」指数据链路与记录完整性，不指模型答得好不好。两类判据必须分开：

| 用途 | 内容 | base 阶段可否设硬门槛 |
| --- | --- | --- |
| (a) run 完整性 | 每个候选一条记录、必填字段齐全、`raw_output` 键存在、无中断崩溃、未处理数量明确、身份三元组唯一 | **可以且必须**：这是「这次跑有没有跑完」，与模型能力无关 |
| (b) 契约清晰度 | 格式合法率（`strict_format_valid` 通过比例）、抽取失败率 | **不可以**：base 阶段这两个数字本身是待测产出，不是门槛。设高门槛会导致 base 永远无法进入 run B |

判定规则：

1. **run A 的通过判据只取 (a)**：记录完整、身份唯一、失败原因分类齐全，即算「跑通」，可以进 run B。格式合法率高低不影响是否进 B。
2. **格式合法率在 base 阶段是产出指标**，按 §6.1 与失败率一并报告，不作为筛选条件。
3. **格式合法率转为准入门槛的时点**：仅当微调模型出现时（那时不合规说明训练或 prompt 有问题，而不是模型太弱）。此条只写时点，不写具体数字——数字属待决项。
4. 本文不设具体的失败率／格式合法率数值门槛；需要数值时由用户在拿到 run A 首份结果后确定。

## 9. 已知限制

- 单模型单次运行不代表稳定性；重复次数未定。
- 无对照素材时层 3 无法执行。
- base 的结果不能外推为「该任务不可学」。
- 真实与虚拟数据分开报告。
