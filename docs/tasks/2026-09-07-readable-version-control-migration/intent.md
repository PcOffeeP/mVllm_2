# Problem

项目已在原分支 `refactor/readable-version-control@1b0d5823` 完成可读版本控制核心基础设施，但现有数据处理、训练、测评和服务流程仍使用旧体系。已有自动化测试和独立复核证明了核心实现的本机行为，尚不能证明训练机真实产物、存储配置和活动入口已经完成迁移。

缺少的证据包括当前有效对象的新旧身份对应关系、真实环境下的运行与恢复验证，以及调用方切换后的完整链路验证。两台机器及目标远端的 Git 状态也需要重新核对。

# Desired outcome

项目实际使用的正式数据、Prompt、训练、保留模型和正式测评可以通过五类完整可读身份查找，并能追溯到实际输入、配置、产物和结果。

约定迁移范围内的活动入口使用新体系；旧体系不再承担这些入口的日常版本选择和正式对象写入。当前数据、服务模型、历史证据和受限测试的使用事实得到保留。

交付物包含人工核对的新旧对象映射、训练机验证结果、适用的备份恢复证据、最终独立复核结论及明确的验证限制，使用户能够据此决定是否合并。迁移成功不表示模型质量达标。

# Affected users and systems

受影响者包括项目维护者、数据审查人员、训练与测评执行者，以及后续接手的 Agent。

受影响系统包括 Mac 开发工作区、Linux 训练机、数据处理与人工审查交接、训练准备和结果记录、模型登记与服务加载、DVC 数据存储、MLflow 记录与模型产物、私人移动硬盘备份，以及两台机器使用的 Git 仓库。

# Constraints

- 沿用已确认的[可读版本控制目标架构](../../plans/2026-09-01-readable-version-control-design.md)；此前对话提出的 M0–M5 分组和五个迁移状态只是建议，不作为已确认要求。
- 复用[实施台账](../../plans/2026-09-01-readable-version-control-implementation.md)中 B0–B12 的成果。真实接入发现缺陷时保留问题和修复证据，不以原测试通过代替真实验收。
- 只迁移来源和身份链可核对的对象；证据缺失项明确列出，不伪造历史运行、正式结论或版本关系。
- 正式对象不得被原地覆盖；迁移和回退均不得重置 holdout 消费事实、有效性标记或模型审批事实。
- GPU、真实模型加载与推理、长时间数据处理遵守训练机执行边界。模型质量改善、重新训练和独立测试集使用不因迁移自动获得授权。
- 备份复制校验与真实恢复验证分别记录；未取得真实恢复证据的类型，不宣称已验证可恢复。
- 历史大型产物清理、merge 和 push 按项目现有明确授权执行。
- [项目 TODO](../../project-todo.md)保持唯一项目任务台账，关联现有 `VERSION-CONTROL-FORMAL-MIGRATION`；Artifact 负责目标、规格与执行计划。
- 本次请求授权形成 Task Artifact；正式迁移实施范围在后续 Plan 确认时明确。
- 用户于 2026-09-07 确认承接现有未合并分支，例外于从稳定 main 新建任务分支的默认规则：保留全部提交历史，将原分支重命名为 `refactor/2026-09-07-readable-version-control-migration`，以 `1b0d5823` 为基础设施承接基线。任务身份为 `2026-09-07-readable-version-control-migration`。该确认不授权提前合并 main。
