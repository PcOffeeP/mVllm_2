# 正式迁移行为规格

上游：[Intent](intent.md)，确认提交 `3dae30a0`。**本文件定义用户已确认的行为契约；实施安排与授权在 Plan 阶段明确。** 现场观察见[训练机调查记录](../../results/version-control-migration-20260907.md)，执行进度由[项目 TODO](../../project-todo.md)管理。

## 对象范围与身份保真

**本次按数据、Prompt、模型、核心训练参数及已有评估指标整理迁移对象。**

- **数据**：迁移已发布的 `v4.1.0-760050fad303` 和 `v4.1.0-ecb5aeb9657c` 两个版本。转换保持样本、划分、标签、审查来源与有效状态，不因迁移重新生成不同的数据内容。
- **Prompt**：仅将当前活动版本 `v4.1-concise-evidence-json-v2` 迁移为新的正式 Prompt。历史模型使用的其他 Prompt 保留已有原始引用或冻结内容，不强行改绑当前 Prompt，也不为历史查询要求逐版重新发布。
- **模型与训练参数**：逐模型保留可核对的来源和核心参数。试验性模型允许保留简明历史记录，不要求补齐所有过程日志、checkpoint 或完整环境包；简化记录不等于授权删除原文件。
- **已有评估指标**：与具体模型及评价口径关联保存；缺失、未执行和已执行失败明确区分。不为迁移重评或补记 passed。

仅准备的实验不登记为 completed 训练或保留模型。身份、权重或结果证据不足时，可以保存明确标注缺失的历史记录，不能把它作为完整的新正式对象供下游执行。**简明历史记录与新正式 train/model/eval 的完整性契约不同，前者不自动获得后者的执行资格。**

每个新正式对象必须有可核对的新旧身份对应、实际产物和完整上游引用。同一目标身份冲突时停止，不覆盖、不自动改号。原始运行事实与本次迁移行为可区分；哈希仅作完整性校验，不作新活动入口身份。

### 核心历史信息的最低内容

以下字段范围表达用户确认的“核心参数”；不能取得的历史值标为未知并注明来源缺口。

- **模型身份**：原模型或实验 ID、基座及可知修订、fold 或全量范围、权重位置及存在性。
- **数据和 Prompt**：原始版本引用，已有冻结输入或摘要；不从当前活动指针反推历史输入。
- **核心训练参数**：seed、学习率、epoch 或训练步数、有效 batch size、优化器、精度、LoRA rank/alpha/target modules，以及会改变输入的采样方案和图像/视频处理配置。
- **评估指标**：已有指标名称与数值、对应模型/权重标识、数据及 split、样本数、评价契约、结果来源；不跨不同口径合并，不把训练 loss 当作模型质量通过。
- **结论**：保留实际运行、质量及审批状态；资料不完整的记录仍可用于历史查询，但不能伪装成可重现或可部署模型。

## 数据发布与人工审查

新发布流程继续采用七个业务阶段，必须提供真实训练准备所需的产物。版本管理迁移不得改变 ROI、剪裁、采样、样本选择或标签语义；发现差异时停止受影响转换。

训练机持有权威工作区。Mac 的审查副本绑定轮次、批次和候选全集；缺项、额外项、部分回传、内容漂移及旧批次均拒绝接收。接收失败保留既有结果，不放行发布。

## 训练与测评事实

新训练显式选择完整数据与 Prompt 身份，冻结实际参数和输入；实际执行必须使用这些输入，记录对应真实 fold、产物和终止状态。创建 Run 或填写完成标记不能代替真实运行证据。

新正式测评精确绑定被测模型及数值 Model Version，保存数据、split、样本范围和评价规则。历史指标缺少新契约所需证据时保留为历史结果，不转换成 passed 的新正式 eval。

**迁移和恢复不产生新的 holdout 使用资格。** 已暴露、已消费、真值权限和一次性授权事实必须保留；既有受限结果不因整理指标而获得读取或公开权限。

## 模型别名与服务接管

**所有活动入口完成切换仍属于最终验收范围，包含实际服务入口。** 不能以仅验证接入能力代替服务切换，也不能因历史模型没有 passed 就自动排除服务。

**严格保留现有门禁，不为历史开发验证发布设置例外：**

| alias | 当前合法条件 |
| --- | --- |
| candidate | 完整有效的来源训练与模型、精确绑定同一模型数值版本的 passed 正式 eval、唯一部署目标、至少 adapter 备份范围 |
| production | 满足上述模型与评测条件，另外有人工 production 批准及 production_bundle 备份范围 |

服务显式指定模式和 alias；production 模式只允许 production alias。启动时在线核对模型有效性、精确版本及物化内容。无合法 alias、版本不符、缺产物或 Registry 不可用时拒绝启动，不能回退到旧指针或人工指定目录绕过门禁。

**历史模型不补 passed、不补发审批。** 之前为验证后续推理链路而作的开发发布只保留为历史事实，不要求继续提供服务，也不赋予新体系准入资格。

**服务入口切换与模型可用性分别验收：** 所有活动服务启动、模型选择和加载入口都必须接入新契约，旧指针及开发发布例外不再可绕过它。没有合格模型时，入口报告缺少合法 alias 并拒绝启动，是允许的运行状态；无需为迁移重评历史模型或制造合格 alias。

入口接管须有实际调用链与拒绝旧路径的证据，不能仅用独立门禁函数测试宣称完成。真实模型加载和推理成功路径若缺少合格模型，明确记录为未验证，不能用拒绝启动测试代替；以后获得合格模型时仍须通过实际加载与推理验证方可宣称模型可用。

## 正式写入与失败恢复

**每个已切换的业务入口只有一个正式写入者，旧入口停止写入。** 切换前须确认输入引用完整、语义一致及真实环境行为满足契约。具体切换执行顺序属于 Plan。

转换或切换失败保留旧正式对象及已经产生的新正式事实。代码回退不等于数据库或文件状态回退；不得抹去新记录、重置 claim、撤销 invalid 事实或恢复更宽松的审批状态。

同一转换中断后的重试必须识别已提交事实和未完成输出；身份或内容冲突停止，不以覆盖正式对象消除冲突。仅能恢复可证实属于同一操作的未完成工作。旧活动解析器须在调用方已脱离后退役；历史文件清理不由此自动授权。

## 存储与备份恢复

训练机为大型正式产物权威位置，Mac 保存轻量记录和审查副本。DVC 管理数据，MLflow 管理运行和模型产物，Git 保存轻量定义与正式导出记录。

备份按正式数据及模型粘性范围决定内容，不根据 alias 当前指向降低历史保留范围。SQLite 快照必须与应恢复的模型身份及产物一致。恢复在隔离位置完成，不覆盖正式对象。

**用户允许先完成其他迁移工作，真实移动硬盘备份恢复单独保持未完成。** 缺少演练时明确标注对应数据、adapter、merged、SQLite 的真实恢复未验证，不宣称备份可恢复；设备恢复可用后仍按原设计取得真实证据。

这项拆分不取消备份功能和受控恢复的契约验收，也不授权删除唯一源副本。若先行提交合并候选，材料必须显著列明真实硬盘验证缺口；是否实际合并仍由用户依据该材料决定。

## 验收与合并边界

- 对两个指定数据版本和当前 Prompt 完成身份、语义及产物一致性验证。
- 历史模型、参数及已有指标有可查询关联；未知项明确，试验性记录不冒充完整正式运行或质量通过。
- 数据、训练准备、实际运行记录、模型登记、测评及服务等活动入口完成接管，失败恢复不破坏既有事实。
- 在训练机取得对应真实环境验证，区分本机测试、模拟对象验证与真实产物证据。
- 文档、活动入口及机器约束一致；最终变更经过独立审查。
- **Codeup 为发布依据**，交付材料覆盖本地及任务分支相对 Codeup main 的全部相关差异；保留两台机器独有工作。merge/push 仍须明确授权。
- 真实硬盘恢复按前述边界单独列明；模型效果改善、重训练、新 holdout 构建及历史大型产物删除不属于自动授权。
