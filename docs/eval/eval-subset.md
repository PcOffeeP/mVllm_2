# 评测子集：画幅三档 · 报告必报项 · `max_pixels` 绑定

**失效条件：** 预处理策略或 `max_pixels` 默认值改变；候选画幅分布改变（新增来源跨出 60×80 至 924×1232）；`size_bucket` 判据改变；清单结构或媒体目录结构改变；抽样原则或冻结口径改变。以上任一发生，分档定义、报告口径与本文的倍数结论都须重新核对。

## 1. 三档定义

| 档名 | 区间（按媒体实际宽度） | 对应判据 |
| --- | --- | --- |
| `w_le_200` | 宽 ≤ 200 | `width <= 200` |
| `w_200_400` | 200 < 宽 < 400 | `width < 400` |
| `w_gt_400` | 宽 ≥ 400 | 其余 |

判据与 `media.size_bucket` 完全同源（常量 `SIZE_BUCKET_SOURCE` 在 `script/five_label_eval/frames.py:36`；三档判定在 `size_bucket()` 函数体 `script/five_label_eval/frames.py:60-61`），即 **200 归 `w_le_200`、400 归 `w_gt_400`**。**旧版边界表述已被实现取代**：旧文档的「含下界不含上界」与实现不符，不得再引用。档名只是标签，`le`／`gt` 不按字面取，归属一律以区间式为准。

## 2. 为什么分档（含必须修正的数字）

| 阶段 | 数值 | 倍差 |
| --- | --- | --- |
| 原始画幅 | 60×80 至 924×1232；面积 4,800 → 1,138,368 像素 | 逐像素约 237 倍（文档中常写作「约 200 倍」） |
| 经 `max_pixels` 预处理后 | 4,800 → 65,536 像素 | **约 13.6 倍** |

`max_pixels` 默认上限为 `256×256` = 65,536 像素（见 `docs/research/minicpm-video-loading.md:35`）。预处理只缩不放，故 60×80 的候选面积不变（4,800），924×1232 的候选被压到 65,536 以内。

**必须写明的结论**：原始差异约 200 倍 → 预处理后约 13.6 倍，**故报告里「200 倍」的说法不成立**——它是预处理前的数字，不能用来论证模型侧的信息量差异。模型实际看到的画幅差异上限由 `max_pixels` 决定。

**但分档依然必要**：13.6 倍仍是显著差异，且小画幅候选在缩放后不会获得任何信息增量（放大不增加信息）；同一标签在不同档上的可见性差异与判读难度不同，混算会把低画幅来源的系统性不确定算成模型判错。

## 3. 报告必报项

三档各自独立给，逐项不可省略。

| 档位 | 来源数 | 片段数 | 各标签的 `无法判断` 比例 | 请求失败／超时／未处理数 |
| --- | --- | --- | --- | --- |
| `w_le_200` | 必报 | 必报 | 必报，逐标签逐个给：单值三类与多选 8 个叶项都按 `无法判断` 统计，多选按叶项各自给 | 必报，三类分列 |
| `w_200_400` | 必报 | 必报 | 同上 | 同上 |
| `w_gt_400` | 必报 | 必报 | 同上 | 同上 |

**硬约束：同一标签不得跨档合并成一个数字。** 可以三档并列展示，但不得加权合成，也不得只报总体。某档来源数 < 3 或该档片段数为 0 时，只报个案与计数、不报比例，也不并入其他档；来源数无论多少都必须报出。

真实数据与虚拟数据分别在各自档内报告；虚拟数据的画幅分布若与真实数据明显不同，须单独说明其分布。

## 4. `max_pixels` 与分档绑定

| 规则 | 理由 |
| --- | --- |
| 改 `max_pixels` 必须同时改分档报告，两者一起改 | 分档的意义是「模型实际可见的画幅」，`max_pixels` 直接决定预处理后的实际画幅；只改一方会让档名与实际画幅脱钩 |
| 不得用统一放大（upscale）消除分档 | 放大不增加信息，只会把「低画幅信息不足」伪装成「画幅一致」，从而掩盖差异来源 |
| 若预处理含缩放，必须记入输入记录的 `resize` 字段并在报告中说明 | 否则无法判断某档的差异来自原始画幅还是来自缩放策略 |
| 跨 `max_pixels` 取值的结果不得直接比较 | 它们是不同的 `input_id`，不是同一实验的重复 |

## 5. 分层抽样原则

| 项 | 要求 |
| --- | --- |
| 分层维度 | 画幅三档 × 标签分布（含各标签的不确定项）× 断裂现象（有／无）× 来源类型（`real`／`virtual`） |
| 每档覆盖 | 三个画幅档都要有片段；不得因为某档「样本难判」而跳过 |
| 抽取方式 | 按上述维度分层后在各层内随机抽，记录随机种子与抽样清单文件（含 sha256） |
| 禁止 | 不得只抽易判样本；不得按模型历史结果抽（会引入选择偏差）；不得在同一子集上反复调参后再报同一批指标 |
| 来源数下限 | 某档来源数 < 3 时不报比例，只报个案与计数 |

## 6. 冻结要求

- 子集一旦用于批次，**候选 ID 列表与清单摘要（`manifest_sha256`）同时冻结**；冻结产物含候选 ID 数组文件及其 sha256。
- 子集变动即新实验：必须新 `run_id`、新 `predictions.jsonl`、独立评分（同一批只允许一个 `(run_id, model_id, prompt_id)`，同一候选批内只允许一行）。
- 冻结后的子集不得因中间结果而调整；确需调整时，旧批次保留并声明作废原因，不得改写旧产物。
- 抽样清单、随机种子、`max_pixels` 取值三样必须与该批次记录同存，否则该批次的分档结论不可复现。
