# 子视频生成与审核规则

**状态：规则审查稿。** 本文汇总本轮已讨论的规则和待审细节，作为后续修改脚本的依据。当前代码尚未全部适配；本次只更新文档，不生成视频。

## 1. 先按时间确定能否生成

读取源视频、[标注表](../data/annotation-table-full.csv)、已有 ROI 和固定三折划分，只处理开发集。子视频继承源视频的划分，不重新划分，也不使用测试集媒体。

多个条件同时出现时，先检查“视频异常且没有断裂时刻或范围”，符合即跳过；否则，未夹紧优先进入现象窗口分支，不回退为普通未断裂窗口。其他来源按断裂时间和状态选择分支。

| 源视频情况 | 处理规则 |
| --- | --- |
| 有精确断裂帧或断裂时刻 | 围绕标注事件生成断裂前、包含断裂和断裂后窗口。已有前后帧时，以后帧为事件锚点，不重新猜测断裂时刻。 |
| 有完整断裂时间范围 | 以范围下界、上界分别确定断前、断后边界；包含断裂的窗口覆盖整个范围，不取中点冒充精确时刻。 |
| 视频异常，且没有断裂时刻或范围 | 跳过该来源，原因直接记录为“视频异常”。 |
| 确认完整视频未断裂，且不属于上一条 | 按未断裂窗口规则生成。 |
| 没有可用断裂时间，断裂状态也无法确定 | 暂不生成事件窗口，原因记录对应标签“无法确定”。 |
| 未夹紧 | 采用第 3 节的现象窗口分支，不把未夹紧时刻写成断裂时刻。 |

模式、位置“无法确定”，以及视频异常、爆炸性异常等标签，不再单独挡住已有可靠断裂时间的视频。未知值保留原含义，不强行映射成旧脚本支持的确定值。“无”“无法确定”“未标注”分别保留。

标注时刻与实际源帧的对应仍须验证；时间点缺少帧号、范围只有一端或边界无法可靠对应时，记录具体缺项，不补造帧号。**仅有时间点时的寻帧办法仍待脚本设计确认**，不重新要求用户确认已经标好的事件本身。

## 2. 断裂窗口沿用现有构造规则

| 类型 | 选窗与数量上限 |
| --- | --- |
| 断裂前 `pre` | 精确事件：不晚于事件前 0.5 秒结束；时间范围：不晚于下界前 0.5 秒结束。脆性窗口靠近事件，最多 3 个；韧性、半脆半韧窗口分布在可用断前区间的前、中、后，最多 15 个；其他模式最多 4 个。 |
| 包含断裂 `fracture` | 尝试 2、3、5、10、20 秒目标时长，采用现有事件位置模板，最多 10 个。精确事件须位于窗口内；范围事件须完整覆盖上下界。素材不足时保留符合现有规则的自适应窗口。 |
| 断裂后 `post` | 从事件或范围上界后 0.5 秒开始，生成完整后段及可用分段，最多 4 个；跳过保护间隔后，至少还需 2 秒源素材。 |
| 未断裂 `no_fracture` | 尝试 2、3、5、10、20 秒及现有不同位置模板，最多 5 个。 |

单个候选至少 1 秒；目标时长可以与实际时长不同。按实际帧区间去重，窗口越界、素材不足或范围覆盖不完整时不生成，并保留原因。前后保护间隔和素材余量均按实际时间戳核对。

**模式无法确定的断前窗口建议待审：** 使用“其他模式”的靠近事件选窗方式，最多 4 个；模式标签仍为“无法确定”。这样选窗不依赖把未知模式改成确定模式。

## 3. 未夹紧按现象时刻单独选窗

当前未夹紧样本的断裂时间、断裂模式为“无”。生成这类片段时，锚点是**未夹紧现象出现的时刻**，不生成“断裂前／断裂后”含义的标签。断裂模式和位置按[标签说明](label.md)填写“无”，断裂状态仍依据片段画面判断。

**现象窗口建议待审：** 参考 2、3、5、10、20 秒目标时长，围绕现象时刻取覆盖现象前后的窗口；窗口不得越过源素材边界，实际长度不足 1 秒则排除。具体事件位置比例、数量上限和自适应方式，需在本稿审查后确定。

当前标注表没有独立的“未夹紧现象时刻／帧号”字段；该时刻的记录位置、来源及对应帧仍需确定。缺少可用现象锚点时不猜测、不借用断裂时间，记录“未夹紧：缺少现象时刻”。

## 4. 文件名只说明来源、类型和序号

统一使用 `源视频ID_类型_序号.mp4`：

```text
video_0045_pre_01.mp4
video_0045_fracture_01.mp4
video_0045_post_01.mp4
video_0107_no_fracture_01.mp4
video_0002_unclamped_01.mp4
```

同一来源、同一类型内，建议按源起始帧、结束帧排序后从 `01` 编号。文件名保持简短；完整参数写入对应记录。序号不代表内容身份，重新生成时以输入摘要和规则摘要区分批次，不覆盖已有结果。

## 5. 每个片段必须有对应的标注与生成记录

建议未来使用 `data/subvideos/manifest.json` 统一保存片段记录、`summary.json` 保存数量与未生成原因，视频放在 `videos/`。这是待审的输出安排，本次不创建这些文件。

| 记录内容 | 每个片段需要保留的关键参数 |
| --- | --- |
| 身份与来源 | 子视频 ID、文件名、源视频 ID、源与 ROI 的路径及内容摘要、输出摘要、原标注身份、各折 train／val 归属。 |
| 源视频中的区间 | 源起止帧、源起止时间、帧区间 `[start_frame, end_frame)`（起点包含、终点不包含）、对应的源时间戳基准。帧号从 0 开始，秒数相对源视频起点。 |
| 片段实际信息 | 输出帧数、实际播放时长、分辨率、帧率与时间基准；源时间区间长度和输出时长分别记录，避免不同时间轴混用。 |
| 事件依据 | 锚点类型：精确断裂、断裂范围、未夹紧现象或无事件；原始标注值、对应源帧和实际时间。范围保留上下界，未夹紧另记现象锚点。 |
| 窗口构造 | 类型、序号、目标时长、实际源区间长度、标准或自适应窗口、模板及事件位置比例、保护间隔、断后素材余量、适用的数量上限。未适用项明确留空并说明，不填虚构值。 |
| 帧对应 | 源 → ROI → 子视频的帧映射、落在片段内的锚点对应输出帧号和时间、两段验证结果及证据摘要。片段内帧号从 0 开始；片段外锚点不伪造输出位置。 |
| 规则与生成状态 | 生成规则身份与参数摘要、代码与工具链身份、生成状态；未生成或排除时记录标签原因及具体缺项。 |
| 五类标签及审核 | 源标签参考、候选初值、人工确认后的五类标签分别保存；同时记录重点审核项、审核状态、审核决定及修改说明。 |

这些参数应能回答：**从哪个源视频的哪一段生成、围绕什么事件、采用哪条窗口规则，以及为什么与同源其他片段不同。**

## 6. 标签先作参考，再逐片段审核

五类标签使用[标签说明](label.md)中的名称和组合约束，不沿用旧脚本内部标签作为最终答案。

| 片段类型或源标签 | 初值与重点审核 |
| --- | --- |
| 断裂前 | 根据时间关系给出“未断裂”候选状态；模式、位置按标签规则填“无”。重点复核画面能否判断未断裂，以及视频异常和位置相关信息；源位置仅保留为参考。 |
| 包含断裂、断裂后 | 优先带入源视频已有模式、位置、异常和现象作为候选参考；断裂状态分别按窗口建议“发生断裂”“已断裂”，不能把源状态原样复制到全部片段。人工确认各项是否在片段中有依据。 |
| 模式或位置无法确定 | 保留“无法确定”，不自动补成确定标签；适用固定值“无”时遵循标签组合规则。 |
| 视频异常 | 有断裂时间时继续生成；逐片段确认异常是否影响判断。断裂前重点审核视频异常及位置，事件和断后保留原标签参考。 |
| 未夹紧 | 重点确认现象在片段中可见；模式、位置为“无”，断裂状态按画面判断。 |
| 爆炸性异常及其他现象 | 保留源标签参考，但不认定每个时间段都出现；按片段画面确认，并检查标签组合。 |

源标签、候选初值和审核后标签不可混写。异常和现象各项的“是／否／无法判断／未标注”分别保存。未审核、通过、修改后通过、拒绝需明确区分；所有拟发布片段都须人工审核，未审核或被拒绝的片段不进入发布数据。

## 7. 生成后验证帧对应

源视频按已有 ROI 决定重放，须与现有 ROI 文件及完整解码帧、时间戳一致。子视频裁剪后，再用独立取帧方式重放同一区间，核对文件、完整帧序列、时间戳和锚点映射。任一段不能验证则保留失败原因，不以图像相似度自动通过。

技术验证通过只说明已绑定输入与输出的帧对应；不能替代片段标签审核。输入、标注、ROI、窗口规则或工具链变化后，受影响结果须重新核对。

**本稿待审细节：** 未夹紧现象时刻的输入位置及窗口参数；模式无法确定的断前选窗方式；仅有时间点时的源帧定位办法；输出文件与字段的具体实现。确认规则后再修改脚本和生成视频。
