# 子视频生成与审核规则

**状态：** 本文记录当前子视频生成与审核规则。统一入口为 [generate.py](../script/subvideo_generation/generate.py)；实际批次状态见 [项目 TODO](TODO.md)。

## 1. 先按时间确定能否生成

读取源视频、[标注表](../data/annotation-table-full.csv)、已有 ROI 和固定三折划分，处理全部开发集和测试集来源，每个来源只生成一次。子视频继承源视频的划分，不重新划分。

| 源视频情况 | 处理规则 |
| --- | --- |
| 有精确断裂帧或断裂时刻 | 围绕标注事件生成断裂前、包含断裂和断裂后窗口。已有前后帧时，以后帧为事件锚点，不重新猜测断裂时刻。 |
| 有完整断裂时间范围 | 以范围下界、上界分别确定断前、断后边界；包含断裂的窗口覆盖整个范围，不取中点冒充精确时刻。 |
| 视频异常，且没有断裂时刻或范围 | 五个断裂锚点列全空或“无”时按下方覆盖窗口生成；有可用锚点时仍走事件窗口，素材不满足窗口条件时记录具体缺项。 |
| 确认完整视频未断裂，且不属于上一条 | 按未断裂窗口规则生成。 |
| 没有可用断裂时间，断裂状态也无法判断 | 按下方覆盖窗口生成，不推测事件；片段断裂状态初值取源标注，“无法确定”归一为“无法判断”，不把源状态原样当作片段结论。 |
| 未夹紧 | 采用第 3 节的现象窗口分支，不把未夹紧时刻写成断裂时刻。 |

模式、位置“无法判断”，以及视频异常、爆炸性异常等标签，不再单独挡住已有可靠断裂时间的视频。未知值保留原含义，不强行映射成旧脚本支持的确定值。“无”“无法判断”“未标注”分别保留。

是否使用覆盖窗口，由标注表本身判定，不再有手写来源名单：五个断裂锚点列（`断裂帧_前`、`断裂帧_后`、`断裂时间点`、`断裂时间范围_下界`、`断裂时间范围_上界`）全部为空或“无”，且（`断裂状态` 为“无法判断”或“无法确定”，**或** `异常_视频异常` 为“是”）时，进入覆盖窗口；其余来源（有锚点因而走事件窗口的“视频异常”来源，以及 `断裂状态` 为“未断裂”且没有视频异常标记的来源）走事件窗口，或按上表记录具体缺项。覆盖窗口每次取 20 秒并向后移动 15 秒，末段贴近视频结尾；短于 20 秒时保留全长。覆盖窗口候选的 `断裂状态` 初值取源标注，“无法确定”归一为“无法判断”，为“未断裂”时模式、位置记“无”；例如 `video_0107`（未断裂、`异常_视频异常` 为“是”、五个锚点全空）的覆盖窗口候选初值是来自源标注的“未断裂／无／无”，不是“无法判断”。来源标签仅供参考，片段标签留待人工审核。“不再有手写来源名单”只针对统一入口；归档路径 `script/subvideo_generation/_legacy/coverage/generate.py` 仍保留自己的来源名单（`DEFAULT_IDS`），仅用于复现该归档路径，不参与统一入口的选路。

**失效条件：** 标注表新增或改名断裂锚点列，`异常_视频异常` 列改名或它的“是”取值用词变化，或“无法判断／无法确定”的用词变化时，须同步修改 `script/subvideo_generation/rules.py` 中的覆盖判据（`COVERAGE_RULE` / `is_coverage_source` / `COVERAGE_ABNORMAL_FIELD`）与候选初值规则（`COVERAGE_LABEL_RULE` / `coverage_candidate_labels`），否则选路结果与候选初值与本表不一致。

标注时刻与实际源帧的对应仍须验证；时间点缺少帧号、范围只有一端或边界无法可靠对应时，记录具体缺项，不补造帧号。**仅有时间点时的寻帧办法仍待脚本设计确认**，不重新要求用户确认已经标好的事件本身。

## 2. 断裂窗口沿用现有构造规则

| 类型 | 选窗与数量上限 |
| --- | --- |
| 断裂前 `pre` | 精确事件：不晚于事件前 0.5 秒结束；时间范围：不晚于下界前 0.5 秒结束。脆性窗口靠近事件，最多 3 个；韧性、半脆半韧窗口分布在可用断前区间的前、中、后，最多 15 个；其他模式最多 4 个。 |
| 包含断裂 `fracture` | 尝试 2、3、5、10、20 秒目标时长，采用现有事件位置模板，最多 10 个。精确事件须位于窗口内；范围事件须完整覆盖上下界。素材不足时保留符合现有规则的自适应窗口。 |
| 断裂后 `post` | 从事件或范围上界后 0.5 秒开始，生成完整后段及可用分段，最多 4 个；跳过保护间隔后，至少还需 2 秒源素材。 |
| 未断裂 `no_fracture` | 尝试 2、3、5、10、20 秒及现有不同位置模板，最多 5 个。 |

事件及未夹紧候选至少 1 秒；目标时长可以与实际时长不同。按实际帧区间去重，窗口越界、素材不足或范围覆盖不完整时不生成，并保留原因。前后保护间隔和素材余量均按实际时间戳核对。`video_0093` 以正常播放的 733 帧及标注前后帧 727、728 为准，文件头另含播放前 38 帧。

**模式无法确定的断前窗口：** 新入口使用“其他模式”的靠近事件选窗方式，最多 4 个；模式标签仍保留原值，不改成确定模式。

## 3. 未夹紧按现象时刻单独选窗

当前未夹紧样本的断裂时间、断裂模式为“无”。生成这类片段时，锚点是**未夹紧现象出现的时刻**，不生成“断裂前／断裂后”含义的标签。断裂模式和位置按[标签说明](label.md)填写“无”，断裂状态仍依据片段画面判断。

以现象出现的源视频帧为锚点，分别尝试 2、3、5、10、20 秒窗口，每种长度最多取一个可用片段。优先居中；接近视频边界时可以移动窗口，使其保留目标时长并包含现象帧。源视频不足目标时长时，该窗口不生成，并记录素材不足。

当前标注表没有独立的未夹紧现象时刻字段。以下记录是生成未夹紧片段使用的源视频帧号，帧号从 0 开始；源视频内容摘要用于确认时刻对应的视频。缺少有效记录时不猜测、不借用断裂时间。

## 4. 文件名只说明来源、类型和序号

统一使用 `源视频ID_类型_序号.mp4`：

```text
video_0045_pre_01.mp4
video_0045_fracture_01.mp4
video_0045_post_01.mp4
video_0107_no_fracture_01.mp4
video_0002_unclamped_01.mp4
video_0107_coverage_01.mp4
```

同一来源、同一类型内，建议按源起始帧、结束帧排序后从 `01` 编号。文件名保持简短；完整参数写入对应记录。序号不代表内容身份，重新生成时以输入摘要和规则摘要区分批次，不覆盖已有结果。

## 5. 每个片段必须有对应的标注与生成记录

结果统一写入 `data/sub_video/`：`manifest.json` 保存逐片段记录，`summary.json` 保存数量与未生成原因，视频放在 `videos/`。每个片段记录原有三折训练、验证或测试归属。

| 记录内容 | 保留的信息 |
| --- | --- |
| 身份来源 | 子视频名称、源视频 ID。 |
| 原视频中的区间 | 原视频的起止时间和起止帧号。 |
| 片段实际信息 | 片段时长、帧数、帧率和分辨率。 |
| 对应标签 | 断裂状态、断裂模式、断裂位置、异常情况和断裂现象。 |
| 审核信息 | 审核状态、审核决定及修改说明。 |

## 6. 标签先作参考，再逐片段审核

五类标签使用[标签说明](label.md)中的名称和组合约束，不沿用旧脚本内部标签作为最终答案。

| 片段类型或源标签 | 初值与重点审核 |
| --- | --- |
| 断裂前 | 根据时间关系给出“未断裂”候选状态；模式、位置按标签规则填“无”。重点复核画面能否判断未断裂，以及视频异常和位置相关信息；源位置仅保留为参考。 |
| 包含断裂、断裂后 | 优先带入源视频已有模式、位置、异常和现象作为候选参考；断裂状态分别按窗口建议“发生断裂”“已断裂”，不能把源状态原样复制到全部片段。人工确认各项是否在片段中有依据。 |
| 模式或位置无法判断 | 保留“无法判断”，不自动补成确定标签；适用固定值“无”时遵循标签组合规则。 |
| 视频异常 | 有断裂时间时继续生成；逐片段确认异常是否影响判断。断裂前重点审核视频异常及位置，事件和断后保留原标签参考。 |
| 未夹紧 | 重点确认现象在片段中可见；模式、位置为“无”，断裂状态按画面判断。 |
| 爆炸性异常及其他现象 | 保留源标签参考，但不认定每个时间段都出现；按片段画面确认，并检查标签组合。 |
| 覆盖窗口 | 不推测断裂时刻；断裂状态初值取源标注（“无法确定”归一为“无法判断”），为“未断裂”时模式、位置记“无”；其余模式、位置及异常、现象沿用源标注（源为空则留空；未夹紧来源的模式、位置按标签规则为“无”）；逐片人工审核。 |

源标签、候选初值和审核后标签不可混写。异常和现象各项的“是／否／无法判断／未标注”分别保存。未审核、通过、修改后通过、拒绝需明确区分；所有拟发布片段都须人工审核，未审核或被拒绝的片段不进入发布数据。

## 7. 生成后验证帧对应

源视频按已有 ROI 决定重放，须与现有 ROI 文件及完整解码帧、时间戳一致。子视频裁剪后，再用独立取帧方式重放同一区间，核对文件、完整帧序列、时间戳和锚点映射。任一段不能验证则保留失败原因，不以图像相似度自动通过。

技术验证通过只说明已绑定输入与输出的帧对应；不能替代片段标签审核。输入、标注、ROI、窗口规则或工具链变化后，受影响结果须重新核对。

**待落实细节：** 仅有断裂时间点时的源帧定位办法。对未确定的情况记录待处理原因，不猜测锚点。

## 8. 验证档位与按来源并行

统一入口提供三档验证，由 `--verification {full,basic,none}` 选择；Python 入口 `run(..., verification="basic")` 的默认值同为 `basic`。批次如实记录实际使用的档位：`full` 批次不写 `verification` 键（隐含 `full`，与旧批次一致），`basic`／`none` 批次在 `manifest.json` 顶层、来源记录和 `candidate["output"]` 三层都写 `verification`。

| 档位 | 保留的检查 | 不做的检查 | 记录 |
| --- | --- | --- | --- |
| `full` | 第 7 节现状：源到 ROI 与 ROI 到片段的帧级重放、像素比对、时间戳核对、收据封条 | —— | `frame_preserving_replay` 收据、`full_decode: "passed"`；顶层、来源和片段记录都不带 `verification` 键 |
| `basic`（默认） | 身份绑定（源／ROI SHA-256、标注、折、策略）、候选与排除窗口清单、输出字节 SHA-256、由规划直接推导的 `frame_mapping`、输出 ffprobe（帧数等于 `end_frame - start_frame`、宽高与 ROI 一致） | 源级重放、参考序列重编码、像素比对、时间戳比对、片段收据 | `verification = {"mode": "basic", "frame_replay": "skipped", "reason": "user_requested_fast_generation"}`，六个字段的 `media`，`full_decode` 不写 `"passed"` |
| `none` | 身份绑定、候选与排除窗口清单、输出字节 SHA-256、规划推导的 `frame_mapping` | `basic` 的全部跳过项，另加输出 ffprobe | 同上但 `mode` 为 `"none"`，且不写 `media` |

**`basic`／`none` 不提供任何帧对应证明。** 记录里 `verification.frame_replay` 为 `"skipped"`，`verification.reason` 说明这是用户要求的快速生成；`frame_mapping` 只说明规划决定的源帧区间与输出帧序号，来自选窗结果而非解码核对。消费方（人工审核工具、训练与评价接入、任何自动判定）不得把 `basic`／`none` 批次当作已验证帧对应，也不得据 `frame_mapping` 反推像素对应；`--audit-only` 对这类批次会报出 `verification_mode` 与 `no_frame_level_replay` 等限制，同样不是帧对应证据。需要帧对应或时间戳证据时必须显式用 `--verification full` 生成。

`--jobs N`（默认 1，即串行）按来源并行裁剪：来源彼此独立，主要耗时是 ffmpeg 子进程。结果仍按来源 ID 顺序回收合并，`manifest.json` 与 `summary.json` 的顺序和内容与串行一致；清单只由主流程（单写者）写入，worker 只返回结果、不写清单。任一来源抛出未预期异常时整批失败，错误消息包含该来源 ID，磁盘上的清单保持可解析（原子写入，不留半截文件）。`--jobs` 可与 `--plan-only` 组合；`--verification`／`--jobs` 与 `--videos-dir`、`--audit-only` 不能组合。同一输出目录续跑（`--resume`）时，验证档位必须与批次记录一致，否则拒绝。

**失效条件：**一旦下游依赖帧对应证明、时间戳证据或 `full_decode` 标记（例如发布前校验改读 `frame_preserving_replay`、训练或评价接入自动判定帧对应），或 ffmpeg／ffprobe 工具链、ROI 生成方式、窗口规划规则变化后需要重新核对证据时，本节关于 `basic`／`none` 的结论不再成立，必须重新评估，或改用 `--verification full` 重新生成该批次。
