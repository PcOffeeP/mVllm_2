# mVllm_2 整体模型测评设计

**文档状态**：设计稿；不代表测评工具、协议或真实模型测评已经实施。

**失效条件**：当新五类测评设计被正式协议取代且本稿不再使用时作废；届时将仍有效内容并入 `docs/facts.yaml`，或删除本文件。

## 1. 整体测评：测什么

测评用于选择适合**辅助人工判断**的多模态模型，分别考察判断质量和运行性能。

**判断质量**关注模型对断裂状态、断裂模式、断裂位置、异常情况和断裂现象的判断，与人工标注有多一致。主要评价目标是：模型在与训练数据相近的条件下，处理不同源视频的表现。

**运行性能**关注模型处理单个片段需要多久，以及逐个处理一批片段时的耗时、完成情况和失败情况。

首轮覆盖单个片段的人工交互和逐个批量处理，并比较模型微调前后的表现。辅助人工场景下的结果不能自动证明模型适合独立运行；人工使用模型后是否提高判断质量或节省时间，需要另行验证。

## 2. 整体测评：怎么测

### 2.1 使用真实视频评价判断质量

保留现有真实视频划分目录和划分脚本。以**视频片段**作为基本评价单位，同时保留**源视频身份**。

人工依据完整评价片段标注五类标签；模型对同一片段给出判断，再按各类别分别比较。报告既展示片段结果，也说明结果涉及多少源视频，以及模型差异是否集中在少数源视频。

如有足够样本，可按材料、设备或拍摄条件分别分析真实视频。某组样本不足时，展示实际数量和观察结果，不强行比较。

### 2.2 在训练机测量运行性能

首个性能环境为 4090 训练机。

| 场景 | 测量与记录 |
| --- | --- |
| 单个请求 | 从视频进入训练机，到得到完整结果的处理时间 |
| 首次加载 | 单独记录加载耗时，与稳定运行耗时分开 |
| 逐个批量处理 | 整批耗时、完成情况，以及成功、失败和超时情况 |

常规样本和困难样本分别报告，并记录各组的选择依据与输入条件。首轮不做并发测评，以后根据实际使用需要单独设计。

成功请求的耗时分布需要同时注明成功数量和总请求数量；失败、超时及已耗时间另行记录。

### 2.3 开发比较与集中测试

开发阶段使用训练集和验证集完成训练、比较与调整；不对每个中间模型使用测试集。

集中测试前，确定有限的候选名单、模型权重、配置和评分规则。首轮使用验证阶段选中的冻结权重；入选的微调模型原则上与对应基础模型成对比较。后续重新训练产生的权重使用新的模型身份，另行评价。

通过标准在正式测试前，结合实际需求、标注分布和开发侧证据确定。判断质量、输出和运行性能分别评定；证据不足时报告“证据不足”。

## 3. 所有测评共同遵守的规则

### 3.1 标签与输出

模型必须输出五类结果：

1. 断裂状态；
2. 断裂模式；
3. 断裂位置；
4. 异常情况；
5. 断裂现象。

状态、模式和位置各为单选，不确定值统一为“无法确定”。异常和现象支持多选；人工对每个项目分别标注“是”“否”“无法判断”或未标注。

统一采用结构化 JSON 作为目标输出形式，具体字段名称和编码在后续协议设计中确定。模型可以附简短依据，但依据不是必填项，暂不评分；人工标注也不要求逐项书写依据。

#### 断裂位置的视觉判断

位置判断按以下顺序进行：

1. 明显位于试样伸出夹具的根部、夹持约束交界附近：**夹持根部**。
2. 不在根部，但断裂位置明显偏向某一夹持端：**标距外非根部**。
3. 画面足以判断相对位置，且不属于前两种情况：**标距内**。
4. 画面不足以判断断裂处与夹具、试样的大致关系：**无法确定**。

上下夹具都可见时，以两夹具之间可见的试样部分作为相对位置参照。断后发生回弹或滑落时，优先依据断裂发生时及其前后的画面判断。

这里的“标距内”是视频视觉分类，不表示已经测得精确工程标距。“明显偏向夹持端”需要使用非 test 的典型样例校准；校准后再统一现有位置说明，并检查已有标注受影响的范围。

未断裂或异常包含“未夹紧”时，模式和位置按固定组合填写“无”。

### 3.2 输出检查和人工诊断

| 检查方式 | 处理规则 |
| --- | --- |
| 严格格式检查 | 检查 JSON、必填字段、字段类型和允许的标签值 |
| 固定规则提取 | 按测评前冻结的规则，提取模型明确表达的内容；不能借助视频或人工答案补答 |
| 人工诊断 | 对自动无法读取或需要分析的输出补充检查，单独报告；不能算作自动成功 |

格式合法性与标签之间的固定组合分别检查。模型回答存在冲突时，保留原始回答，按实际输出逐类评分并记录冲突，不自动替模型修正。**冲突结果是否允许自动使用，留待后续决定。**

后续可以探索使用大模型辅助判读已有输出，但需要先与人工判读结果对照；直接让另一个模型复核视频属于另一个后续方向。

### 3.3 判断质量的计分与分母

五类标签分别评分。异常与现象逐项统计；异常优先关注漏报，同时报告误报。

#### 单选标签

| 人工标注 | 模型结果 | 处理 |
| --- | --- | --- |
| 有效标签，包括“无法确定” | 相同标签 | 该类判断正确 |
| 有效标签 | 不同的有效标签 | 该类判断错误 |
| 有效标签 | 缺字段、无法提取或请求失败 | 留在该类应评价样本中，记为未成功判断并记录原因 |

#### 异常和现象

| 人工逐项标注 | 模型对该项的结果 | 处理 |
| --- | --- | --- |
| 是 | 报告该项 | 识别出该项 |
| 是 | 完整列表可读，但未报告该项 | 漏报 |
| 否 | 报告该项 | 误报 |
| 否 | 完整列表可读，未报告该项 | 正确未报告 |
| 无法判断 | 报告或未报告 | 该项评价结果记为“无法判断”，保留原因 |
| 未标注 | 报告或未报告 | 不计为是或否，记录尚未标注 |
| 是或否 | 整个字段缺失、不可提取或请求失败 | 记为未成功判断，不能当作空列表或正确未报告 |

合法空列表表示模型没有报告该类中的任何项目；缺字段、无法提取或请求失败则是未成功判断。人工真值为“无法判断”或未标注时，不能依据空列表认定模型正确。

每个标签分别报告：

- **识别出多少**：正确报告该标签的数量，占人工明确标有该标签数量的比例；请求失败仍保留在应评价分母中。
- **报出的有多少正确**：模型报告该标签且人工标注明确的结果中，与人工标注一致的比例。
- 对应的数量、源视频覆盖和失败数量。

对应分母为零时报告“无法计算”。

#### 五类全部正确

该比例只在五类所需人工真值均足以判定的片段中计算，作为逐类、逐项结果的补充。单选“无法确定”是有效真值；异常或现象中存在无法判断、未标注项目时，不能直接当作该项为“否”。

符合分母条件的片段中，模型漏字段或请求失败不能记为五类全部正确。

### 3.4 失败、中断和无效结果

所有已提交请求均记录为成功、失败或超时。固定批次清单中，另行区分**已尝试失败**和**尚未处理**。

失败原因尽可能区分模型输出问题、程序或环境问题，以及原因待查。整轮中断时报告实际完成的覆盖范围；未处理片段不能算成模型错误，部分结果也不能包装成完整比较。

模型身份或输入清单无法确认时，不采信该方案结果。显存不足等问题应记录；量化或其他调整后的配置作为单独候选。

### 3.5 标注版本与结果留档

每轮比较使用明确的标注版本。用户可以复查部分样本；复查有助于发现问题，但不能作为独立标注者一致性的证据。

发现标注疑问时记录原因，由人工复查。确认修正后保留修正记录，让参与比较的模型使用同一份修正后的标注重新计分。

每轮保留模型、数据、标注、提示词、输入处理、评分规则和运行配置的身份，以及原始输出、失败记录和汇总结果。逐片段记录、失败清单和汇总可以复用现有组织方式；旧 v4.1 指标、阈值和性能协议不直接迁入新测评。

## 4. 模拟视频测评方案

Blender 模拟视频主要用于训练和补充诊断；模拟视频结果与真实视频结果分别报告。

拟使用的模拟视频可参考已有生成信息辅助标注，再由人工按当前标签规则确认。是否记录某个现象，以画面中是否可见为依据。

优先避免使用直接参考本轮验证或测试所用真实视频的模拟素材进行训练。模拟来源不清楚时先核查；真实视频划分保持不变。

选择有代表性的候选模型，开展三组训练数据对照：

1. 使用真实视频训练；
2. 使用模拟视频训练；
3. 使用真实与模拟视频混合训练。

三组使用同一个基础模型及初始版本，在同一份真实验证集上按统一口径比较，并记录各组的数据量、标签覆盖、训练配置和资源消耗。

首轮对照服务于实际选型。若三组数据量或训练配置不同，结果反映的是整套训练方案的差异；如需进一步判断模拟数据本身的影响，可另行设计条件受控的对照。

## 5. 多模型测评方案

### 5.1 统一比较依据

各候选模型使用同一批真实评价片段、同一份人工标注和同一评分口径。模型可以采用适合自身的输入处理和提示方式，实际配置须事前记录。

跨模型结果反映**模型与配置的整体表现**，不能单独归因于模型架构。

正式比较前，先完成模型适配调研，弄清各候选模型支持的输入、提示方式、资源需求，以及这些差异对比较的影响。

人工以完整片段为标注依据。模型只接收到部分画面时，保留能够取得的实际输入信息；必要时诊断关键画面是否进入模型输入。

### 5.2 比较微调前后与稳定性

每个具备条件的模型均比较微调前后的表现，并保留同一片段上的配对结果。

主要比较之外，选择部分有代表性的片段重复运行，观察判断、输出失败和耗时是否变化。重复次数及具体样本根据后续数据和资源情况确定；部分样本的稳定性结果不能代表所有视频。

### 5.3 简单基线与候选选择

简单基线依据训练侧数据确定并冻结，用于检查模型是否只是重复常见答案。超过基线不等于模型合格。

候选选择同时考虑综合表现、单项优势和实际可运行性。少样本类别报告实际证据及其范围；验证集中缺少某标签样本时，该项按证据不足处理，训练样本结果只作诊断。

未来若引入模型组合，仍使用相同的评价片段和口径，与单模型比较判断质量、等待时间和资源开销；组合方式另行设计。
