# 断裂位置典型样例校准（执行前工作指导）

**定位：** 执行前的固定指导，读者为后续执行者与用户。本文只规定做法与产出，不含任何已完成结果。

**失效条件：** `docs/label.md` 的位置判据、`data/annotation-table-full.csv` 列结构或 `data/splits/three-fold/test.json` 成员变更后，重新核定本文。

## 1. 目的与范围

- 目的：用**非 test 来源**（开发侧 89 源）校准「断裂位置」四类标签的视觉判据，产出供人工判读参考的典型样例图文。
- 组织方式：按三个易混淆对组织（见第 3 节），每例 3 张 ROI 帧 + 1 张广角确认图与一句判定理由。

**不做（越界即停）：**

- 不改 `data/annotation-table-full.csv` 任何单元格；不改 `docs/label.md`、`docs/roi-rules.md`。
- 产物不用于训练、不作为测评真值、不进入任何划分文件。
- 不据此重标或批量修正既有标签，只产出参考样例。

## 4. 截帧规格

每例 **4 张图 = 3 张 ROI 主图 + 1 张广角确认图**。"每例 3 张"指 ROI 主图数量，广角图为额外 1 张。

| 图 | 来源 | 帧号 | 用途 |
| --- | --- | --- | --- |
| ROI 断前最后一帧 | `/Users/pcoffeep/AgentPlayground/active-projects/TensileAgent-Finetune/data/roi/videos/<video_id>.mp4` | `断裂帧_前`（最后一帧仍连通，DF-013） | 连通状态下断裂位置最清楚 |
| ROI 首帧分离 | 同上 | `断裂帧_后`（第一帧已分离，权威锚点） | 定位断裂点 |
| ROI 断后帧 | 同上 | `断裂帧_后 + N`，`N = round(实测 fps)`（约 1 s），且须 `断裂帧_后 + N ≤ 视频总帧数 − 1` | 断后位移与夹具关系 |
| 广角确认 | `/Users/pcoffeep/AgentPlayground/active-projects/TensileAgent-Finetune/data/videos/<video_id>.mp4` | 与 ROI 断后帧同帧号 | 确认试样与夹具的整体关系 |

- **图片来源以 ROI 裁剪画面为主**：测评时模型看到的就是该视野；广角图只用于确认夹具关系，不替代 ROI 图。
- **帧号口径**：标注表帧号**从 0 开始**（`docs/label.md`:88）；取帧按 0 基索引定位，`ffmpeg` 的 `select='eq(n,<帧号>)'` 中 `n` 即该 0 基帧号。
- **时间范围替换规则**：若某视频 `断裂帧_前/后` 为空且 `断裂时间范围_下界/上界` 有值（全表 8 行，均属开发侧），则**下界帧作断前帧、上界帧作首帧分离帧**，换算 `帧号 = round(时刻 × 视频帧率)`，`视频帧率` 取标注表实测 fps（DF-013 由实测 fps 派生的同一口径）；断后帧仍为 `上界帧 + N`。
  - 例（第 9 例）：fps=30.00094 → 下界 161.9282596 s ≈ 帧 4858；上界 162.428243915024 s ≈ 帧 4873；断后帧 4903（总帧数 5009，未越界）。
- 本任务不执行任何 ffmpeg/截帧；以上仅为后续执行阶段的操作口径。

## 5. 判据写法约束

- 只写"看什么"，即画面里可直接指认的位置关系；不写因果猜测式表述。
- **禁止**：「看到回弹就是根部」「因为抖动所以是标距内」等以机制推断类别的写法。
- 每例一句判定理由，句式为「断裂处 + 与夹具/试样可见边界的关系」。

| 类别 | 允许写法（示例） |
| --- | --- |
| 夹持根部 | 断裂处落在试样伸出夹具的交界附近，断口紧贴夹口边缘 |
| 标距外非根部 | 断裂处明显偏向某一夹持端，但断裂处与夹具交界之间仍可见一段未断试样 |
| 标距内 | 断裂处位于两夹具之间可见试样段的内部，两侧均可见较长未断试样 |
| 无法判断 | 夹具或试样交界不在画面/被遮挡，无法指认断裂处与夹具的可见关系 |

- 判读顺序沿用 `docs/label.md` 第 5 节：先夹持根部 → 再标距外非根部 → 最后标距内。

## 6. 输出规格

执行后的目标结构（本轮已产出以下产物，与本规范同次提交）：

```
docs/label-calibration/
  README.md                                # 图文页，按三个易混淆对分节
  cases.csv                                # 逐例记录
  images/<video_id>_<帧号>_roi.png          # ROI 主图（无损 PNG）
  images/<video_id>_<帧号>_wide.jpg         # 广角确认图（JPEG）
```

- 文件名规则：**两种扩展名并存**——ROI 主图用 `images/<video_id>_<帧号>_roi.png`（无损 PNG），广角确认图用 `images/<video_id>_<帧号>_wide.jpg`（JPEG），目录内不出现其它扩展名。`<帧号>` 逐例取 `前帧号`/`后帧号`/断后帧号，广角图取断后帧号，与 `cases.csv` 一致。
- `cases.csv` 字段（顺序固定，共 9 行 + 表头）：`video_id`、`易混淆对`、`人工标签`、`前帧号`、`后帧号`、`roi图路径`、`广角图路径`、`判定理由`。
- 条数：9 例 × 4 图 = **36 张**（27 张 `_roi.png` + 9 张 `_wide.jpg`）。
- 格式与体积：**单张 ≤ 220 KB**、**总量 ≤ 8 MB**（README/CSV 不计）。格式取舍的实测依据：
  - 本机无 `pngquant`/ImageMagick/Pillow，无有损 PNG 压缩链路可用；
  - 1280×720 的广角帧存 PNG 实测 808.3 KB，最高压缩（`-compression_level 100 -pred mixed`）仍 758.8 KB，超单张 220 KB 上限，故广角图改 JPEG `-q:v 3`，实测 92–109 KB（`video_0045` 源分辨率小，为 20.5 KB）；
  - ROI 图尺寸 ≤ 492×656，PNG 实测最大 190.5 KB（`video_0045_5530_roi.png`），未超上限，保持无损 PNG；
  - 实测合计 36 张 **2,318,389 B（2.21 MiB）**，单张最大 190.5 KB，均在上限内。
- **默认进 Git**：36 张合计 2.21 MiB；ROI 图保持无损，若后续为减小体积另做有损压缩，须复核断口与夹具边界仍可辨认。
- 超阈值替代方案：若总量 > 8 MB，把图片放到 `data/label-calibration/images/`，并**在 `.gitignore` 显式新增** `/data/label-calibration/images/`（现有规则只忽略视频，PNG 不会被自动忽略），用 `git check-ignore -v` 复核；`README.md` 改引用该路径并记录尺寸与体积清单。
- "干净"的定义：目录内只有上表三类文件；不含中间产物、候选未用帧、截图脚本、临时裁剪文件。

## 9. 已知限制

- **ROI 与源视频帧号是否严格同序未在本稿核实**：执行时须比对 `data/roi/videos/<video_id>.mp4` 与源视频的总帧数/时长，与标注表 `视频总帧数`、`视频帧率` 对照；不一致时不得直接沿用标注帧号，须记录换算口径或停止该例，并把结论写入 `README.md`。
- 单人判读，无第二标注者；本校准**不构成标注者一致性证据**，一致性需独立样本与独立标注者另行验证。
- 9 例为说明性样例，不覆盖全部工况，不能据此推断位置标签的整体正确率或模型表现。
- 画面压缩（ROI 裁剪 + PNG 压缩）可能影响细节判读；判读以原视频/原 ROI 帧为准，图片仅作参考。
- 时间范围行的帧号由 `round(时刻 × 实测 fps)` 估算，变帧率视频该换算为估算值（与 `docs/label.md`:88 同口径）。
