# 开发集初步子视频结果与下一轮规则建议

**2026-11-08 已完成旧窗口规则加严初裁：89 个开发集源视频中，48 个生成了 813 个初步片段，41 个保留原因并跳过。** 813 个片段均裁剪成功；这些结果用于检查旧规则的适用情况，尚未填写本轮五类片段标签、人工审核或发布。

本轮按用户确认的顺序推进：先初裁并总结，再提出新规则供用户审查，审查后才按新规则重新生成。固定划分保持原样，测试集媒体未传入本次训练机工作区，也未生成测试片段。

本文保留旧规则初裁的历史结果和当时待审建议。用户确认后的帧对应批次已有独立的[本轮结果](subvideo-aligned-results.md)；本页的 813 个片段及跳过统计不代表新批次状态。

## 3. 813 个片段来自 48 个断裂源视频

| 窗口角色 | 片段数 | 涉及源视频数 |
| --- | ---: | ---: |
| 断裂前 `pre_event` | 482 | 43 |
| 包含事件 `transition` | 283 | 48 |
| 断裂后 `post_event` | 48 | 21 |
| 合计 | 813 | 48 个不同源视频 |

片段时长为 **1.5–20 秒**，累计约 **5,217.65 秒**，视频合计约 **91.31 MiB**。48 个有输出来源各生成 3–28 个片段。按同源帧区间存在正长度交集、每对只计一次计算，共有 3,427 对时间重叠窗口，其中断前／包含事件之间 933 对、包含事件／断后之间 331 对。它们继承同一来源的划分，不能把 813 个片段或累计时长当作独立试验数量、互不重复的时长或样本充分性的证据。

本轮 48 个有输出的源视频在源级标注中均为“发生断裂”。开发集的 3 个源级“未断裂”视频分别因未夹紧、视频异常和帧时间检查未通过而跳过，因此没有 `stable_negative` 角色的候选。482 个断裂前窗口仍可能在片段级表现为未断裂；窗口角色不能替代看片后的最终标签。

各片段继承源视频的三折归属，没有另做划分：

| 1 | 572 | 241 |

每折统计都对应同一批 813 个片段。数字只说明当前候选的归属，不证明每类标签在每折都充分。

## 4. 41 个源视频为何暂不生成

| 工具记录的首个跳过原因 | 源视频数 | 本次含义 |
| --- | ---: | --- |
| 帧时间戳不符合严格固定帧率检查 | 24 | 当前工具不能据此可靠使用旧帧率选窗；尚不能直接判定实际原因或素材不可用。 |
| 视频异常 | 8 | 旧初裁准入规则不接受这类源记录。 |
| 缺少精确事件时间或相邻前后帧 | 3 | 仅有范围或边界不满足要求时不补造时间点。 |
| 爆炸性标注需要新规则 | 2 | 当前异常标注与旧机制选窗的对应关系不直接套用。 |
| 源状态不支持或不确定 | 2 | 缺少旧规则可接受的明确源状态。 |
| 旧窗口机制映射不支持 | 1 | 不能可靠决定旧选窗分支。 |
| 未夹紧 | 1 | 旧初裁准入规则不接受。 |
| 合计 | 41 | 均保留源记录和原因。 |

工具按检查顺序记录首个阻挡原因，一个视频可能还存在其他限制。因此，表中“缺少精确事件边界 3 个”不等于开发集中只有 3 个时间信息不完整的视频；被更早检查挡住的视频不会继续检查后面的条件。

对这 24 个来源，随后在训练机用同一工具分别检查源视频和 ROI，共取得 48 条逐项探测记录：

| 源视频检查 | 对应 ROI 检查 | 来源数 |
| --- | --- | ---: |
| 未通过 | 通过 | 19 |
| 未通过 | 未通过 | 5 |
| 通过 | 未通过 | 0 |

因此，24 个源视频均未通过当前固定帧率时间格检查，其中 19 个对应 ROI 通过、5 个 ROI 也未通过。这定位了本次阈值检查在哪一侧失败，仍不能单凭失败认定实际变帧率，也不能说明源与 ROI 的全部帧对应关系已经核实。

另对 29 个未通过媒体读取轻量 FFprobe 元数据，命令均退出 0。平均帧率与名义帧率不一致也出现在部分通过检查的 ROI 中，因此这项元数据差异不能单独解释失败原因。下一轮仍需检查实际时间戳偏差和帧对应，不能直接放宽阈值或将 24 个来源全部归为真实变帧率。

## 6. 实际验证及证据范围

本次实际处理使用训练机独立工作区中的代码提交 `9769920`。独立 Python 3.11 环境的 `linux-gpu` 检查通过；没有加载模型或启动训练。低优先级运行的 `--plan-only` 和同目录 `--resume` 均退出 0，最终清单 `complete=true`、`plan_only=false`，813 个候选全部为 `cropped`，失败为 0。

工具逐片段核对帧数、分辨率、帧率、时长并完整解码，813 项均记录 `full_decode=passed`。结果同步回本机后，主 Agent 核对了全部输出文件摘要、48 个已用来源及 ROI 摘要、全部输入摘要；实际视频集合与清单一致。训练机传入的源与 ROI 媒体各 89 个，均对应开发集，21 个测试 ID 没有媒体或候选。

代码有 28 项合成测试通过，覆盖旧窗口结果、事件后 2 秒边界、测试隔离、摘要变化、恢复和不覆盖等行为；独立代码核查确认迁入的 16 个旧窗口函数与来源函数一致。合成测试和代码核查支持工具行为，真实媒体检查支持本批文件的可读取性及身份；它们均不能证明片段视觉标签正确、人工审核完成、样本充分或模型效果达标。

本次原始运行日志保存在训练机 `/tmp/subvideo-pilot-plan-20261108.log` 和 `/tmp/subvideo-pilot-crop-20261108.log`，临时日志路径不作为长期结果身份；可追溯输入、输出和逐条状态以项目中的 manifest 为准。

补充时间戳诊断的逐项日志为训练机 `/tmp/subvideo-timestamp-investigation-20261108.log`。首次脚本在 48 条探测记录逐项写入后，因汇总中的 tuple 键无法转为 JSON 而退出 1，原计划随后的轻量元数据部分没有执行；主 Agent 随后独立解析已有逐项日志，确认 24 对来源的计数。轻量元数据另行补跑，记录在 `/tmp/subvideo-timestamp-metadata-20261108.log`。这轮诊断的汇总写出失败不能写成整轮命令成功，也不改变已完成初裁命令的退出码；上述临时日志同样不作为长期结果身份。
