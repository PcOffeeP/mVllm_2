# 微调数据集建设实施方案

> 状态：已批准
> 版本：2
> 项目计划：docs/PROJECT_PLAN.md
> 项目计划版本：7

## 步骤目标与范围

本步骤把现有 110 个原始视频和 CSV 标注转化为可复现、无原视频级泄漏、能够被 LLaMA-Factory 和 MiniCPM-V 4.6 实际加载的训练与验证数据，并生成与真值隔离的冻结测试输入清单。完成后应具备权威视频库存、训练采用标签、确定性三折划分、连续视频样本、实际抽帧映射、ShareGPT 多模态 JSON 和完整质量报告。

本步骤只建设数据基础，不执行正式微调、不选择 checkpoint、不实现 Agent Runtime，也不使用冻结测试集评估模型。执行前必须先落实已批准的模型—Agent 接口方案 v3 中与五字段输出、MiniCPM-V 实际视频处理器和抽帧元数据有关的公共能力。

## 实施方案

### 标签治理与五类训练语义

`data/02_annotations/all_videos_tag.csv` 的原始字段保持只读。代码现有的 `has_fracture_canonical`、`location_canonical` 等字段名可以继续使用；本文把它们称为“训练采用值”，即发生字段冲突后实际用于样本构建的标签。[断裂行为分类指南](../../assets/frac_mode.md)只用于理解视觉现象，不得覆盖 CSV 或已确认的训练语义。

权威库存按具体类型而不是旧的粗粒度 `is_abnormal` 划分：

| 视频组 | 数量 | `has_fracture` 训练采用值 | `type` | 时间标签 | 允许生成的样本 |
|---|---:|---|---|---|---|
| 确认断裂且时间可靠 | 88 | `true` | 七种断裂模式之一 | 可靠 | 完整视频、聚焦正样本、断裂前后负样本 |
| 确认未断裂 | 7 | `false` | `未断裂` | 不适用 | 完整视频、固定位置负样本 |
| 未夹紧 | 1 | `false` | `未夹紧` | 不适用 | 仅完整视频 |
| 视频异常，是否断裂不确定 | 7 | `null` | `视频异常` | 不可用 | 仅完整视频 |
| 视频异常，确认断裂但时间不可靠 | 7 | `true` | `视频异常` | 不可靠 | 仅完整视频，`fracture_between=null` |

CSV 中 `is_abnormal=TRUE` 不能把 `type=未断裂` 的 7 个视频改成视频异常；它们的训练异常标记应为 false。`type=视频异常` 的 14 个视频按 `has_fracture` 和事件字段区分上述两种异常。确认断裂但时间不可靠的视频即使带有数字时间或帧号，也只能把这些值保留在追溯记录中，不能生成精确区间监督。

训练采用值至少包括 `has_fracture_canonical`、`location_canonical`、`is_abnormal_canonical`、`video_anomaly_kind`、`event_time_reliable`、`is_label_conflict` 和治理原因。两类视频异常分别使用 `fracture_presence_unknown` 与 `fracture_time_unknown`。除 88 个确认断裂视频外，`location_canonical` 均为 `null`；训练数据不生成人工 `unknown` 位置。

### 视频级划分

划分以原视频为最小单位，固定随机种子为 42。原视频数量不超过两条的三个稀有断裂类别共 5 个视频组成训练专用池，加入每个 fold 的训练集，不进入验证集或冻结测试集。其余视频按类型和有效位置分层，先划出约 20% 的独立测试集，再对剩余视频进行三折训练与验证划分。

标签治理规则变化后必须重新生成划分，不沿用旧文件中的分层结果。划分完成后冻结测试视频 ID、排序后的清单和清单哈希。一个原视频产生的全部连续子视频、样本和追溯记录只能跟随原视频进入同一集合；验证和测试数据不进行复制、过采样或类别平衡。

### 连续视频候选样本

所有模型媒体保持连续时间轴，由 MiniCPM-V 4.6 自身视频处理器均匀选择最多 8 帧。项目不预先抽帧，也不为训练指定额外采样 FPS。完整视频样本直接引用原视频；只为最终选中的聚焦或负样本生成连续子视频，不复制整段原视频。

确认断裂且时间可靠的视频建立以下正样本候选池：

- 一个完整视频候选。
- `3s`、`10s`、`30s` 三种聚焦长度。
- 每种长度让断裂事件位于子视频的 `20%`、`35%`、`50%`、`65%`、`80%` 五种相对位置。

候选不是无条件训练样本。每个候选必须通过真实 MiniCPM-V 4.6 视频处理器取得实际帧序列；只有存在唯一相邻索引满足 `sampled_frame[i] < event_frame_original <= sampled_frame[i+1]` 时才保留。若不能包围事件，先调整连续片段边界重新生成；仍不满足时排除并记录原因。`fracture_between` 不得使用首尾替代值或边界哨兵。

负样本候选包括：

- 确认断裂视频中与断裂事件保持至少 1 秒安全间隔的断裂前片段。
- 确认断裂视频中的少量断裂后困难负样本，用于区分“正在发生断裂”和“已经断裂”；所有实际采样帧必须晚于事件，持续撕裂或视觉含糊的候选排除。
- 7 个确认未断裂视频的完整视频，以及 `3s`、`10s`、`30s` 在前部、中部、后部固定位置生成的连续候选。

未夹紧和两类视频异常只保留完整视频，不通过重叠切片放大稀少来源。人工负片段统一使用 `has_fracture=false`、`type=未断裂`、`fracture_between=null`、`location=null`，父视频断裂模式和位置只保存在顶层追溯信息中。

训练集先建立完整候选清单，再按固定种子、每个原视频上限和类别上限选择媒体，使确认断裂正样本与可靠负样本比例保持在 `1:1` 至 `2:1`。验证集保留自然分布。所有训练 assistant 答案使用 `confidence=1.0` 表示监督标签确定，不把它解释成经过校准的推理概率。

### 实际抽帧、媒体与样本格式

训练数据构建器调用接口方案规定的项目侧预处理适配层，检查 MiniCPM-V 4.6 实际子处理器最大帧数为 8，并取得每个候选实际选择的临时视频帧序号和时间戳。连续子视频生成清单负责把这些值映射回原视频帧号和时间戳。不能只使用 LLaMA-Factory 外层 `video_maxlen`、理论 FPS 或均匀间隔公式生成标签。

在全量生成前，使用覆盖完整视频、3 秒、10 秒、30 秒、不同类别和不同事件位置的校准集，通过数据构建适配层和 LLaMA-Factory 实际 batch 加载链路比较处理器版本、最大帧数、抽帧数量、顺序和映射。两条链路必须完全一致；缺少抽帧元数据、实际超过 8 帧或映射不一致时停止。

训练和验证样本采用 ShareGPT 多模态格式：`messages` 依次包含与接口方案完全一致的固定 system prompt、包含一个 `<video>` 标记的 user prompt、严格五字段 assistant JSON；`videos` 只包含对应的一个连续视频路径。顶层追溯信息至少保存来源视频、片段范围、样本类型、训练采用标签、父视频类型与位置、实际抽帧映射、处理器指纹、选择原因和排除原因，不进入 assistant JSON。

永久帧图只保留校准和人工审计样本，不为全量训练样本保存。连续子视频、帧缓存、元数据和大型 JSON 继续放在仓库忽略目录中；提交到仓库的只包括生成逻辑、配置、数据清单哈希和不含敏感媒体的统计报告。

### 测试真值隔离

冻结测试输入只包含视频 ID、媒体定位信息和清单版本，不包含事件时间、事件帧、断裂模式、位置、assistant 答案或根据真值生成的切片。模型、Agent、CLI 和普通 UI 推理不得读取 CSV 真值。单独保存的评分真值仅供评估模块在全部预测完成后读取，且测试清单哈希必须与预测产物一致。

## 执行清单

- [ ] 落实接口方案 v3 的五字段契约和真实 MiniCPM-V 预处理适配层，确认子处理器最大帧数为 8，并能取得实际抽帧索引、时间戳和处理器指纹。
- [ ] 重建 110 个视频的权威库存和训练采用标签，正确区分 88 个确认断裂、7 个确认未断裂、1 个未夹紧及两组各 7 个的视频异常，同时保留所有 CSV 原字段和治理原因。
- [ ] 使用更新后的五类语义重新生成确定性视频级划分，建立 5 个视频的训练专用稀有池，冻结约 20% 测试清单及其哈希，并验证所有集合的原视频级隔离。
- [ ] 建立完整视频、三种聚焦长度和五种事件位置的正样本候选，以及断裂前、少量断裂后和确认未断裂视频的负样本候选；输出候选数量、来源和预计磁盘占用。
- [ ] 对所有候选运行真实处理器抽帧与标签计算，只保留能正确包围事件的正样本，排除时间不可靠、持续撕裂、重复帧、越界和无法映射的候选并记录原因。
- [ ] 按固定种子和来源上限选择训练样本，保证正样本与可靠负样本比例为 `1:1` 至 `2:1`，同时保持验证集自然分布且未夹紧、视频异常只使用完整视频。
- [ ] 生成最终连续子视频、实际抽帧映射、顶层追溯信息和 ShareGPT 训练/验证 JSON；生成不含真值字段的冻结测试输入及独立评分真值。
- [ ] 使用校准集比较数据构建适配层与 LLaMA-Factory 实际 batch 的抽帧数量、顺序和映射，并分别对三个 fold 完成至少一个真实 batch 的数据加载冒烟检查。
- [ ] 运行全量质量校验，检查媒体、五字段组合、类别闭集、严格相邻索引、处理器指纹、正负比例、来源上限、原视频泄漏、测试真值隔离、清单哈希和失败记录；任一强制条件失败时不得发布数据版本。
- [ ] 冻结数据版本，记录代码提交、配置哈希、处理器版本、输入视频清单、划分清单、样本清单、统计报告和磁盘占用，供后续微调实施方案引用。

## 预期结果

完成后，本地生成一份版本化数据基础：110 视频权威库存、处理冲突后的训练标签、训练专用稀有池、三折训练/验证划分、冻结测试清单、必要连续子视频、实际 MiniCPM-V 抽帧映射、ShareGPT JSON、独立评分真值和全量质量报告。

数据产物能够被 LLaMA-Factory 实际加载，训练答案与模型真正看到的最多 8 帧严格对应；两种视频异常得到不同训练表达但都不会伪装成未断裂或精确断裂。完成本步骤只说明数据可用于训练，不代表模型效果已经达标。

## 验收标准

- 权威库存恰好覆盖 CSV 中的 110 个视频 ID，能够复现 88 个确认断裂、7 个确认未断裂、1 个未夹紧、7 个是否断裂不确定的视频异常和 7 个断裂时间不可靠的视频异常。
- 7 个 `type=未断裂` 视频的训练异常标记为 false；两类视频异常分别使用 `has_fracture=null` 和 `has_fracture=true, fracture_between=null`，不可靠事件时间和帧号不进入精确监督。
- 88 个确认断裂视频的 64 个标距内和 24 个标距外位置保持不变；其他类别位置均为 `null`，训练数据中不存在人工 `unknown`。
- 三个稀有断裂类别共 5 个视频只进入每折训练集；冻结测试集约占可分配视频的 20%，与所有训练、验证来源视频互斥，并具有稳定清单哈希。
- 同一原视频的全部候选、媒体和训练样本只属于同一集合；每个普通非测试视频在三折验证集中恰好出现一次。
- 所有输入媒体保持连续时间轴且未经项目侧预抽帧；MiniCPM-V 4.6 实际子处理器最大帧数为 8，所有样本保存实际抽帧数量、顺序、时间戳和源视频映射。
- 所有正常断裂正样本均满足 `sampled_frame[i] < event_frame_original <= sampled_frame[i+1]`，`fracture_between` 严格为 `[i,i+1]` 且未越界；全量产物不存在边界哨兵或根据理论 FPS 推算的标签。
- 断裂后困难负样本与事件至少间隔 1 秒且不包含持续撕裂；未夹紧和视频异常没有通过局部切片扩增，所有人工负片段不泄漏父视频断裂答案。
- 训练集确认断裂正样本与可靠负样本比例位于 `1:1` 至 `2:1`，验证集和测试集没有为平衡而复制样本。
- 数据构建适配层与 LLaMA-Factory 实际 batch 对校准样本给出完全一致的处理器指纹、帧数、顺序和映射，三个 fold 均能成功加载至少一个真实 batch。
- 测试输入不含任何真值或真值派生切片；模型和 Agent 推理不读取 CSV，独立评分真值只能在预测完成后使用。
- 全量校验在产物完整合法时成功；媒体缺失、非法五字段组合、抽帧元数据缺失、映射不一致、原视频泄漏、真值泄漏或清单哈希不匹配时失败。

## 风险与待确认事项

- [非阻塞] MiniCPM-V 4.6 实际子处理器参数可能不受 LLaMA-Factory 外层配置控制；数据发布必须以真实子处理器检查和 batch 对照结果为准。
- [非阻塞] 连续聚焦与负样本仍会占用磁盘；先生成候选清单并估算，再只生成最终选中的媒体，完整视频保持原路径引用。
- [非阻塞] 断裂后画面可能仍包含持续损伤过程；将其限制为少量困难负样本并排除视觉含糊片段，不能为了平衡强行保留。
- [非阻塞] 所有训练答案使用 `confidence=1.0`，该字段不能据此视为已经校准；可靠性和阈值只能由后续模型验证确定。
