# 数据划分设计：保留测试集，调整开发三折

**规则已由用户确认；2026-11-07 已生成并核验源视频划分。** 固定已有 21 个 test 视频，按用户确认的来源组重排 89 个开发视频，取消旧六条永久训练的特例，让每个开发来源恰好验证一次。结果见[本轮划分结果](data-split-result.md)；划分不保证模型效果改善。

## 1. 先看关键规则

train 是训练集，val 是开发阶段的验证集，test 是测试集。三折对应**三次独立的模型训练与验证运行**：每次用一折来源作 val，其余两折来源作 train，不是把同一个模型连续训练三轮。

| 关键规则 | 本稿的具体建议与边界 |
| --- | --- |
| 固定测试成员 | 保留已有 21 个 test 视频；只调整 89 个开发视频。开发重排不能给 test 增添稀有正例，也不能抹去历史暴露。 |
| 先按来源绑定 | 同一试样或同次试验的视频及派生片段属于同一来源组；一折内不能同时进 train 和 val，也不能跨开发与 test。不能为凑数量拆组。 |
| 每个开发来源轮转一次 | 每个获准开发组恰好进一次 val、另外两次进 train；单例也按这条规则轮转，具体见第 2 节。 |
| 先求合法，再比较好坏 | 输入与标签合法、来源完整、划分互斥且完整等条件必须先满足。合法候选再按“覆盖缺口 → 视频数 → 标签比例 → 共现 → 固定排序”比较，前项同分才看后项。 |
| 平衡五类、11 个字段 | 状态、模式、位置分别平衡；异常 3 项、现象 5 项逐项处理，不沿用旧混合类型，也不把 11 个字段拼成大量小组合。不确定值、固定“无”和空白分开处理，见附录 B2。 |
| 数量只是目标 | 若 89 个视频各自独立，val 目标为 30／30／29，train 为 59／59／60；实际受来源归组和覆盖约束影响，不保证精确达到。 |
| 不用模型结果选划分 | 划分评分只比较开发 train／val 的标注统计与来源分配，不使用模型预测、验证表现或 test 得分，不代表准确率或模型能力。 |

用户已确认 110 个源视频分别来自独立试验，本轮据此将每个视频作为一个来源组；文件哈希检查未发现完全相同的视频，但未证明不存在近似素材。21／89 为当前 test／开发视频 ID 基线。若发现同源视频跨 test 与开发，暂停该组，由用户决定隔离、排除或移动；模拟来源的使用边界仍待核查，正式条件见附录 B1。

## 2. 极少数正例在三折中到底去哪

下面用 `g` 表示**开发集中具有某标签值证据的独立来源组数**。表中只看同一个标签的正例，A、B、C 各代表一个独立来源组；先假设它们可分到不同 val 折、其他标签不造成冲突。这些都是解释规则的假设示例，不是已生成的分配。同源视频或子片段必须一起移动，不能当作新的独立正例。

### 只有 1 个独立正例：两次训练，一次验证

例如，唯一“未夹紧”视频 `video_0002` 若经核实代表唯一独立正例组，并假设把它分到 fold 0 的 val：

| 独立运行 | 该正例的去向 | train 中该标签正例组数 | val 中该标签正例组数 |
| --- | --- | ---: | ---: |
| fold 0 | val | 0 | 1 |
| fold 1 | train | 1 | 0 |
| fold 2 | train | 1 | 0 |

因此它参与**两次独立模型的训练、一折模型的验证**。fold 0 的模型训练时没有该标签正例，留出结果只能作个案，不能证明通过本轮训练学会了该标签。fold 1、2 的模型虽然训练见过这个正例，但它不再作为这两个模型的验证样本，无法用它证明对独立正例的识别能力；这两折也无法估计该标签的正例召回。

三折如何用于最终模型选择、是否再用全部开发集重新训练，**本划分方案尚未确定**。不能据单例的轮转去向，假定最终模型必然见过或没见过它。

### 有 2 个独立正例：分到两个 val 折，第三折只有训练正例

若 A、B 分别进入 fold 0、1 的 val：

| 独立运行 | train 中的正例组 | val 中的正例组 |
| --- | --- | --- |
| fold 0 | B（1 组） | A（1 组） |
| fold 1 | A（1 组） | B（1 组） |
| fold 2 | A、B（2 组） | 无（0 组） |

每个正例仍是两次 train、一次 val。两个有正例验证的运行，各有另一个独立正例用于训练；第三折的 val 没有该标签正例。若 A、B 实为同源，则只能按 `g = 1` 处理。当前“爆炸性断裂”有 2 个开发正例视频，只有来源核实后才能判断是否适用此例，不能据此声称它们已分到两折。

### 有 3 个或更多独立正例：争取每折 train、val 都覆盖

若恰有 3 个独立正例 A、B、C，且可分别进入三个 val 折，则：

| 独立运行 | train 中的正例组 | val 中的正例组 |
| --- | --- | --- |
| fold 0 | B、C（2 组） | A（1 组） |
| fold 1 | A、C（2 组） | B（1 组） |
| fold 2 | A、B（2 组） | C（1 组） |

`g ≥ 3` 时，目标是每折 train 和 val 各至少有 1 组；更多正例再争取比例接近。开发中“开裂”和“断后脱夹”各有 3 个正例视频，但只有各自确属 3 个独立来源组且其他约束允许，才可能达到表中的覆盖。若 `g = 0`，则无法靠重排获得该标签证据，不能估计该值的正例识别表现。

**这些目标可能冲突，不能逐标签独立分配后再拼在一起。** 同一来源组可以同时带有多个标签，移动它会同时改变这些标签的分布；来源绑定也可能把多个正例视频合成一组。数量上，`g = 1` 或 `2` 已不可能三折 val 都有正例；`g ≥ 3` 也不保证所有标签的目标能同时满足。附录 B3 要求区分数量不足、已证实的组合冲突与本次搜索未找到，不把搜索失败写成无解证明。

切出更多同源子片段不会增加 `g`。固定 test 当前没有未夹紧、爆炸性断裂和开裂正例，重排开发集也补不上这些缺项。独立正例少于 3 组的值只作个案，不用于稳定排名模型；达到 3 组仍不证明样本充分或统计稳定。

## 3. 划分“评分”怎样选出候选

这里评分的对象是**数据分配方案**。先排除不满足附录 B1 正式条件的分配，再仅凭开发标注与来源统计比较合法候选，不运行模型，也不以模型准确率或 test 分数选划分、种子。下表从上到下比较，**只有前一项完全同分，才比较下一项**；这叫字典序比较，不把各项加权相加成一个总分。

| 顺序 | 比较什么 | 怎样算更好 |
| --- | --- | --- |
| 1 | 覆盖缺口 | `g ≥ 3` 的确定值，累计未达“train、val 各至少 1 组”的折数；`g = 2` 累计距离“两折 val 覆盖”所缺折数。总缺口越少越好，每个标签值一票；不要求单例三折覆盖。 |
| 2 | 源视频数量 | 先比较三折 val 相对开发视频数 1/3 的最大绝对偏差，再比较绝对偏差之和；偏差超过 2 个源视频时预警，不拆组。 |
| 3 | 各字段的标签比例 | 比较各值在 val 的来源组数与总支持组数 1/3 的偏差；确定值权重 1，“无”和不确定值 0.5。这些权重只用于本项，不改变前后项的优先级。 |
| 4 | 两标签共现 | 只比较至少 6 个独立组支持的共现，使其比例更接近；不要求所有组合出现，不把不可能的组合算作缺项。 |
| 5 | 固定排序 | 仍同分时按稳定 group_id 的折号序列，取字典序最小者，避免人工挑结果。 |

**假设比较示例：** 89 个开发视频各自独立，开裂恰有 3 个独立正例；A、B、C 都满足正式条件，其他标签覆盖相同。下表是假设候选，不是实际搜索结果。

| 候选 | 各折 val 开裂正例组数 | 总覆盖缺口 | 各折 val 视频数 | 最大人数偏差 | 人数偏差之和 |
| --- | --- | ---: | --- | ---: | ---: |
| A | 1／1／1 | 0 | 28／30／31 | 5/3 | 10/3 |
| B | 2／1／0 | 1 | 30／30／29 | 2/3 | 4/3 |
| C | 1／1／1 | 0 | 30／30／29 | 2/3 | 4/3 |

A 与 B 比，先看覆盖缺口，A 的 0 小于 B 的 1，因此选 A，不能用 B 更均衡的视频数抵消覆盖缺口。A 与 C 比，覆盖同为 0，才比较视频数，选 C；此时不用再比较标签比例。如果前两项也同分，才继续看第 3、4、5 项。

精确比例公式及复现记录见附录 C。拟用 seed 42 至 141 的 100 个起点搜索，只接受按上述顺序严格更好的移动或交换；有界搜索不保证全局最优。本轮已完成 100 个起点的搜索并生成结果；未证明全局最优，详见[本轮划分结果](data-split-result.md)。

## 4. 相对旧规则改了什么，代价是什么

旧规则按混合类型 `type` 划分：总数不超过 2 的类型永久放进 train，其余数据先分出 test，再分三折。`type` 混合了断裂模式、异常和位置，不能直接用于本轮五类、11 字段标签。

此前只读核查显示：110 个视频中，21 个属于 test、89 个属于开发；三折 val 只覆盖其中 83 个，另 6 个一直训练。三折 val 都没有未夹紧和爆炸性断裂正例；fold 2 还没有开裂和断后脱夹正例。旧规则、六条视频及统计依据见附录 A。

推荐方案取消永久训练特例，用全部获准开发来源轮转，并按新字段覆盖选优；代价是旧开发结果不能与新结果直接比较，而且须接受第 2 节的稀有标签限制。保留测试成员可以减少因成员变化带来的比较差异，但这批 test 有历史使用记录，不能称为从未暴露的独立测试集。

| 其他选择 | 需要接受的代价 |
| --- | --- |
| 沿用全部旧清单 | 保留当前验证覆盖缺项 |
| 让单例永久用于训练 | 放弃单例留出评价，不再满足全部开发来源都验证一次 |
| 重划全部 110 个视频 | 改变测试成员组成，已有暴露记录仍须保留；本稿不推荐作为默认选择 |

### A1. 旧规则及可核对的结果

旧规则来自原项目 [source_bootstrap.py](../../mVllm_2/pipeline/source_bootstrap.py) 的 `_rare_pool`、`_compute_strata`、`stratified_split` 和 `_split_payload`。以下为静态规则说明，不是重新运行旧入口的建议：

1. 按全部旧 `type` 计数，总数 ≤ 2 的类型进入永久训练稀有池，不进 test 或 val。
2. 其余记录位置缺失者进 `N/A`，其他先按 `type × location_canonical` 分层；≤ 2 条的小组合按位置合为 `rare_fracture`。若仍有非 `N/A` 小层，整批退回 `type_only`，位置缺失者仍为 `N/A`。
3. 默认 test 比例 0.2、三折、seed 42。同一伪随机发生器按各层输入顺序打乱；层大小 ≥ 2 时，test 配额先取 `max(1, round(层大小 × 0.2))`，再逐次减少，尽量给普通开发池留至少 3 条。逐层取整，所以总数未必精确为 20%。

5. 保存 ID、计数、方法、种子等元数据；最终 ID 排序不证明随机过程的输入顺序已固定。

## 附录 B：推荐方案的完整规则

### B1. 来源隔离与正式划分条件

“来源组”指同一试样或同一次试验的全部视频，包括多机位、重复文件，以及裁剪、ROI、帧采样、片段等派生物；能证明来自同次试验的近似素材也绑定。哈希不同不证明来源独立，拿不准的关联先列疑点。模拟视频若参考测试素材，须记录参考关系并另行确认用途，不能仅因文件是新生成的就进入训练。

同一来源组在一折内只能属于 train 或 val，也不能跨开发与 test。组内任一已知成员出现某标签，即记录该组具有该标签证据；一个组可具有多种证据，这不等于某个片段同时具有这些标签。

**21／89 只是当前 ID 基线。** 若核查发现同组视频跨越已有 test 和开发，固定测试成员与来源隔离就发生冲突：暂停该组分配，提交证据和隔离、排除或移动建议，由用户决定；不自动移动成员，其他不受阻工作继续。冲突未解决前不能声称“无泄漏”。本轮来源分组依据用户对 110 个视频各为独立试验的确认；文件哈希检查无完全相同视频，但未完成近似素材或模拟来源审查。

正式划分必须满足：输入身份与标签合法、来源组完整、开发/test 隔离、每折 train/val 互斥且完整、每个获准开发组恰好验证一次。更好的比例不能抵消这些条件；来源冲突或未完成标注须明确阻塞相应输入，不能静默删除。

### B2. 标签覆盖、未知值与评价限制

本轮五类中，状态、模式、位置各 1 个字段，异常 3 项、现象 5 项，共 11 个字段。

覆盖目标按独立来源组数 `g` 确定：`g ≥ 3` 争取每折 train／val 都有支持组，`g = 2` 争取覆盖两个 val 折，`g = 1` 只作一折留出个案，`g = 0` 明示未覆盖。逐折去向、当前稀有标签及多标签冲突见第 2 节；这些规则同时适用于单选确定类别和各多选项的“是”“否”。

标签处理建议如下，仍须与[模型评价设计](design-test.md)一并确认，不表示现有训练或评分接口已支持这些做法：

| 标签值 | 怎么处理 |
| --- | --- |
| 状态、模式、位置的确定类别 | 各字段分别平衡，用适用类别评价识别表现 |
| 固定值“无” | 保留并检查固定组合，参与较低优先级的比例平衡；不作为断裂模式或位置的正例 |
| 单选“无法确定” | 保留为不确定目标，单独报告数量和处理表现，不整行排除 |
| 多选“是／否／无法判断” | 每个子字段分别处理；确定正负例与不确定判断分开评价，不把无法判断当否 |
| 标注状态“无法判读” | 按各字段已有证据安排来源，不把整行变为全未知；片段是否可用另审 |
| 空白 | 输入未完成，记录缺口并阻止该行正式发布，不补成无或不确定；当前 11 个模型字段无空白 |

建议训练保留已判读的不确定样例，让模型有机会学习证据不足时的输出；不把它们作为确定类别的正例。具体多值输出和指标分母须经评价设计确认，再在相应任务中实现。“无”和不确定值均单独统计与均衡，不在分母中合并，也不要求每折出现。时间点、帧号和范围只用于获准的子视频生成，不作当前模型时间预测标签，也不用于划分平衡。

测试报告只能说明实际覆盖范围。后续评价须逐折展示已知正负例、未知、不适用及独立组分母；有片段时同时报告片段数和来源数。某折无正例时，正例召回无法估计，不能填满分或随意填零。独立正例组少于 3 的值只作个案，不用于稳定排名模型；单例留出时训练无正例须明示。达到 3 组也不能直接称为统计稳定或能力已验证。划分得分不等于模型指标，具体评分、汇总和来源聚合仍由评价设计处理，本文不新增其实施前置条件或正式阈值。

### B3. 选优顺序与未满足项

第 3 节列出完整选优顺序与假设例，精确公式见附录 C。覆盖、人数、字段比例和共现逐项比较，前项同分才进入后项，仍同分用固定排序；这些规则已获确认；本轮实际结果见[本轮划分结果](data-split-result.md)。

找不到全满足的结果时，先接受人数预警和较低优先级的比例偏差，再将剩余覆盖缺口交用户审阅。报告须区分“数量上不可能”“已有组合冲突证据”和“本次搜索未找到”，不把搜索失败当成无解证明；不自动拆组、改 test、复制正例、合并未知或删难例。关键比较仍缺证据时，可建议延后能力结论或另收独立来源；新增采集及隔离方案另行决定，未来数据不算当前覆盖。

### B4. 确认后的实施与交付

以下为确认后实施和交付要求；本轮已生成源视频划分，其他阶段状态见[本轮划分结果](data-split-result.md)：

## 附录 C：评分、搜索和复现细节

### C1. 五项比较的精确定义

依附录 B3 的顺序逐项比较，同分才进入下一项：

1. **覆盖缺口：** 对 g ≥ 3 的每个确定类别及多选确定值，数出未达“val 与 train 各至少 1 组”的折数；再加 g = 2 时距离“两折 val 覆盖”所缺折数。总缺口越少越好，每个标签值一票；单例不要求三折覆盖。
2. **人数偏差：** 相对开发视频数的 1/3，先最小化三折最大绝对偏差，再最小化绝对偏差之和；建议 2 个源视频为预警线。
3. **字段分布偏差：** `n(f,l)` 是折 f 的 val 中支持标签值 l 的组数，`g(l)` 是开发中支持该值的总组数。相对偏差为 `|n(f,l) - g(l)/3| / max(1, g(l)/3)`。对这些项先在每字段内部平均，再在五类任务间平均，避免八个多选项压过状态、模式、位置；确定值权重 1，“无”和不确定值权重 0.5。同步输出未加权明细，不能用总分掩盖缺项。
4. **共现偏差：** 对开发中至少 6 个独立组支持的两标签共现，用同样相对偏差比较，仅作同分细化。
5. **最终同分：** 按稳定 `group_id` 排序，比较对应折号序列，取字典序最小者，即从头比较，首个不同处取折号较小的候选。

人数与分布分开报告，来源组数、源视频数和片段数不能混用。

### C2. 固定搜索方法及限制

建议用种子 42 至 141 产生 100 个起点，按支持组少的标签优先安排未分配组，再按固定顺序尝试单组移动、双组交换。每次只接受五项比较中严格更好的结果，扫描至无改善，最后取全部候选中最佳者；不用模型预测或 test 得分选种子。具体实现按本设计开展。

这是有界搜索，不保证全局最优。未满足目标时，报告实际最佳候选、缺口、相关来源组和已尝试范围，并按附录 B3 区分数量不足、已证实的组合冲突与搜索未找到。

### C3. 复现与发布记录

来源组表按稳定 `group_id` 排序，组内成员 ID 排序；标签按[标签说明](label.md)顺序，稀有程度同分的组按 group_id 处理。所有随机操作用局部伪随机发生器，记录种子序列和各起点配置，不依赖文件遍历、集合或字典的偶然顺序。

未来发布须把 CSV、来源组表、旧清单、标签规则、候选规则版本、输入输出 SHA-256、代码提交、运行环境和人工例外绑定到同次运行。同输入与配置重跑须逐文件一致，不能只核对人数。
