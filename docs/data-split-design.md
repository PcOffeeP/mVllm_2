# 数据划分设计：保留测试集，调整开发三折

**待用户确认，尚未实施（2026-11-07）。** 建议保留已有 21 个测试视频，只重排 89 个开发视频，让每个独立来源都轮到一次验证。现有清单在方案确认前仍是有效基线。

train 是训练集，val 是开发阶段的验证集，test 是测试集。“三折”就是做三次训练与验证，每次换一部分来源做 val，其余来源做 train。本文决定数据怎样分配，不保证模型效果会变好。

## 1. 旧规则是什么，现在有什么问题

旧规则按混合类型 `type` 划分：总数不超过 2 的类型永久放进 train，其余数据先分出 test，再分三折。旧 `type` 混合了断裂模式、异常和位置，不能直接用于本轮新标签。

此前只读核查显示：110 个视频中，21 个属于 test、89 个属于开发；三折 val 只轮到了其中 83 个，另 6 个一直用于训练。现有三折 val 都没有“未夹紧”和“爆炸性断裂”正例；第 2 折还没有“开裂”和“断后脱夹”正例。旧规则、六条视频及统计依据见附录 A。

本轮要判断状态、模式、位置、异常、现象五类，共 11 个字段。因此建议分别照顾各字段的覆盖，不再沿用旧混合类型，也不把 11 个字段拼成大量小组合。

## 2. 推荐怎么改，需要接受什么代价

**保留 test，取消旧六条永久训练的特例，让全部开发来源三折轮转。** 若 89 个视频各自独立，val 目标为 30／30／29，train 为 59／59／60。同一试样或同次试验的视频及派生片段必须绑定，不能为凑数量拆开；先核实来源，再实际分配。

保留这 21 个 test 成员，可以维持既定测试边界，减少结果比较时由成员变化带来的差异。重新划分会改变成员组成，但不能抹去已有暴露记录，也不能让数据因此成为从未使用过的独立测试集。

选择分配结果时，依次比较：**标签覆盖 → 视频数量 → 各字段比例 → 两标签组合**。只有前一项同分才比较后一项，最终同分用固定排序决定。精确覆盖规则见附录 B，评分公式与 100 个起点的搜索方法见附录 C；这些仍是待确认建议，尚未生成候选，也未证明能同时满足。

需要接受三点代价：

- 旧开发结果不能与新结果直接比较。

- 开发重排补不上 test 的覆盖缺项：固定 test 没有未夹紧、爆炸性断裂和开裂正例；它曾被使用，也不能称为从未暴露的独立测试集。

其他选择及其代价如下：

## 附录 A：旧规则与本轮统计

### A1. 旧规则及可核对的结果

旧规则来自原项目 [source_bootstrap.py](../../mVllm_2/pipeline/source_bootstrap.py) 的 `_rare_pool`、`_compute_strata`、`stratified_split` 和 `_split_payload`。以下为静态规则说明，不是重新运行旧入口的建议：

1. 按全部旧 `type` 计数，总数 ≤ 2 的类型进入永久训练稀有池，不进 test 或 val。
2. 其余记录位置缺失者进 `N/A`，其他先按 `type × location_canonical` 分层；≤ 2 条的小组合按位置合为 `rare_fracture`。若仍有非 `N/A` 小层，整批退回 `type_only`，位置缺失者仍为 `N/A`。
3. 默认 test 比例 0.2、三折、seed 42。同一伪随机发生器按各层输入顺序打乱；层大小 ≥ 2 时，test 配额先取 `max(1, round(层大小 × 0.2))`，再逐次减少，尽量给普通开发池留至少 3 条。逐层取整，所以总数未必精确为 20%。
4. 剥离 test 后重新分层、打乱，以 `ceil(层大小 / 3)` 连续切三块作 val，其余两块加稀有池作 train；第三折往往较小。
5. 保存 ID、计数、方法、种子等元数据；最终 ID 排序不证明随机过程的输入顺序已固定。

## 附录 B：推荐方案的完整规则

### B1. 来源隔离与正式划分条件

“来源组”指同一试样或同一次试验的全部视频，包括多机位、重复文件，以及裁剪、ROI、帧采样、片段等派生物；能证明来自同次试验的近似素材也绑定。哈希不同不证明来源独立，拿不准的关联先列疑点。模拟视频若参考测试素材，须记录参考关系并另行确认用途，不能仅因文件是新生成的就进入训练。

同一来源组在一折内只能属于 train 或 val，也不能跨开发与 test。组内任一已知成员出现某标签，即记录该组具有该标签证据；一个组可具有多种证据，这不等于某个片段同时具有这些标签。

**21／89 只是当前 ID 基线。** 若核查发现同组视频跨越已有 test 和开发，固定测试成员与来源隔离就发生冲突：暂停该组分配，提交证据和隔离、排除或移动建议，由用户决定；不自动移动成员，其他不受阻工作继续。冲突未解决前不能声称“无泄漏”。目前尚未做素材去重、来源核验或模拟来源审查。

正式划分必须满足：输入身份与标签合法、来源组完整、开发/test 隔离、每折 train/val 互斥且完整、每个获准开发组恰好验证一次。更好的比例不能抵消这些条件；来源冲突或未完成标注须明确阻塞相应输入，不能静默删除。

### B2. 标签覆盖、未知值与评价限制

本轮五类中，状态、模式、位置各 1 个字段，异常 3 项、现象 5 项，共 11 个字段。

覆盖按**独立来源组**计数，不按片段数计数。一个视频切出很多片段，仍不能补出多个独立正例。令 `g` 为开发中具有某标签值证据的独立组数，对单选确定类别、每个多选项的“是”和“否”，建议：

| 支持组数 | 覆盖目标及限制 |
| --- | --- |
| g ≥ 3 | 每折 val 和 train 各至少 1 组；这仍不证明样本充分 |
| g = 2 | 尽量分到两个不同 val 折；至少一折 val 缺该值，逐折核查 train 是否保留支持组 |
| g = 1 | 只在一折 val 出现，该折 train 无该值；只作个案描述 |
| g = 0 | 明确未覆盖，不能估计该值的正例识别表现 |

当前未夹紧最多覆盖 1 个 val 折、爆炸性断裂最多 2 个；来源合并后还可能更少。开发中开裂、断后脱夹各有 3 个正例视频，只有各自确属 3 个独立组且其他约束允许，才可能三折各有一个。

标签处理建议如下，仍须与[模型评价设计](design-test.md)一并确认，不表示现有训练或评分接口已支持这些做法：

| 标签值 | 怎么处理 |
| --- | --- |
| 状态、模式、位置的确定类别 | 各字段分别平衡，用适用类别评价识别表现 |
| 固定值“无” | 保留并检查固定组合，参与较低优先级的比例平衡；不作为断裂模式或位置的正例 |
| 单选“无法确定” | 保留为不确定目标，单独报告数量和处理表现，不整行排除 |
| 多选“是／否／无法判断” | 每个子字段分别处理；确定正负例与不确定判断分开评价，不把无法判断当否 |
| 标注状态“无法判读” | 按各字段已有证据安排来源，不把整行变为全未知；片段是否可用另审 |
| 空白 | 输入未完成，记录缺口并阻止该行正式发布，不补成无或不确定；当前 11 个模型字段无空白 |

建议训练保留已判读的不确定样例，让模型有机会学习证据不足时的输出；不把它们作为确定类别的正例。具体多值输出和指标分母须经评价设计确认，再在相应任务中实现。“无”和不确定值均单独统计与均衡，不在分母中合并，也不要求每折出现。时间点、帧号和范围只用于获准的子视频生成，不作当前模型时间预测标签，也不用于划分平衡。

测试报告只能说明实际覆盖范围。后续评价须逐折展示已知正负例、未知、不适用及独立组分母；有片段时同时报告片段数和来源数。某折无正例时，正例召回无法估计，不能填满分或随意填零。独立正例组少于 3 的值只作个案，不用于稳定排名模型；单例留出时训练无正例须明示。达到 3 组也不能直接称为统计稳定或能力已验证。划分得分不等于模型指标，具体评分、汇总和来源聚合仍由评价设计处理，本文不新增其实施前置条件或正式阈值。

### B3. 选优顺序与未满足项

以下均是待确认的建议，尚未生成候选，也未证明能同时满足。**先比较第一项，只有同分才比较下一项：**

1. 覆盖缺口最少：优先让可覆盖的确定标签出现在相应 train 和 val。
2. 三折视频数最均衡：目标各占开发视频的 1/3，偏差超过 2 个源视频时预警并说明原因；不为凑人数拆组或牺牲更优先的覆盖。
3. 各字段比例最接近：分别比较标签分布，“无”和不确定值权重为确定值的一半。
4. 两标签组合更均衡：只比较至少 6 个独立组支持的共现，不要求所有组合出现，也不把逻辑上不可能的组合算作缺项。
5. 仍同分时按固定排序决定，不由人挑“好看”的结果。

例如，假设其他覆盖相同，A 能让开裂三折各有一组，人数为 28／30／31；B 人数为 30／30／29，但一折没有开裂，应选 A。这是假设例，不是实际分配。精确公式、搜索和复现要求见附录 C。

找不到全满足的结果时，先接受人数预警和较低优先级的比例偏差，再将剩余覆盖缺口交用户审阅。报告须区分“数量上不可能”“已有组合冲突证据”和“本次搜索未找到”，不把搜索失败当成无解证明；不自动拆组、改 test、复制正例、合并未知或删难例。关键比较仍缺证据时，可建议延后能力结论或另收独立来源；新增采集及隔离方案另行决定，未来数据不算当前覆盖。

## 附录 C：评分、搜索和复现细节

### C1. 五项比较的精确定义

依附录 B3 的顺序逐项比较，同分才进入下一项：

1. **覆盖缺口：** 对 g ≥ 3 的每个确定类别及多选确定值，数出未达“val 与 train 各至少 1 组”的折数；再加 g = 2 时距离“两折 val 覆盖”所缺折数。总缺口越少越好，每个标签值一票；单例不要求三折覆盖。
2. **人数偏差：** 相对开发视频数的 1/3，先最小化三折最大绝对偏差，再最小化绝对偏差之和；建议 2 个源视频为预警线。
3. **字段分布偏差：** `n(f,l)` 是折 f 的 val 中支持标签值 l 的组数，`g(l)` 是开发中支持该值的总组数。相对偏差为 `|n(f,l) - g(l)/3| / max(1, g(l)/3)`。对这些项先在每字段内部平均，再在五类任务间平均，避免八个多选项压过状态、模式、位置；确定值权重 1，“无”和不确定值权重 0.5。同步输出未加权明细，不能用总分掩盖缺项。
4. **共现偏差：** 对开发中至少 6 个独立组支持的两标签共现，用同样相对偏差比较，仅作同分细化。
5. **最终同分：** 按稳定 `group_id` 排序，比较对应折号序列，取字典序最小者，即从头比较，首个不同处取折号较小的候选。

人数与分布分开报告，来源组数、源视频数和片段数不能混用。

### C2. 固定搜索方法及限制

建议用种子 42 至 141 产生 100 个起点，按支持组少的标签优先安排未分配组，再按固定顺序尝试单组移动、双组交换。每次只接受五项比较中严格更好的结果，扫描至无改善，最后取全部候选中最佳者；不用模型预测或 test 得分选种子。具体实现待本设计确认后开展。

这是有界搜索，不保证全局最优。未满足目标时，报告实际最佳候选、缺口、相关来源组和已尝试范围，并按附录 B3 区分数量不足、已证实的组合冲突与搜索未找到。

### C3. 复现与发布记录

来源组表按稳定 `group_id` 排序，组内成员 ID 排序；标签按[标签说明](label.md)顺序，稀有程度同分的组按 group_id 处理。所有随机操作用局部伪随机发生器，记录种子序列和各起点配置，不依赖文件遍历、集合或字典的偶然顺序。

未来发布须把 CSV、来源组表、旧清单、标签规则、候选规则版本、输入输出 SHA-256、代码提交、运行环境和人工例外绑定到同次运行。同输入与配置重跑须逐文件一致，不能只核对人数。
