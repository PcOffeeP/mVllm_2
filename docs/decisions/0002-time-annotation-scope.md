# DEC-002：断裂时间信息用于生成，不纳入当前模型时间预测任务

- **决策状态：已确认边界的补记。** DF-019 记录用户于 2026-11-07 澄清的使用范围。
- **记录日期：2026-11-07。**
- **适用范围：** 当前数据衔接设计、训练任务范围与模型评价范围。
- **实施状态：** 时间、帧号和范围记录保留；它们与新子视频生成链的具体接入尚待确认和实施。
- **验证状态：** 本记录仅整理使用边界，不提供新链路生成、时间预测训练或真实模型评价结果。

## 决定

断裂时间类标注**可以用于子视频生成**。当前不为模型时间预测任务构建训练集，也不评价模型对时间类标签的预测表现。当前面向模型判别的范围仍为断裂状态、断裂模式、断裂位置、异常情况和断裂现象五类。

已有断裂帧、时间点和时间范围记录保留，不因这一决定删除或改写。它们的标注含义继续依 [DEC-001](0001-annotation-baseline.md#事件锚点与记录边界)及[标签说明](../label.md)；本条没有赋予时间范围、中点或首帧 `0` 新含义。

## 这项边界解决什么

它把“用人工时间证据辅助制作片段”和“让模型预测断裂时间”分开。允许前者，不能据此扩大为后者的训练或评价任务。这是对用户明确使用范围的整理；现存材料没有提供需要补写的完整历史备选方案比较。

## 仍待决定与实施的部分

旧候选规划读取事件时间生成窗口并推导状态。允许使用时间信息，并不说明旧选窗、自动标签和跳过规则已经适合本轮：帧号怎样转换为输入，只有范围、单侧边界、首帧已分离、缺失或不可靠时间时怎样处理，都仍需确认。时间辅助产生的建议也不能自动证明片段画面支持所有标签。

DF-015 记录的历史 post 观察窗要求仍需衔接；不能将此条理解为取消要求，或宣称旧代码已落实要求。具体问题由[数据衔接讨论稿第 4、5 节](../data-handoff-decisions.md#4-时间信息和窗口怎样衔接)维护。

本记录本身不授权生成子视频、迁移或修改代码、运行训练或真实评价，也不授权使用 test。
