## 4. 如何维护这些文档

- **总览**保留当前短结论、状态边界和入口，不复制完整规则或实验日志。
- **DEC 记录**保存有长期影响的决定、理由或原理由缺口、适用范围及重议条件。DEC 编号与 DF 编号独立，现有 `DF-*` 标识保留。
- **facts.yaml**继续保存设计与代码事实、原有证据锚点和误读说明；它不是全部已确认决定的列表。
- **专题文档**维护完整标签或设计规则；**TODO**维护进度、依赖、下一步和验收标准；结果文档维护实际运行身份与结果。

决定被取代时，保留原记录，标明取代关系并更新总览。发现材料冲突时先报告，不能用本目录摘要覆盖源级规则或把未决内容补成已确认。发生相关变更时同步核对相应记录和原事实条目；总览与来源不一致时，不自行择一执行。

**失效条件：** 用户确认新的决策入口取代本目录时，本总览作废；标签、划分、时间用途、新旧链路或授权边界变化时，受影响条目必须重新核对。它不提供独立的数据处理、训练、真实评测、test 使用或迁移授权。
