# `tensile-vlm/v3` 跨仓视觉契约设计

## 目标与范围

视觉模型从“在当前 clip 的相邻采样帧中定位断裂”改为“判断当前 clip 可见的阶段状态”。
本阶段冻结单 clip 输出字段、枚举、Prompt、搜索语义和跨仓 artifact；同步 mVllm_2 与
TensileAgent 的设计依据和契约测试。本阶段不修改 TensileAgent 状态机，不生成新子视频，
不训练或部署模型。

## 非目标

- 不原地修改或删除仍在使用的 `tensile-vlm/v2`。
- 不兼容映射 `fracture_between`；旧字段不得伪装成 v3 状态证据。
- 不覆盖旧子视频、历史人工审查或已激活的 `08_training_ready` 发布。
- 不在本阶段决定 20/10/5/3/2 秒子视频的最终配比。

## 约束与假设

- mVllm_2 是契约 artifact 的权威来源，TensileAgent 保存逐字节等价的消费副本。
- 单 clip 输出固定为五个必需字段：`clip_state`、`fracture_mechanism`、`root_break`、
  `location`、`special_case`；不允许额外字段。
- `clip_state` 是 Agent 搜索的唯一方向性字段。其余字段只用于最终模式、齐根属性和位置汇总。
- `未夹紧`和`视频异常`通过 `special_case` 表达，并要求 `clip_state=无法判断`。
- 模型只报告当前 clip 可见证据；区间合法性、覆盖、收缩、预算、冲突和终止仍由代码负责。

## 方案比较与结论

选择新增破坏性版本 `tensile-vlm/v3`，同时保留 v2 artifact。原地扩展 v2 会破坏版本与 hash
语义；让服务长期同时返回 v2/v3 字段会模糊训练目标并增加非法组合，因此均不采用。v3 在阶段
A 只作为冻结的目标契约存在，运行时仍使用 v2，直到后续数据、模型和 Agent 迁移分别完成。

## 契约与搜索语义

`clip_state` 枚举及含义：

- `未断裂`：当前 clip 的可靠可见证据位于断裂事件之前；未来搜索向更晚时间移动。
- `发生断裂`：当前 clip 同时具有事件前后可见证据；未来搜索在该区间内继续收缩。
- `已断裂`：当前 clip 的可靠可见证据位于断裂事件之后；未来搜索向更早时间移动。
- `无法判断`：不提供搜索方向；未来代码使用重采样、重叠区间、冲突或异常兜底。

`fracture_mechanism`、`root_break`、`location` 和 `special_case` 均可为 `null`。`未断裂`
不得携带断裂分类信息；`special_case` 非空时状态必须为 `无法判断`，且断裂分类信息必须为空。
对 `发生断裂`、`已断裂`及不属于特殊情况的`无法判断`，可见且可判断的汇总字段可以独立
给值，证据不足的字段保持 `null`，不得从源标签或其他轮次补造。

## 数据与迁移边界

训练机现有 `data/03_subvideos` 和激活发布继续只读有效。后续阶段 B 先从版本化
`video_meta.roi.json` 生成带内容身份的候选计划；dry-run 不编码 MP4。获批计划的媒体写入
新的隔离目录，旧审查仅按完全一致匹配引用，部分重叠只作参考。只有新人工审查、质量门、
版本冻结和发布全部成功后，才显式切换激活版本。

## 失败处理

- 非法枚举、缺字段、额外字段或跨字段冲突：视为非法模型输出，不产生方向性证据。
- `无法判断`：不缩小候选区间，不解释为阴性。
- 多轮状态冲突：由未来确定性 Verifier 保留冲突并继续采样或终止为不可识别。
- contract version/hash 漂移：未来运行时继续 fail closed；阶段 A 通过固定 hash 测试防漂移。

## 验证策略

- 两仓 artifact JSON 完全一致，规范化 SHA-256 固定。
- schema 字段顺序、枚举、nullable 和跨字段规则与 `pipeline/v3_labels.py` 一致。
- Prompt 明确五字段与状态定义，且不再要求 `has_fracture` 或 `fracture_between`。
- 两仓相关契约测试、完整测试和 `git diff --check` 通过。

## 后续阶段

阶段 B 只实现候选计划 dry-run、统计和历史审查匹配；计划经人工确认后才生成媒体。阶段 E
再把 TensileAgent 从局部帧索引定位迁移为片段状态搜索，不能在阶段 A 提前混入运行时改造。
