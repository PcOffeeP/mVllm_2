# `tensile-vlm/v4.1` 临界未断裂语义设计

## 目标与范围

在不混淆普通阴性与断裂前预测的前提下，让模型学习韧性断裂临界阶段可见的局部颈缩、变细和
损伤集中信息。v4.1 保持四字段输出：

- `clip_state`
- `fracture_mechanism`
- `fracture_site`
- `special_case`

新增 `clip_state=临界未断裂`，不直接放宽普通 `未断裂`。

## 非目标

- 不把所有断裂前片段自动标为临界状态。
- 不从源视频最终标签直接生成无需复核的训练真值。
- 不允许普通无断裂源视频携带预测机制或位置。
- 不修改当前 TensileAgent v2 生产运行时。
- 不删除或覆盖 v3、v4 契约、队列和人工决定。
- 不重新编码已有 MP4 或 JPG。

## 约束与假设

- `未断裂` 表示当前采样帧没有可靠的断裂或临界断裂征兆，三个附加字段仍为 `null`。
- `临界未断裂` 表示尚未断裂，但采样帧已出现足以支持人工判断的韧性断裂临界视觉征兆。
- 当前只为韧性断裂建立临界语义；其他机制继续保持原有规则。
- `临界未断裂` 时 `fracture_mechanism` 只能为 `韧性断裂` 或 `null`，
  `fracture_site` 可独立为三级位置之一或 `null`，`special_case` 必须为 `null`。
- 机制和位置在该状态下是预测线索，不是已观察到的最终断裂结果。

## 方案比较

1. 直接允许 `未断裂` 携带机制和位置：改动最小，但同一状态同时表示普通阴性和预测，
   Agent 无法区分证据阶段。
2. 新增 `临界未断裂`：保持四字段，显式区分普通阴性和断裂前预测，搜索方向仍明确。
3. 新增两套预测字段：语义最纯，但会把输出扩展到六字段并显著增加数据和推理负担。

采用方案 2。

## 契约与 Agent 语义

`clip_state` 枚举增加 `临界未断裂`。搜索语义为
`fracture_event_is_after_clip_with_visible_precursors`，与 `未断裂` 一样指向更晚区间，但
要求后续实际断裂证据确认。

Agent 对 `临界未断裂` 中的 `fracture_mechanism` 和 `fracture_site` 只保存为
`prospective` 证据：

- 不能单独形成最终断裂类型或位置；
- 不能单独判定已经断裂；
- 后续 `发生断裂` 或 `已断裂` 证据一致时可作为辅助证据；
- 与后续结果冲突时以后续实际断裂证据为准并记录冲突。

## 候选与人工复核

从已物化的 development 候选中新增临界复核候选，选择条件全部满足：

- `window_role=pre_event`
- `window_variant=pre_event_back`
- `source_type=韧性断裂`
- 媒体及帧图通过既有 hash 门禁

当前数据对应 176 个候选、41 个源视频。系统使用源视频最终标签生成待审建议：
`clip_state=临界未断裂`、`fracture_mechanism=韧性断裂`，位置由既有无冲突位置映射得到。
这些只是审核建议，必须人工逐条确认；审核者可改回普通 `未断裂`，也可将机制或位置改为
`null`。原有 598 个断裂复核候选继续保留，因此 v4.1 队列共 774 条。

## 组件与数据流

- 新增 v4.1 contract artifact 和标签验证器。
- 新增 v4.1 内容寻址队列与决定 schema，绑定完整 materialized 清单、媒体 hash、契约 hash
  和候选选择策略版本。
- V4 工作台切换到 v4.1 队列，保持帧优先、视频默认折叠。
- 将当前 v4 草稿中的全部终态决定逐条校验后迁移；新增临界候选保持未审核。
- TensileAgent 保存逐字节一致的 v4.1 consumer artifact 和未来聚合边界，运行时仍为 v2。

## 失败处理

- 普通 `未断裂` 携带任何附加标签时拒绝。
- `临界未断裂` 携带非韧性机制或特殊情况时拒绝。
- 临界候选不满足选择条件、媒体 hash 漂移或来源位置冲突时拒绝入队。
- v4 决定的 candidate ID、媒体 hash 或系统建议与 v4.1 基础候选不一致时拒绝迁移并输出冲突。
- v4.1 未完成全量复核前不得冻结训练发布。

## 验证与迁移

- 两仓 v4.1 artifact 逐字节一致且 canonical hash 固定。
- 标签测试覆盖普通阴性、临界韧性、可空预测字段、非法机制和特殊情况。
- 队列验证 598 个既有候选加 176 个临界候选，媒体全部复用。
- 当前 v4 已审决定完整迁移，数量不减少；迁移时以最新草稿为准。
- 两仓全量测试和 `git diff --check` 通过。
- 浏览器确认 `临界未断裂` 可选、帧优先、视频折叠，进度与迁移报告一致。

## 发布纪律

两个仓库分别提交，不 push。训练机只接收 mVllm_2 提交，新 v4.1 队列和决定写入新目录。
旧 v4 服务在迁移完成后由 v4.1 工作台替换；旧数据保持只读可追溯。
