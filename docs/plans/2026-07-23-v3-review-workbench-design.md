# v3 人工复检工作台精简设计

## 目标与范围

把 `review_v3_candidates_app.py` 从流程验证界面改成适合连续处理 598 条候选的人工复检工作台。
本次只调整导航、信息层级和完成行为，不修改 v3 标签、决定 schema、队列身份校验或媒体哈希门禁。

## 非目标

- 不自动生成任何人工决定。
- 不改变 `approved/corrected/dropped/needs_regenerate` 的含义。
- 不修改候选媒体、历史参考或已经冻结的三条小样本决定。
- 不进入标签汇总、训练发布或模型训练。

## 方案比较

1. 左侧可搜索紧凑列表：默认只显示未审核候选，支持状态、源视频和关键词过滤，适合逐条连续审核。
2. 全量表格：单屏信息密度更高，但视频审核时需要在表格和媒体区之间频繁切换。
3. 单条向导：界面最简单，但难以定位指定源视频、回看已审核记录或跳过问题样本。

采用方案 1。它兼顾连续审核、快速跳转和状态可见性，且不需要引入新的数据模型。

## 推荐界面

- 顶部只显示进度：总数、已完成、未完成及四种终态计数。
- 左侧为紧凑候选列表：
  - 默认状态筛选为“未审核”；
  - 可切换查看全部或指定终态；
  - 可按 `candidate_id`、`source_video` 搜索；
  - 可按源视频筛选；
  - 每项只显示状态、源视频、片段角色和短时间区间。
- 中间显示当前视频与采样帧；实际帧映射默认折叠。
- 右侧显示五字段编辑和三个决定按钮；保存后自动跳到下一条未审核候选。
- 系统建议以紧凑字段摘要显示。历史参考默认折叠，只展示匹配数量和是否存在一致建议。
- 队列身份、哈希、路径和输出目录归入侧栏“高级信息”，默认折叠。
- 移除主界面的手动冻结按钮。选定队列全部形成终态后自动尝试冻结；失败时保留草稿并显示错误。

## 状态与数据流

启动时仍执行现有 queue、manifest、候选和选中媒体哈希校验。界面读取同一草稿文件，并按
`selected_candidate_ids` 顺序构建列表。每次决定先规范化并原子保存草稿，然后重新计算筛选结果
和下一条未审核候选。完成全部选定候选后调用现有内容寻址冻结函数；幂等重试返回同一批次。

三条小样本决定属于独立 candidate ID 集合，不能自动并入 598 条全量草稿。全量审核时相同三条
仍会出现在队列中；后续如需复用，必须通过显式、可审计的决定导入流程完成，不在本次 UI 改造中
隐式复制。

## 失败处理

- 媒体、manifest 或 queue 漂移：启动即拒绝，不显示可审核界面。
- 草稿身份不匹配：拒绝覆盖，保留既有文件。
- 非法五字段组合：不保存，直接显示字段错误。
- 保存失败：停留当前候选，不自动跳转。
- 自动冻结失败：草稿仍保留全部终态决定，界面显示失败原因，可修复后幂等重试。
- 当前筛选无结果：显示空状态，并允许切换到“全部”或其他状态。

## 验证

- 单元测试覆盖筛选、搜索、下一条未审核选择、完成统计和自动冻结触发条件。
- 入口脚本跨工作目录启动测试继续通过。
- 本机全量 pytest 与 `git diff --check` 通过。
- 训练机先用已完成的三条小样本验证折叠、列表、状态切换和自动冻结幂等性，再以完整 598 条队列
  启动正式审核工作台。
