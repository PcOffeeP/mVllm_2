# 测评管线重设计：从形式合法到语义可判

> 状态：设计稿，2026-10-18 起草于分支 `feat/evaluation-development`。本轮只出设计，不改字段、不改实现、不提交。门槛数值、k 值、T1 模型选型、M3 权重等待用户裁决，清单见第 11 节。

> 事实边界：第 1 节实测数字来自 2026-10-18 训练机实测。本机未复现任何训练机结果，也未在本机跑模型推理。仓库内没有新口径（8 帧 / 512 视觉 token）的 425 条结果文件，`docs/results/model-r1-effect-profile-20261018.md` 记录的是旧口径。

## 1. 背景与问题

R1 模型 `v4.1-agent-pipeline-fold0-r1` 的 425 条评测记录暴露出三个互不相同的问题。格式全对、语义塌缩是病灶本身；七道冻结门对此病灶不敏感，是门禁缺口；已断裂 0/33 与换管线无关，是归因边界。三者分开处理。

### 1.1 实测事实：换管线与零召回无关

同一模型、同一批 425 条数据、同一份 Prompt，只改输入管线。

| 指标 | R1 旧口径 | R1 新口径 |
| --- | --- | --- |
| 输入管线 | 1 组时间融合 / 64 视觉 token | 8 帧 → 8 组 / 512 视觉 token |
| 样本数 | 425 | 425 |
| joint 正确率 | 41.18% | 50.59% |
| 「发生断裂」recall | 45.83% | 59.72% |
| 「已断裂」recall | 0/33 = 0 | 0/33 = 0 |
| strict_valid_rate | 1.0 | 0.9906 |
| 「临界未断裂」recall | 0.2281 | 0.1053 |

新口径数字来源：2026-10-18 训练机实测；仓库内尚无对应结果文件，须补登记后才可作为可追溯证据。读法四条。发生断裂（精确匹配）recall 45.83% → 59.72%，检出率另见第 6.5 节；临界未断裂 0.2281 → 0.1053。换管线没有解决已断裂，两套口径都是 0/33。管线、模型版本、数据发布与样本集、评测标准四个因素已逐个排除（标注正确性不在其内，另受第 3.5 节 V1 约束）；判据已存在于契约（见第 3 节），0/33 的来源在判档与视觉可辨识性。四态等权平均使该类归零不触发门禁，属门禁不敏感问题，见第 1.3 节。

### 1.2 格式满分、语义塌缩

33 条「首帧即断裂」样本上，模型一条都没判对。同批的 strict_valid_rate 是 1.0（旧口径）与 0.9906（新口径）。两项并列说明：输出形式全部合法，判读内容与真值无对应关系。形式合法率接近 1 与语义召回接近 0 同时成立，是本轮要处理的病灶。

### 1.3 七道冻结门对本病灶不敏感

阈值定义在 `finetune/holdout_metrics.py:12-20`，七项硬编码，`validate_thresholds` 拒绝任何改动。

| 门 | 冻结阈值 | 敏感度 |
| --- | --- | --- |
| `four_state_macro_recall` | 0.4006 | 已断裂归零只损失 1/4 权重，剩余三类仍能托住均值 |
| `fracture_three_state_macro_recall` | 0.3 | 三态均值，单类归零只削去三分之一 |
| `joint_correct_rate` | 0.3921 | 425 条全对的联合口径，天花板远高于阈值 |
| `runtime_failure_count` | 0 | 只度量崩溃 |
| `strict_valid_rate` | 1.0 | 只校验形式 |
| `已断裂_recall` | 0.15 | 33 条里判对 5 条即过 |
| `未断裂_recall` | 0.7 | 与已断裂无关联 |

三项机制解释这门为什么不拦。

- joint 是四字段全对的联合口径。33 条已断裂全对，joint 也只到 208/425 ≈ 48.94%；这 33 条全错时 joint 停在 41.18%，高于 0.3921。
- `four_state_macro_recall` 等权平均，一类召回归零只削去 0.25 的上限。旧口径四态为未断裂 0.832461、发生断裂 0.458333、临界未断裂 0.228070、已断裂 0，四态均值 0.379716。三类合计再高约 0.0836 即越过 0.4006，抬到 0.4006 以上不需要已断裂贡献分，该类归零不构成结构性拦截。
- `已断裂_recall` 取 0.15，5/33 = 0.151515 即通过。历史批次出现过 0/33 仍被判过的情况；该批次逐条出处本稿未附，核实前只按机制说明使用。

`strict_valid_rate` 的校验范围单独说清：单 JSON、无重复键、恰好四字段、枚举合法、跨字段组合合法，不校验判读内容是否与视频对应。1.0 只证明输出可解析。

### 1.4 政策层放宽与闸机缺口

| 放宽项 | 内容 | 后果 |
| --- | --- | --- |
| 形式门放宽 | `strict_valid_rate` 1.0 → 0.99 | 少数坏输出不再阻断 |
| 结论门放宽 | 两门为 false 仍授权 stage_e/f | 未通过的门不阻止下一阶段 |
| 绝对性能降级 | 绝对性能指标取 `record_only` | 只记录，不阻断 |

闸机分布不齐。新体系 `versioning/registry.py:995` 有 `require_passed=True` 硬闸机，结论不是 `passed` 即抛 `PromotionGateRejected`。老体系 `pipeline/model_registry.py` 与 `finetune/release_validate.py` 没有对应闸机，走老路径的结论可以绕过门。

### 1.5 真值分布与训练池供给

| 真值状态 | 条数 |
| --- | --- |
| 未断裂 | 191 |
| 临界未断裂 | 57 |
| 发生断裂 | 144 |
| 已断裂 | 33 |

训练池里已断裂不稀缺：1253 条候选中 188 条（15.00%），每 epoch 3000 行中 564 行（18.80%），重复倍率 3.0 已顶 `SIGNATURE_COUNT_CAP`（`finetune/train_build_source_aware_dataset.py:30`）。数据供给不是瓶颈，瓶颈在判据与度量。

## 2. 主体与术语

全文用下表代号指称四方主体，不用笼统说法指代任何一方。硬边界：M 只产文本，不参与判分；T1 与 T2 只产判读意见，不产最终指标；指标由脚本算；结论由人或 Agent 给，且能被脚本证据推翻。

| 代号 | 是什么 | 职责 | 典型实现 |
| --- | --- | --- | --- |
| M | 被微调的 MLLM（MiniCPM-V + LoRA），被测对象 | 输入帧与 Prompt，输出文本 | R1、R2 训练产出的 adapter 或 merged 权重 |
| T1 | 文本判读 LLM，通过 API 调用（本地只能跑 89B 级模型，性能不足） | 读 M 的原始输出、契约与可选真值，做抽取、语义等价判定、异常识别 | 待定的 API 模型，见第 11 节 |
| T2 | 视觉核验 LLM，可选，抽检用 | 读帧与 M 的输出，验证 M 的视觉断言 | 待定，启用与否见第 11 节 |
| 我（Agent） | 组织测量、核验事实、归因、写报告、提决策 | 把数字变成可裁决的结论 | 本 Agent 与参与执行的子 Agent |
| 人 | 用户 | 定标准、标判例、终极裁决 | 用户本人 |

## 3. 标签语义与判据

### 3.1 权威定义

用户裁决，本稿照记，不得改动。

| 标签 | 定义 |
| --- | --- |
| 已断裂 | 传入的第一帧就已经断了 |
| 发生断裂 | 一开始没断或快断，片段内才发生 |

两者区别是时间位置，不是严重程度：首帧即断裂与中途断裂，视觉证据位置不同，模型要做定位，不做排序。

### 3.2 判据已存在：契约已编码时序语义

本稿起草时把 0/33 归因于 Prompt 未显式要求首帧顺序，并提出改造 Prompt。逐字查证 `pipeline/contracts/tensile_vlm_v4_1.json` 后，该假设不成立：判据早已写在契约里。

契约 `search_semantics` 把时序语义编码成「断裂事件相对片段的位置」，`direction_field` 即 `clip_state`。以下为节选，仅按轴重排，未改键名与取值：

```text
"direction_field": "clip_state",
"未断裂": "fracture_event_is_after_clip",
"临界未断裂": "fracture_event_is_after_clip_with_visible_precursors",
"发生断裂": "fracture_event_is_within_clip",
"已断裂": "fracture_event_is_before_clip",
"无法判断": "no_directional_evidence"
```

四个有方向的取值分别表示断裂事件位于片段之后（未断裂）、片段之内（发生断裂）、片段之前（已断裂）、无方向证据（无法判断）；`临界未断裂` 是「位于片段之后但已有可见前兆」的加分档。契约把「首帧锚点」写成的是 `fracture_event_is_before_clip` 的语义条件，`analysis.user_prompt` 原文已给出该条件，相关整句为：

> 片段内明确出现从连续到分离的变化时为发生断裂；可靠画面从一开始就已分离且没有片段内断裂前证据时为已断裂；

「可靠画面从一开始就已分离」即首帧锚点，「没有片段内断裂前证据」排除片段内新发生的断裂。判据在契约里，不属于需要新增的内容。

### 3.3 三处表述一致

| 用户口述语义 | 契约键值 | Prompt 条件 |
| --- | --- | --- |
| 已断裂 = 第一帧就断了 | `fracture_event_is_before_clip` | 可靠画面从一开始就已分离且没有片段内断裂前证据 |
| 发生断裂 = 一开始没断或快断，片段内才发生 | `fracture_event_is_within_clip` | 片段内明确出现从连续到分离的变化 |

用户口述的「已断裂 = 第一帧就断了」与契约 `fracture_event_is_before_clip`、与 Prompt「可靠画面从一开始就已分离」三处一致，不存在需要新增的锚点要求。

### 3.4 因此不改标签值

四态闭集同时被三项依赖：契约枚举（`clip_states` 与 `search_semantics`）、1,678 条既有样本（`data-v4.1-r2` 候选计数，见 `docs/results/training-data-ledger-20261017.md`）、历史指标（第 1.1 节与第 1.5 节的 recall 与 support 均按四态切片）。改标签值须重标全量并破坏跨批次可比性，收益不抵成本。本轮及 R2 均不改标签值。

不改的是四态定义与闭集，不禁止纠正单条错误标注（见第 3.5 节 V1）。

`assets/frac_mode.md` 不是标签权威来源，其自述原文为：

> 定位：用于理解视觉现象的领域参考，不是训练标签或代码枚举的权威来源。
> 原始标注以本批 inputs 明确绑定的 `all_videos_tag.csv` 为准；
> 正式发布标签与代码闭集遵守现行业务契约及人工审查；本文不得覆盖 CSV 原字段或 canonical 口径。

该文件讲的是断裂模式（韧性、脆性、爆炸性），不构成四态 `clip_state` 定义，不能作为改标签值的依据。（原文该行含 Markdown 链接标记，此处保留文字、去链接标记；第 4 行截取至分号；末尾关联文档一行从略。）

### 3.5 真正待验证的三件事

按验证成本从低到高排列。三项都不是改标签值，也不需要重训。

| 编号 | 待验证问题 | 验证方法 | 成本 | 判据 |
| --- | --- | --- | --- | --- |
| V1 | 33 条「已断裂」是否真符合「首帧即已分离」 | 人工抽看 10–30 条首帧 | 人工 10–30 条 | 抽看样本与 `fracture_event_is_before_clip` 语义一致；出现不一致即先修标注，暂不谈模型 |
| V2 | ROI 裁剪下断口是否肉眼可分 | 抽看首帧与原视频对照 | 人工抽看 + 原视频比对 | 首帧里断口可辨；不可辨则问题在帧数、分辨率或 ROI |
| V3 | 模型能否描述出「已分离」但没据此定档 | 用契约 `evidence` 通道跑 33 条，纯推理、无需重训 | 训练机执行，一次 33 条推理 | 观察描述出现分离证据而 `clip_state` 未取已断裂，即判档问题 |

V3 用到的 `evidence.system_prompt` 原文要求只描述可见变化、不打标签：

> 你是一位材料力学视频观察助手。请只依据当前输入的采样帧，按时间顺序描述试样的可见变化，包括伸长、变细、颈缩、连续性中断、分离、打滑、遮挡或画面异常。不要引用其他分析结果，不要输出分类标签或 JSON，只输出一段简洁的视觉观察。

该通道的输出可以独立回答「模型看见了吗」，与定档动作分开，因此能把视觉问题与判档问题切开。

### 3.6 观察结果如何分流

若 V3 的观察描述里出现「已分离 / 断开」却仍输出「未断裂」，问题在判档而非视觉；若描述里压根没提分离，问题在视觉可辨识性（帧数 / 分辨率 / ROI）。

## 4. 每步归属表

下表为用户已确认的归属。起步阶段与定型阶段的主体可以不同。

| 步骤 | 内容 | 起步由谁做 | 定型后由谁做 | 理由 |
| --- | --- | --- | --- | --- |
| S1 | 取样本、定分母 | 脚本 | 脚本 | 分母必须可复算 |
| S2 | 抽帧 | 脚本 | 脚本 | 帧数与时间戳必须可复现 |
| S3 | 推理 | M | M | 被测对象的输出就是被测内容 |
| S4 | 结构解析（S1–S4 级） | 脚本 | 脚本 | 输入相同则输出必须相同 |
| S4' | 解析兜底 | T1 | 脚本 + 兜底 | 先靠 T1 摸清坏输出形态，再固化成规则 |
| S5 | 形式校验 | 脚本 | 脚本（永远） | 规则完全确定，不容判读 |
| S6 | 语义抽取 | T1 | 词表 + 规则，T1 兜底 | 语义先由 LLM 摸边界，再收窄成词表 |
| S7a | 状态判分（标签比对） | 脚本 | 脚本 | 真值与预测都在手里，比对是确定运算 |
| S7b | 语义等价判定 | T1 | 判例库 + T1 兜底 | 表述不同、语义相同的判定需要理解 |
| S7c | 机制/位置判分 | T1 | 词表规则 + T1 | 位置与机制的表述空间大，规则覆盖不全 |
| S8 | 聚合与指标 | 脚本 | 脚本（永远） | 同一批记录必须算出同一个数 |
| S9 | 门禁判定 | 脚本 | 脚本（永远） | 门禁结论必须可审计、可复算 |
| S10 | 归因与结论 | 我（Agent） | 我（Agent） | 需要跨步骤整合与判断 |
| S11 | 定标准与放行 | 人 | 人 | 涉及取舍与责任 |

分界原则：输入相同则输出必须相同，交给脚本；需要理解语义，交给 T1；需要业务取舍，交给人。S5、S8、S9 永远不给 T1，理由是同一组：可复现、可审计。形式校验是枚举与字段约束，聚合是指定公式，门禁是阈值比较，三者输入输出完全确定。交给 LLM 会引入不可复算的偏差：同一批记录换个时间判读可能得出不同结果，门禁结论就无法作为晋级依据。S9 是最后一道闸机，闸机本身若是概率性的，闸机不成立。

## 5. T1 设计（API）

T1 通过 API 调用才能达到可用性能。本地 89B 级模型在语义等价判定上性能不足，只作离线探索，不进正式链路。

### 5.1 输出 schema

缺任一字段整条作废。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `label` | 枚举 | `未断裂` / `临界未断裂` / `发生断裂` / `已断裂` / `abstain` |
| `evidence_span` | 字符串 | M 原始输出中支撑判读的原文片段；为空则整条结果作废 |
| `judge_id` | 字符串 | 判读器身份，含模型标识与版本 |
| `prompt_version` | 字符串 | 判读 Prompt 的完整版本标识 |
| `confidence` | 0–1 浮点 | 判读自评置信度，用于抽检分层 |
| `reason_code` | 枚举 | 归因码：位置错、机制错、证据缺失、表述歧义 |

### 5.2 三种调用模式

| 模式 | 阶段 | 调用量 | 用途 |
| --- | --- | --- | --- |
| 全量标注 | 冷启动期 | 全部记录 | 建立基线，产出判例库候选 |
| 兜底 | 规则未命中时 | 未命中部分 | 补规则覆盖不到的表述 |
| 抽检探针 | 定型后 | 5% 记录 | 监控脚本与 T1 的分歧率 |

### 5.3 审查要求

- 双判读一致性：两个独立 T1 实例判同一批记录，Cohen's κ ≥ 0.6。
- 与人工标注一致率 ≥ 0.85。
- 盲化：T1 不看门禁结论、不看历史分数、不看其他样本的判读意见。
- 偏置统计：统计长度偏置（M 输出越长越易被判为某一类）与顺序偏置（四态枚举顺序影响判读）。
- 版本冻结：模型、Prompt 版本、`temperature=0` 三项同时冻结并写入 `judge_id`。任一项变化即新判读器，须重做一致率检验。

### 5.4 成本估算

只给公式与待填参数，不给单价。

```text
总成本 = N × 调用模板数 × (1 + 重试率) × (平均输入 token × 输入单价 + 平均输出 token × 输出单价)
```

`N` 取 425。调用模板数指同批记录需要的不同判读模板数，全量标注通常为 1，双判读为 2。单价待定，取 API 供应商公开价，本稿不预设。

| 参数 | 含义 | 取值 |
| --- | --- | --- |
| 输入单价 | 每千输入 token 价格 | 待填 |
| 输出单价 | 每千输出 token 价格 | 待填 |
| 平均输入 token | 单次调用输入长度 | 待填 |
| 平均输出 token | 单次调用输出长度 | 待填 |
| 重试率 | 解析失败或超时的重试占比 | 待填 |
| 调用模板数 | 每批记录使用的判读模板数 | 待填 |
| 抽检比例 | 定型阶段抽检覆盖率 | 5% |

### 5.5 失败与超时降级

1. 单条超时或解析失败，按重试率上限重试；仍失败记 `judge_unavailable`。
2. 整批 T1 不可用，回落人工抽检，抽检结论只对当批有效。
3. 该批指标标记 `judge_unavailable`，在报告中单列。
4. 不得把 `judge_unavailable` 静默按通过处理，也不得从分母剔除；剔除会抬高剩余样本的指标。

## 6. 匹配等级 M1–M5 与指标口径

等级把「判对」与「判错」之间的灰色地带单独计量。

### 6.1 等级定义

| 等级 | 名称 | 定义 | 示例 |
| --- | --- | --- | --- |
| M1 | 精确匹配 | 预测标签与真值相同 | 真值已断裂，预测已断裂 |
| M2 | 语义等价 | 表述不同、语义相同 | 真值已断裂，预测「首帧即断裂」 |
| M3 | 时序档位错 | 相邻档位混淆 | 真值已断裂，预测发生断裂 |
| M4 | 错误 | 方向错，跨档 | 真值已断裂，预测未断裂 |
| M5 | 未识别 | abstain 或未作答 | 输出为空、拒答、无法抽取 |

M3 单独理解：真值已断裂、预测发生断裂，说明模型看到了断裂，只是把「一开始就断」说成「中途才断」。这是距离判断错，不是看不见断裂。M4 是方向错，模型认定同一片段没有断裂。

### 6.2 指标定义

| 指标 | 定义 |
| --- | --- |
| 严格准确率 | (M1 + M2) / N |
| 宽松准确率 | (M1 + M2 + w·M3) / N，w 待定 |
| M3 率 | M3 / N，单列报告 |
| M4 率 | M4 / N |
| M5 率 | M5 / N |

M3 不计入严格正确，用户已同意按此执行。M3 必须单列，因为它是 R1 病灶的直接度量：M3 率高说明看到了断裂但定位错，对应第 3.5 节 V3 判档待验证项；M4 率高指向另一类问题，模型没把断裂当断裂。两者混看，会把定位问题误判成识别问题。

### 6.3 混淆矩阵模板

每行是一个预测标签（四态加 abstain），每列是一个真值状态，格子填样本计数。

| 预测 \ 真值 | 未断裂 | 临界未断裂 | 发生断裂 | 已断裂 |
| --- | --- | --- | --- | --- |
| 未断裂 | M1 | M3 | M4 | M4 |
| 临界未断裂 | M3 | M1 | M3 | M4 |
| 发生断裂 | M4 | M3 | M1 | M3 |
| 已断裂 | M4 | M4 | M3 | M1 |
| abstain | M5 | M5 | M5 | M5 |

相邻档位记 M3，跨两档及以上记 M4。已断裂与未断裂相距三档，判成未断裂记方向错。

### 6.4 等级归类示例

| 真值 | M 原始输出要点 | 等级 | 说明 |
| --- | --- | --- | --- |
| 已断裂 | 首帧即有断口，全程保持断裂 | M1 | 标签一致 |
| 已断裂 | 首帧已见断口，属一开始就断 | M2 | 表述不同，语义相同 |
| 已断裂 | 起拍完整，约 2 秒后出现断裂 | M3 | 看到了断裂，位置判错 |
| 已断裂 | 全片段未见断裂 | M4 | 方向错 |
| 发生断裂 | 首帧完整，末帧断裂 | M1 | 标签一致 |
| 发生断裂 | 首帧即断裂 | M3 | 相邻档位混淆 |
| 未断裂 | 无法判断 | M5 | abstain |

### 6.5 指标按两轴拆分

四个 `clip_state` 不是单一有序刻度，而是两个维度的交叉：轴 1「断没断」，轴 2「什么时候断」。

- 轴 1（断裂是否已发生）：`fracture_event_is_after_clip`（未断裂）与 `fracture_event_is_after_clip_with_visible_precursors`（临界未断裂）为未发生，`fracture_event_is_within_clip` 与 `fracture_event_is_before_clip` 为已发生。
- 轴 2（断裂相对片段的位置，仅在已发生时定义）：`fracture_event_is_before_clip`（首帧即断 = 已断裂）与 `fracture_event_is_within_clip`（片段内断 = 发生断裂）。

两个替代指标。

| 指标 | 所属轴 | 定义 | 分母 / `support` |
| --- | --- | --- | --- |
| 断裂检出率 | 轴 1 | 能否判断「这个片段里试样已经断裂」：真值为已发生断裂的样本（发生断裂 + 已断裂）中，预测侧判为已发生的占比 | 真值侧 `|{真值 ∈ 已发生}|` = 177 |
| 时序定位准确率 | 轴 2 | 能否判断断裂发生在片段之前还是片段之内：预测侧判为已发生断裂的样本中，位置（before / within）与真值一致的占比；条件于已判为断裂的样本 | 预测侧 `|{预测 ∈ 已发生}|`，随预测分布变化 |

```text
断裂检出率   = |{真值 ∈ 已发生 ∧ 预测 ∈ 已发生}| / |{真值 ∈ 已发生}|
时序定位准确率 = |{预测 ∈ 已发生 ∧ 位置与真值一致}| / |{预测 ∈ 已发生}|
已发生 = {发生断裂, 已断裂}；位置 = {fracture_event_is_before_clip, fracture_event_is_within_clip}
已发生断裂的 support = 发生断裂 144 + 已断裂 33 = 177
```

时序定位准确率的三条口径约定。

- 分母为 0 时：跨批次按样本级合并，不做批次级平均；某批分母为 0（例如模型整批判为未断裂）时该批该指标记 `undefined` 并单独计数，不得剔除非零批次或整批丢弃。
- `support` 口径与门禁规则不同：该指标的 `support` 是预测侧 `|{预测 ∈ 已发生}|`，而第 7.3 节规定「`support` 指该类别真值条数」，两者不是同一个量，不能直接套用 7.3 的 `support < 20` 判 `insufficient_evidence`；接入门禁前须为它单列规则。
- 条件于预测侧，必须成对报告：检出率上升会扩大分母，定位准确率可能机械下降。该指标单独引用无效，须与断裂检出率成对报告；跨批次比较须同时登记两个值。

与 6.1 / 6.3 的关系。M1–M5 与 6.3 的混淆矩阵建立在四态排列的相邻关系上（「相邻档位」「相距三档」），只作为兼容口径保留；两轴口径下，轴 1 的漏检 / 误报与轴 2 的位置错分别记，不再借「相邻档」表达。6.1 与 6.3 原文不动。

`four_state_macro_recall` 把两轴拍平成一个算术平均，导致两类不同错误混算：轴 1 的漏检与轴 2 的位置错在同一个均值里互相掩盖。

R1 实测：四态联合 recall（不分轴）。下表给的是该状态整体判对的占比，不是某一轴的指标。联合 recall 无法直接读成轴 1 / 轴 2 的指标：拆解需要四态真值行的全部预测侧交叉计数，轴 1 用到 33 与 144 两行，轴 2 的分母还要 未断裂 191、临界未断裂 57 两行预测成发生断裂的计数（共 129）。旧口径这批矩阵已在库，本节后文据此给出点估计；新口径矩阵尚未入库（第 11 节 U8）。「契约方向值」列是该状态在 `search_semantics` 中的取值，不是指标所属轴的判定。

- 临界未断裂 0.228070 → 0.105263 明显下降。该档的退化不被任一轴指标直接度量：它有 17 条被判成发生断裂，只体现为对时序定位准确率分母的惩罚（属 45 条轴 1 误报之一），不被记为「该档退化」本身。
- 已断裂 0/33 指无一被判成 `已断裂`（精确状态命中为 0）：其中 18 条被判成 `发生断裂`，在轴 1 上计命中、在轴 2 上计位置错；14 条被判成 `未断裂`、1 条被判成 `临界未断裂`，属轴 1 漏检。因此「已断裂 0/33」不等于「这 33 条在轴 1 上全未检出」。

旧口径点估计。前提：33 条已断裂的标注确实符合 `fracture_event_is_before_clip` 语义；该项待人工抽看首帧（第 3.5 节 V1、第 11 节 U11），在此之前上述计数按「标注待验证」使用。真值已发生（发生断裂 + 已断裂）计 177 条，其中判为已发生的有 84 条（发生断裂命中 66 + 已断裂被判为发生断裂 18），断裂检出率 = 84/177 = 0.474576。预测侧判为已发生的有 129 条（发生断裂 129 + 已断裂 0），位置与真值一致的有 66 条，时序定位准确率 = 66/129 = 0.511628。两数已由脚本从上述两份在库文件复算，并与 `evaluation_summary.json` 的混淆矩阵逐格对齐。

可解读性边界。在预测侧从未输出 before 的条件下，时序定位准确率退化为「发生断裂」的精确率 P(真值 = 发生断裂 | 预测 = 发生断裂)，不是定位能力刻度；分母 129 中有 45 条真值为未发生（轴 1 误报），按定义永不可能计入正确。因此该值须与「已断裂输出为零」并列呈现，不得单独作为能力结论。

轴 2 在输出侧塌缩。旧口径 `prediction_clip_state_distribution` 里没有「已断裂」键，即模型一次都没有输出过 before：33 条已断裂中 14 条判成未断裂、1 条判成临界未断裂、18 条判成发生断裂。轴 2 的问题不是「定位不准」，而是该档位在输出侧完全缺失，与第 1.2 节的塌缩现象同属一类。

新口径只到下界。新口径（8 帧 / 512 视觉 token）的混淆矩阵在仓库内不存在（第 11 节 U8），只有第 1.1 节的实测数字，因此只能给界：发生断裂精确命中 86 条，断裂检出率 ≥ 86/177 = 0.485876。上界分两种情形：若新口径同样从不输出 before（旧口径实测 `prediction_clip_state_distribution` 无「已断裂」键，即此情形），则 33 条已断裂至多全部被判成发生断裂，上界 = (86 + 33)/177 = 119/177 = 0.672316；若新口径出现「发生断裂 真值 → 已断裂 预测」的输出，上界退化为理论上界 1，无信息量。旧口径实测 84/177 = 0.474576 落在 [0.485876, 0.672316] 区间下方，故「小幅提升成立、幅度未知」；精确值仍待新口径混淆矩阵（第 11 节 U8）。

方向结论。断裂检出率在新口径下不低于 0.485876，高于旧口径 84/177 = 0.474576，即小幅提升成立；但幅度下限只有 2 条样本（84 → 86），不足以支撑「检出能力明显改善」的结论。

结论：`four_state_macro_recall` 保留作兼容参考与历史对比，主指标改为两轴分开报告。旧口径两轴点估计已由脚本从在库逐样本记录复算（见上），新口径点估计待其结果文件与混淆矩阵入库（第 11 节 U8）；本稿只给定义、复算值与新口径的下界。

范围声明：本轮只改报告口径。两轴指标接入第 7.4 节门禁、第 9 节 `metric_spec_version`、第 10.1 节改造清单，须待指标精算，受第 11 节 U7 约束，不在本轮落地。

## 7. 指标与门禁 v2

### 7.1 三层结构

| 层级 | 作用 | 达标处理 | 不达标处理 |
| --- | --- | --- | --- |
| L0 硬阻断 | 检查记录本身是否可信 | 进入 L1 | 整批判失败，不参与加权 |
| L1 能力门 | 统计意义上的最低能力 | 通过 | 判失败，进入归因 |
| L2 参考指标 | 观察趋势 | 记录 | 只记录，不阻断 |

L0 与 L1 分开的意义：被截断、乱码、拒答这类记录的分数没有解释力，算进 L1 会污染能力判断。L0 先清，L1 再算。

### 7.2 L0 七条硬阻断

用户已确认这七条够用。任一触发即该条无效。

| 编号 | 触发条件 |
| --- | --- |
| L0-1 | 空输出或纯空白 |
| L0-2 | 崩溃、超时、OOM |
| L0-3 | 被 `max_new_tokens` 截断 |
| L0-4 | 乱码 |
| L0-5 | 拒答 |
| L0-6 | 退化循环：同一短语无终止重复 |
| L0-7 | 泄露真值：输出里出现输入真值或标注痕迹 |

整批 L0 命中率写入报告，命中率本身是信号：截断命中率高说明输出预算不足，乱码命中率高说明生成异常。

### 7.3 门槛形式：Wilson 下界

门限从「点估计 ≥ T」改为「Wilson 95% 置信区间下界 ≥ T」。33 条样本里 5 条正确得 0.1515，置信区间下界远低于 0.15，点估计无法支撑「已具备该能力」的结论。support 指该类别真值条数，`support < 20` 判 `insufficient_evidence`；该状态既不判通过也不判失败，该类别门保持待定，不得用于晋级。

### 7.4 新增门

| 门 | 形式 | 目的 |
| --- | --- | --- |
| 塌缩检测门 | 预测分布与真值分布的 JS 散度 ≤ 阈值 | 捕捉形式合法但分布塌缩 |
| M3 上限门 | M3 率 ≤ 阈值 | 直接约束时序档位错 |
| 视觉依赖门（可选） | 视频截断到断裂前帧，模型应改判 | 判分不变则说明未真正用视觉 |

塌缩检测门针对第 1.2 节的现象：预测集中在单一类别时 JS 散度显著偏高，这类结果即使准确率可取，也不代表能力。M3 上限门是核心新增门，它把 0/33 与「看到了但定位错」分开计量，避免只靠 M4 一个维度判断。视觉依赖门是反事实检验：截掉断裂发生后的帧，M 仍给出相同判读，说明它没看视频，判读来自 Prompt 或先验；该门成本较高，可选。

### 7.5 门槛推导方法

1. 定义漏检与误报的代价比 k：漏检一条断裂的代价是误报一条的 k 倍。
2. 用 k 得判正概率 1/(1+k)，作为扫描起点。
3. 在真值分布上扫描，得到每个门槛对应的 recall 与误报率。
4. 取满足代价约束的最低 recall 作为目标 recall。
5. 把目标 recall 换算成 Wilson 95% 下界阈值，即门限。

| 情景 | k（漏检 : 误报） | 参考量 1/(1+k) | 最低 recall 目标 | Wilson 下界阈值 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 宽松 | 3 | 0.25 | 待精算 | 待精算 | k 待用户确定，数值待脚本精算 |
| 平衡 | 10 | 0.0909 | 待精算 | 待精算 | k 待用户确定，数值待脚本精算 |
| 严格 | 50 | 0.0196 | 待精算 | 待精算 | k 待用户确定，数值待脚本精算 |

`k` 待用户确定，数值待脚本精算。参考量 1/(1+k) 由公式直接给出，只说明推导方向，不充作门限。指标定义、门槛数值、口径三者必须同批修改，否则 R2 的 0.52 与 R1 的 0.41 不是同一个量，不可比。分批改的后果是台账里同时存在两种「准确率」，任何跨批次比较失去依据。

| --- | --- | --- | --- | --- |
| 阶段一 探索 | T1 全量标注 | 只做形式校验与聚合 | 双判读 κ ≥ 0.6、与人工一致率 ≥ 0.85、连续 3 批稳定 | κ 或一致率不达线，补标例后重跑，不进阶段二 |
| 阶段二 混合 | 脚本为主，T1 兜底 | 词表与规则判读，未命中交 T1 | 脚本与 T1 分歧率 ≤ 5%、连续 3 批稳定 | 分歧率 > 5% 回退阶段一 |
| 阶段三 定型 | 脚本覆盖，T1 抽检 | 全量脚本判读，5% 抽检 | 抽检一致率 ≥ 95%、连续 5 批稳定 | 抽检一致率 < 95% 回退阶段二 |

两点说明。批次指同一口径下的完整评测批次，不是单次抽样。降级由自动检测触发（分歧率、一致率越阈值即报警），回退决定由人做：自动检测只报警，回退会改变判读主体，属口径变更。

## 9. 口径版本化

每条指标必须同时带四项元数据，缺任一项的数字不可引用。

| 元数据 | 内容 | 作用 |
| --- | --- | --- |
| `eval_pipeline{frames, groups, vision_tokens}` | 帧数、时序组数、视觉 token 数 | 绑定输入链路 |
| `parser_version` | 解析器版本 | 绑定解析行为 |
| `metric_spec_version` | 指标定义版本 | 绑定指标口径 |
| `judge_id` | 判读器身份 | 绑定判读主体 |

示例片段。`metric_spec_version` 与 `parser_version` 取占位标识，正式标识在改造分支内按仓库规则登记。

```yaml
metric:
  name: 已断裂_recall
  value: 0.0
  support: 33
  eval_pipeline:
    frames: 8
    groups: 1
    vision_tokens: 64
  parser_version: placeholder-parser-v1
  metric_spec_version: placeholder-metric-v1
  judge_id: script
```

R1 旧口径 = `{frames: 8, groups: 1, vision_tokens: 64}`，R1 新口径 = `{frames: 8, groups: 8, vision_tokens: 512}`。两者 `metric_spec_version` 也不同：旧口径按四字段全对计 joint，新口径引入 M1–M5 等级与 Wilson 下界门。帧数相同而组数不同，正是第 1.1 节「同模型同数据同 Prompt，只改管线」的解释。四项元数据缺任一项即标 `unbound`，不得进入门禁计算，不得进入跨批次对比。

## 10. 实施顺序与分支计划

本轮不改字段、不改实现。设计定稿后开新分支一次性改造测评与门禁，不分散成多次改动。分散改会让中间状态里新旧口径并存，门禁读到的指标定义不确定。分支按仓库规范取 `eval/` 前缀，具体名称开工时确定。

### 10.2 实施顺序

1. 先落字段与解析（`finetune/v4_1_runtime.py`、`finetune/validation/`），后续环节读同一份解析结果。
2. 再落 T1 判读器与判例库，跑阶段一，取得 κ 与一致率证据。
3. 再重写门禁（`finetune/holdout_metrics.py`），门限数值靠阶段一的分布数据精算。
4. 最后接闸机（`versioning/`），避免中途出现「新指标配旧闸机」。

### 10.3 旧口径数字的处理

改造必须支持把 R1 旧口径数字重新标注为「不可直接比较」，不做静默换算。旧记录保留原值，补写四项元数据，在报告与台账显式标注口径差异。用换算系数把旧数字折算成新口径的做法禁止使用：换算依赖对分布形状的假设，假设无从验证。
