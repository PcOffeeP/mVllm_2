# V4.1 视觉适配与数据扩充微调优化设计

## 目标与范围

在保持 `tensile-vlm/v4.1` 四字段输出契约不变的前提下，解决当前模型能够稳定输出合法
JSON、却不能可靠识别断裂视觉语义的问题。本轮只处理两条主线：

1. 让 LoRA 覆盖 MiniCPM 的视觉塔，并让多模态投影层参与训练。
2. 增加具有独立视觉信息的人工审查数据，并用受控重采样缓解训练阶段的类别不均衡。

标签语义、Agent 搜索逻辑和人工审查结论不在本轮修改范围内。本轮属于训练配方和训练数据
覆盖度升级，不创建新的模型输出契约版本。

## 当前基线与问题证据

三折验证共 1216 条，运行异常为 0，输出契约合法率为 100%，但：

- `clip_state` 加权正确率为 42.60%；
- 模型将 77.71% 的样本预测为 `未断裂`，而验证集真实占比为 44.98%；
- `临界未断裂`、`发生断裂`、`已断裂` 的召回率分别只有 21.12%、3.43%、2.00%；
- 非空断裂机制和断裂位置的准确率分别只有 19.46% 和 23.66%。

现有 LoRA adapter 的目标模块只包含语言模型层。训练框架对 MiniCPM 默认设置
`freeze_vision_tower=true` 和 `freeze_multi_modal_projector=true`，因此 `vpm` 视觉塔和
`resampler` 多模态投影层均未适配。

当前不可变发布包含 1275 个候选，但只来自 85 个源视频。候选数量不能等同于独立视觉样本
数量。部分标签只有极少源视频：

| 标签 | 候选数 | 独立源视频数 |
|---|---:|---:|
| 韧性断裂 | 391 | 41 |
| 脆性断裂 | 211 | 25 |
| 界面脱粘 | 90 | 8 |
| 爆炸性断裂 | 9 | 1 |
| 半脆半韧断裂 | 1 | 1 |
| 标距外非齐根 | 129 | 13 |
| 齐根断裂 | 73 | 7 |
| 临界未断裂 | 161 | 35 |

因此，模型当前主要学会了稳定的文本输出模式，但视觉层没有进行领域适配，多个细分类别也
缺乏足够的独立视觉变化。

## 权威来源与明确非目标

- 人工审查决定是唯一训练标签真值。
- 不由模型、脚本或 Codex 重新观看帧并推翻人工标签。
- 不因为同一源视频的历史标签而自动修改候选级人工决定。
- 不生成伪标签，不用模型输出补齐稀有类别。
- 不把重复候选或同源重叠窗口统计成新增独立数据。
- 不修改当前不可变发布 `v4.1.0-760050fad303`。
- 不直接进入完整三折重训；先完成可归因的单折对照实验。
- 本轮不同时大幅修改 LoRA rank、dropout、学习率和视觉覆盖范围，避免无法判断收益来源。

媒体存在性、哈希、契约合法性和人工决定绑定仍由程序校验，但这些校验不包含主观视觉
重审。

## “重采样”和“增加数据”的区别

### 训练重采样

重采样是优化阶段的权重控制。同一人工审查候选可能在一个训练周期中被抽到更多次；同一源
视频下的不同候选也可能参与多次训练。它能减少多数类对损失的支配，但不会产生新的视觉
信息。

实现时不复制或改写不可变数据集文件，而是生成带版本、随机种子和权重的训练采样清单。
采样顺序为：

1. 先选择目标 `clip_state`、断裂机制或断裂位置类别；
2. 再优先选择该类别中本轮使用次数较少的源视频；
3. 最后在该源视频内选择人工审查候选；
4. 设置单源视频贡献上限，避免一个稀有源视频被重复成几十个“独立样本”。

训练集可以重采样；验证集和测试集禁止重采样。分折必须先按源视频完成，再对训练折采样，
防止同源泄漏。

### 数据扩充

数据扩充必须引入新的独立源视频、试样、断裂外观或拍摄变化，并完成既有人工审查流程。
同一源视频裁出更多重叠窗口只增加候选数，不计为独立数据量增长。

数据扩充优先级由“独立源视频覆盖不足”决定：

1. 半脆半韧断裂、爆炸性断裂；
2. 界面脱粘；
3. 齐根断裂、标距外非齐根断裂；
4. 临界未断裂；
5. 已有较多覆盖的韧性标距内断裂。

不预设“多少条一定足够”的虚假固定数字。每次新增发布都生成按独立源视频数量分层的学习
曲线；只有新增源视频继续带来验证集宏平均召回率提升时，才认为数据仍处于有效增长区间。
只有一个源视频的类别只能用于流程验证，不能宣称模型已经学会该类别。

## 方案比较

### 方案 A：只做重采样和数据扩充

优点是训练稳定、显存风险最低。缺点是视觉编码保持冻结，细微颈缩、裂纹和断开特征仍只能
依赖通用视觉表征，可能继续只学习类别先验。

### 方案 B：只开放视觉层

优点是可以验证视觉适配是否为主要瓶颈。缺点是稀有类别仍缺少独立视觉样本，视觉层可能
记忆少数源视频并在验证集失效。

### 方案 C：分阶段结合视觉适配与数据扩充

先使用当前不可变发布做视觉覆盖对照实验，证明训练链路和视觉梯度有效；随后在新人工审查
数据发布上加入源视频感知的受控重采样，再执行完整三折训练。该方案能分别归因“视觉层开放”
和“数据覆盖增长”的收益，采用此方案。

## 推荐训练架构

### 阶段 1：当前数据上的视觉覆盖对照

固定 fold0 数据、提示词、标签、帧契约和现有超参数，比较三个配方：

| 配方 | 语言 LoRA | `resampler` | `vpm` 视觉塔 | 用途 |
|---|---|---|---|---|
| R0 | 是 | 冻结 | 冻结 | 已完成基线 |
| R1 | 是 | 全量训练并保存 | 冻结 | 验证投影层收益和显存 |
| R2 | 是 | 全量训练并保存 | LoRA | 推荐视觉适配方案 |

R2 使用以下显式配置：

```yaml
finetuning_type: lora
lora_target: all
freeze_vision_tower: false
freeze_multi_modal_projector: false
additional_target: resampler
```

`lora_target=all` 在视觉塔解冻后允许 LoRA 发现 `vpm` 中的线性层；框架会始终从普通 LoRA
目标中排除投影器，因此 `resampler` 必须通过 `additional_target` 完整保存，不能只设置
`freeze_multi_modal_projector=false`。

阶段 1 保持 rank 8、dropout 0.25、学习率 `5e-6`、weight decay 0.2 和三轮训练不变，用于
隔离视觉覆盖变量。只有 R2 明确优于 R0/R1 后，才进入 rank、dropout、学习率和正则化的
第二轮小规模搜索。

### 阶段 2：新增人工数据与源视频感知采样

新增数据沿用 V4.1 人工审查和冻结发布流程，生成新的内容寻址训练发布。训练采样清单至少
记录：

- 发布 ID 和契约哈希；
- 候选 ID、源视频 ID 和人工决定 ID；
- `clip_state`、断裂机制、断裂位置；
- 样本权重、单源上限和随机种子；
- 各类别的候选数与独立源视频数；
- 训练折采样前后分布。

采样首先平衡四个可搜索状态，再在断裂相关状态内部改善机制和位置覆盖。若某个细分类别只
有极少源视频，不通过无限重复强行“平衡”，而是保留其真实覆盖并在报告中标为数据不足。

### 阶段 3：完整三折确认

只有阶段 1 的视觉配方通过门槛、阶段 2 的新发布完成全量人工审查后，才运行完整三折训练、
模型合并和 1216 条以上的全量推理评估。

## 组件与职责

- 训练配方：新增 R1/R2 单折实验配置，显式声明视觉冻结状态和 `resampler` 保存方式。
- 配置验证器：拒绝“声称视觉 LoRA、实际仍冻结视觉塔”的配置。
- adapter 覆盖检查：训练后检查 adapter 目标包含 `vpm`，并确认 `resampler` 被保存。
- 数据覆盖审计：按候选和独立源视频分别统计状态、机制、位置及其组合。
- 采样清单生成器：只读取人工冻结发布，生成可追踪、可复现的训练索引，不改写原发布。
- 评估器：继续使用现有严格 V4.1 解析，增加宏平均状态召回率、断裂相关宏召回率和预测分布。
- 发布门禁：保留契约合法率、运行异常、媒体哈希、同源隔离和不可变发布检查。

## 模型选择与验收

训练过程不能继续只用 `eval_loss` 作为最终效果判断。checkpoint 可以用损失做早停，但配方
晋级必须依据完成推理后的任务指标。

阶段 1 开发门槛：

- 训练配置实际覆盖声明的视觉模块；
- 一个最小训练 smoke test 中，`vpm` LoRA 和 `resampler` 都获得非零梯度；
- adapter 可保存、重新加载并合并；
- 推理运行异常为 0，V4.1 契约合法率保持 100%；
- R2 的断裂相关三状态宏平均召回率相对 R0 至少提高 10 个百分点；
- `临界未断裂`、`发生断裂`、`已断裂` 中至少两个状态的召回率提高，任一状态不得下降超过
  5 个百分点；
- 单一预测状态占比不得超过 70%；
- 结果按 fold、状态、机制、位置和独立源视频覆盖一起报告。

阶段 2/3 数据与效果门槛：

- 新数据全部具有人工审查决定，不存在模型伪标签；
- train/validation/test 按源视频隔离；
- 稀有类别同时报告候选数和独立源视频数；
- 学习曲线至少使用三个按独立源视频嵌套的数据规模和两个固定随机种子；新增源视频后的
  断裂相关宏平均召回率应高于只增加重复次数的对照组；
- 以四状态宏平均召回率为主指标，联合正确率和未断裂误报率为约束指标；
- 不把 `null` 标签带来的表面机制/位置准确率当作断裂识别能力。

## 失败处理

- 视觉配置训练后 adapter 不含 `vpm`：立即失败，不允许降级成语言 LoRA 后继续。
- `resampler` 未随 adapter 保存：立即失败，不允许合并或评估。
- 视觉方案显存不足：先退回 R1 投影层实验，不静默冻结视觉层。
- 重采样清单出现未知人工决定、跨折源视频或单源超限：拒绝发布。
- 稀有类别没有新增独立源视频：如实标记数据不足，不用无限重复伪造平衡。
- 视觉适配只提高训练集、不提高验证集：判定为同源记忆或过拟合，停止完整三折。
- 合法率下降或运行异常出现：先修复训练/推理链路，不把异常计为模型错误。

## 开发与验证顺序

1. 固化当前三折结果为 R0 基线报告。
2. 实现数据覆盖审计和源视频感知采样清单格式。
3. 实现 R1/R2 配置、配置验证器和 adapter 覆盖检查。
4. 在训练机执行最小视觉梯度、保存、加载和合并 smoke test。
5. 在 fold0 执行 R1/R2 对照训练与全量 fold0 推理。
6. 根据对照结果确定是否进入超参数小规模搜索。
7. 收集并人工审查新的独立源视频，冻结新的内容寻址数据发布。
8. 在新发布上执行源视频感知重采样和完整三折训练。
9. 合并模型并运行严格 V4.1 全量推理，发布覆盖度、召回率、混淆矩阵和失败清单。

## 交付边界

本设计可以立即交付阶段 1 的开发、配置验证、覆盖审计和训练机 smoke test。阶段 2 的数据
扩充工具可以完成，但新独立源视频的采集和人工审查仍需要人工输入；在这些数据实际存在前，
不能声称已经完成“数据量不足”的效果验证。
