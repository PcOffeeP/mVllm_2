# Python 脚本目录整理设计

## 目标

让 `finetune/` 和 `pipeline/` 一眼可读，不引入复杂分层。

## 规则

1. 当前流程入口留在原目录，文件名和命令不变。
2. 已完成、已替代或只用于历史复现的脚本移入单层 `archive/`。
3. 公共运行时模块不为“视觉整齐”强行搬家。
4. 每个目录增加 `SCRIPTS.md`，只说明当前入口、用途和历史入口位置。
5. 历史证据内容和配置哈希不改写。

## 目标结构

```text
finetune/
├── 当前数据、训练、评测入口
├── 公共 runtime
├── archive/        # 已完成或被替代的训练工作流
└── SCRIPTS.md

pipeline/
├── 当前数据与服务模块
├── scripts/        # 当前可执行数据流程
│   ├── archive/    # 旧 V2/V3/V4 工具
│   └── SCRIPTS.md
├── archive/        # 旧标签与审核模块
└── SCRIPTS.md
```

## 验证

- 更新所有 Python import、测试和当前文档命令。
- 历史配置与 manifest 保持原字节和哈希。
- 运行根脚本语法检查、残余引用检查和全部可运行 CPU 测试。
- 本机原子提交后，再按双机 Git 状态决定训练机同步时机。
