# 视频 ROI 选框、裁剪与审核

从项目根目录启动：

```bash
python3 script/roi/roi.py
```

macOS 也可双击本目录的 `run_roi.command`。启动器优先使用项目 `.venv/bin/python`，否则使用 `python3`。命令与界面使用同一套决定和处理清单；有现成决定和没有决定的视频会出现在同一工作列表中。

工具的画面保留及审核依据是 [ROI 裁剪规则](../../docs/roi-rules.md)。几何、ffmpeg 编码与媒体属性校验从原项目 `2c272ce` 的 ROI 实现抽出；本工具独立运行，不依赖原项目的版本注册和发布体系。

## 安装后打开工作列表

需要 Python 3.10 及以上，PATH 中可用的 `ffmpeg`、`ffprobe`，以及界面依赖：

```bash
python3 -m pip install -r script/roi/requirements.txt
python3 script/roi/roi.py
```

如果项目环境已安装这些依赖，可直接用 `.venv/bin/python script/roi/roi.py`。界面仅监听本机 `127.0.0.1`。

1. 在工作列表中选择视频，播放原视频并查看关键过程。预览位置支持以单帧时长为步长调整；变帧率视频的步长仅辅助定位。
2. 选择固定 3:4 框或全画面补边。拖动后点击“采用当前拖框”，最终生效的像素框、各方向裁剪量或补边量会显示在下方。也可精确输入像素坐标。
3. 填写源画面证据审核。异常与现象逐项检查；“证据不足”须区分源视频本来不足和处理造成损失，“不适用”须说明依据。填写实际看过的秒数或区间后，保存范围和审核。
4. 点击“生成／重试／核对可复用视频”。工具检查媒体属性；满足身份与几何条件的已有视频可复用，否则重新编码。
5. 播放实际输出，与源视频对照，再填写输出证据审核。输出视频通过两次审核和媒体检查后才显示“已完成”。

**没有已有决定属于正常情况。** 工具会显示“待选框”，不会自动批准全画面。暂时无法审核时，填写待处理原因并点击“保存选框和审核进度”或“保存输出审核进度”；草稿会恢复到工作列表，仍保持待审核，其余视频可继续处理。历史记录中的五项可见性布尔值不会代替当前证据审核。

## 默认输入与可选参数

所有相对路径按项目根目录解析，与命令执行时的当前目录无关。

| 输入 | 默认路径／行为 | 参数 |
| --- | --- | --- |
| 源视频 | `data/videos/`，递归读取支持的视频文件；文件名去扩展名作为唯一 ID | `--videos-dir` |
| 辅助标签 | `data/annotation-table-full.csv`，不存在时仍可选框；只读 | `--labels` |
| 已有决定候选 | `data/roi/imports/roi_decisions.legacy.json`，可缺失 | `--decisions` |
| 已有输出清单 | `data/roi/imports/media-manifest.legacy.json`，可缺失 | `--existing-manifest` |
| 已有视频目录 | `data/roi/imports/media/<视频ID>.mp4`，可缺失 | `--existing-media-dir` |
| 划分记录 | `data/splits/` 下仅有一个可识别版本时自动读取；多个版本时须选择 | `--splits-dir` |
| 输出目录 | `data/roi/` | `--output-dir` |
| 项目根目录 | 按脚本所在位置自动定位 | `--project-root` |

支持扩展名为 `.mp4`、`.mov`、`.mkv`、`.avi`、`.m4v`、`.webm`，大小写均可。浏览器能否播放原视频取决于封装和编码；无法播放时，请用外部播放器对照原视频，界面中的 ffmpeg 单帧预览仍可辅助选框。当前不生成浏览器预览代理。相同文件名对应多个路径或扩展名时，记录 ID 冲突并停止相关视频。所有源视频均纳入工作列表，不根据训练、验证或测试划分筛选；原标注表及数据划分不会被修改。已有划分以 `test.json`、`fold_N_train.json` 和 `fold_N_val.json` 中的 `video_ids` 数组读取。清单分别记录 test/development 及开发集每折的 train/val；新视频没有对应划分时标为 `not_provided`，仍可裁剪。划分内重复或跨集合冲突会显式列出并保持待核实。多个版本不自动猜测或合并，可用 `--splits-dir data/splits/所选版本` 指定。

例如处理新目录：

```bash
python3 script/roi/roi.py --videos-dir data/new-videos --output-dir data/new-roi
```

决定 JSON 使用含 `decisions` 数组的对象。旧决定中的 `source_video_id`、`source_sha256`、`source_resolution`、`mode`、`pixel_box` 可作为候选；源摘要、分辨率或方向不一致时，必须复核。工具生成的决定还含 `rule_version` 和逐项的 `source_review`。

已有视频仅在源摘要、输出摘要、处理方式、像素框及清单声明的编码配置一致时作为复用候选；之后仍需通过媒体检查和实际输出审核。旧清单若未声明 `exact=1`，工具依据源视频实际像素格式检查色度对齐。可识别的 4:2:0、4:2:2、4:4:4 格式按各自对齐要求核对起点；未对齐、未知格式及其他采样格式的旧固定框输出不自动复用，会按当前生效框重新生成。输出的 `yuv420p` 编码不能代替源像素格式核对。仅有视频文件而没有可核验清单时，工具不会按文件名认定身份。已有清单顶层含 `encoding_profile`（原格式的 `video_codec`、`preset`、`crf`、`pixel_format`、`audio`、`frame_sync`），以及 `videos` 数组，逐条包含 `source_video_id`、`source_sha256`、`output_sha256`、`mode` 和 `pixel_box`。

全画面补边先在 4:4:4 画面上执行，确保奇数边距不会被色度采样取整，最后按配置编码为 `yuv420p`。旧补边结果也须能证明实际边距与当前记录一致；源格式未知或边距不对齐时重新生成。

## 输出文件与状态

```text
data/roi/
├── drafts.json                     # 尚未批准的选框与源审核进度
├── decisions.json                  # 生效范围及源画面审核
├── manifest.json                   # 全量工作列表、身份、参数、输出与审核状态
├── batch-errors.json               # 最近一次有生成错误的批处理记录
├── media/<视频ID>/<处理摘要>.mp4     # 生成或复用的输出
└── imports/                        # 可选候选资料，只读
```

`manifest.json` 记录每个 ID 的源路径、SHA-256、分辨率、方向、帧数、帧率、时长、候选决定、输出路径和摘要。成功生成后还记录编码配置、四个方向的裁剪和补边像素数、输出分辨率、媒体检查状态及输出审核。辅助标签随工作记录保留，供审核参考，不回写标注表。

| 状态 | 含义／下一步 |
| --- | --- |
| `needs_decision` | 无决定；选框和审核 |
| `needs_review` | 候选身份不符、旧规则或审核缺项；复核并保存 |
| `ready` | 源画面审核已完成；可生成 |
| `needs_output_review` | 媒体检查通过；检查实际输出 |
| `success` | 源画面、媒体属性和实际输出审核通过 |
| `needs_verification` | 方向等属性需要核实 |
| `failed` | 输入或生成失败；原因保留，生成失败可重试 |

处理摘要包含源身份、画面范围、规则及处理版本和编码配置。不同处理摘要使用不同输出文件，历次输出和审核按摘要保存在 `history` 中。切回此前范围时，工具重新核对历史输出身份后恢复对应结果。已存在但没有对应记录的文件不会被直接覆盖或认定合格。清单覆盖所有输入 ID；此前登记的视频缺失或不可访问时，仍保留该条目及历史记录并显示失败，不能因为文件消失而变成全量完成。同一文件恢复后按摘要重新核对。若有意开始不同的视频集合，应使用单独的输出目录。

## 无界面核对与批处理

只核对输入并写工作清单：

```bash
python3 script/roi/roi.py --scan
```

生成所有 `ready` 条目：

```bash
python3 script/roi/roi.py --batch
```

批处理不弹出选框界面，也不替用户填写审核。没有决定或尚未审核的条目保持待处理。退出码 `0` 表示扫描完成，或批处理后所有条目已完成；`2` 表示仍有待处理项；`1` 表示配置、输入读取或生成错误。生成失败原因也会写入处理清单和错误汇总。

## 验证范围与当前边界

编码采用 H.264、`fast`、CRF 23、`yuv420p`、去音频。工具检查输出解码、分辨率、帧数、标称帧率和时长；这些检查不能证明细节无损或逐帧时间戳完全相同，实际画面仍须人工审核。

带非零旋转标记的视频保持待核实，当前不会自动猜测方向或转换裁剪坐标。帧率、时长、帧数无法可靠获取时保留失败原因。工具不自动推断事件时间，不生成子视频，不评价标签或模型效果。

首次核对会读取源文件摘要和媒体元数据。文件头帧数只作为未核实信息显示，可能与实际解码帧数不同；生成或复用当前视频时才实际计帧，并按源摘要缓存结果，输出也实际计帧后比较。清单分别记录 `metadata_frame_count` 和有效 `frame_count`，`frame_count_basis=decoded` 表示已实际计帧；普通列表刷新不逐条解码视频。后续列表刷新按文件大小、修改时间复用缓存；保存决定、生成或复用输出、确认输出审核前，针对当前视频重新核对完整摘要。缓存仅用于浏览提速，不替代处理前的身份检查。生成后的输出会完整解码校验。长视频或整批处理应在训练机运行；本机用于开发及小型合成样例检查。测试命令：

```bash
python3 -m pytest -q script/roi/tests
```

测试和编译通过只覆盖实现逻辑及合成样例，不能替代真实视频画面验收。

**失效条件：**入口、默认路径、记录格式、审核规则、编码或媒体验收方式变化时，更新本说明。记录的规则版本发生变化后，需要重新核对受影响决定和输出。
