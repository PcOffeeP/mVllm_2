# 源视频固定 ROI 选框与标签

在项目根目录启动：

```bash
.venv/bin/python script/roi/roi.py
```

macOS 也可双击本目录的 `run_roi.command`。启动器优先使用项目 `.venv/bin/python`，否则使用 `python3`。需要 Python 3.10 及以上、PATH 中可用的 `ffmpeg` 和 `ffprobe`。界面依赖安装命令：

```bash
python3 -m pip install -r script/roi/requirements.txt
```

## 使用原 ROI 选框界面

界面直接以原项目 `roi_annotation_app.py` 为底本，保留原来的三栏、控件顺序、抽帧滑块、3:4 红框和对照预览。左侧筛选、搜索和选择源视频；中间查看源视频与当前帧、拖动红框；右侧设置裁剪决定，并显示按当前标注预填的标签。

工作列表覆盖全部源视频，不按训练、验证或测试划分筛选。已有 ROI、标签审查记录和裁剪决定通过当前工作区读取。

“原始视频播放”“当前帧 ROI 对照预览”“关键时刻 ROI 预览”沿用原界面的展开区。此界面以源视频选框为主，**不会默认播放已有的完整 ROI 成品**。工作清单仍保留并连接身份匹配的旧 ROI 文件，选框和保存决定不会覆盖这些文件。

1. 在左侧用状态、视频 ID 或材料类型筛选，再选择视频。
2. 在右侧选择“固定 ROI”或“不裁剪”。用中间的“抽帧时间（可拖动）”定位画面；固定 ROI 时直接拖动或缩放红框，当前红框就是待保存范围。
3. 需要时展开当前帧对照或关键时刻预览，查看原图与裁剪范围。
4. 点击“保存当前决定”保存该视频的范围和备注。此按钮**只保存决定，不生成视频**；需要生成时，另用下方的 `--batch` 命令处理已保存范围。

原界面的审核状态和可见性控件继续显示，但不构成逐标签强制审核门，也不会把已有决定视为当前视频已被人工看过。原视频、原标注表、已有 ROI 文件和历史记录均保留。

## 当前标签与独立审查记录

右侧“已有标签”默认填入当前标注；空值、“否”“无”“无法判断”和历史原值分别保留。无需为每个字段重新选择或为每个视频点击“通过”。标签有问题时，修改对应值，再点击“保存标签审查记录”。原始标注 CSV 始终只读。

标签修改保存到独立的 `label_reviews.json`，绑定视频 ID、源视频摘要、ROI 输出摘要和原标注内容。身份仍匹配时恢复已保存修改；身份变化时保留旧记录，但不自动套用。未保存的标签修改按视频和身份保留为界面草稿；检测到其他页面保存了新版本时，会阻止旧页面覆盖。

“ROI 可用”和工作清单的 `complete` 仅表示媒体结果已提供，**不表示已完成人工画面审核**。旧记录中的请求框可能经过当时 FFmpeg 的色度对齐；清单分别保留请求范围与可还原的实际边界，不把旧像素位置改写成当前精确框。

## 默认输入与输出

所有相对路径按项目根目录解析，与执行命令时的当前目录无关。

| 输入或输出 | 默认路径／行为 | 可选参数 |
| --- | --- | --- |
| 源视频 | `data/videos/`，递归读取，文件名去扩展名作为唯一 ID | `--videos-dir` |
| 已有标注 | `data/annotation-table-full.csv`，可缺失，只读 | `--labels` |
| 当前决定及处理清单 | 输出目录中的 `decisions.json`、`manifest.json`；缺失时从空记录开始 | 随 `--output-dir` |
| 草稿和标签审查记录 | 输出目录中的 `drafts.json`、`label_reviews.json`；按需读取，可缺失 | 随 `--output-dir` |
| 旧决定 | `data/roi/imports/roi_decisions.legacy.json`，可缺失 | `--decisions` |
| 旧结果清单 | `data/roi/imports/media-manifest.legacy.json`，可缺失 | `--existing-manifest` |
| 旧视频 | `data/roi/imports/media/<视频ID>.mp4`，可缺失 | `--existing-media-dir` |
| 已整理的当前结果 | `data/roi/videos/<视频ID>.mp4`，由清单确认身份后读取 | 随 `--output-dir` |
| 输出目录 | `data/roi/` | `--output-dir` |
| 划分记录 | `data/splits/` 下唯一可识别版本自动读取；多个版本须选择 | `--splits-dir` |
| 项目根目录 | 按脚本位置定位 | `--project-root` |

例如处理新视频目录：

```bash
.venv/bin/python script/roi/roi.py --videos-dir data/new-videos --output-dir data/new-roi
```

支持 `.mp4`、`.mov`、`.mkv`、`.avi`、`.m4v`、`.webm`，大小写均可。相同文件名对应多个路径时记录 ID 冲突。浏览器能否播放取决于封装与编码；无法播放原视频时，可用外部播放器对照，界面单帧预览仍可辅助选框。

当前决定优先于可选的旧决定；已有结果也依赖当前清单中保存的输出身份和处理记录。新视频没有决定时仍能进入工作列表，待用户选框或选择全画面后处理。当前项目已将决定和结果整理到当前工作区，`imports/` 不再是当前数据的必需目录。

可选旧决定文件包含 `decisions` 数组，每条以 `source_video_id`、`source_sha256`、`source_resolution`、`mode` 和 `pixel_box` 绑定原视频及范围。旧清单包含 `videos` 数组，每条须有来源与输出的完整摘要、处理方式，以及与实际媒体一致的输出分辨率；帧率与时长如有记录也会核对。仅凭文件名不会认领旧视频。

同一源文件在不同 ffprobe 版本中可能得到不同的标称帧率。仅对沿用旧结果，工具在来源和输出摘要一致、旧来源与旧输出记录自洽、当前帧数和总时长匹配、平均帧率差异不超过与一帧相称的容差时保留旧视频，并提示这项元数据差异。该检查未比较逐帧时间戳；记录不足、明显缺帧或时长变化仍会阻止采用。新生成结果的验收规则不因此放宽。

下表是脚本可能读取或生成的文件，不表示每项都会存在。`videos/` 中是显式整理后的结果；批处理新生成的结果先写入 `media/`。

```text
data/roi/
├── videos/<视频ID>.mp4             # 显式整理后统一摆放的当前结果
├── decisions.json                  # 已保存的裁剪决定及源视频身份
├── manifest.json                   # 源、标签、划分、裁剪结果、身份及状态
├── .roi.lock                       # 并发读写协调锁，不是裁剪结果
├── drafts.json                     # 可选：选框草稿及已转存决定的历史草稿
├── label_reviews.json              # 可选：主动保存的标签审查修改
├── batch-errors.json               # 可选：批处理中发生错误时写入的记录
├── media/<视频ID>/<处理摘要>.mp4     # 可选：按已保存范围新生成的结果
└── imports/                        # 可选：外部提供的旧决定、清单及视频
```

清单保留源视频和输出摘要、媒体信息、旧请求框与实际边界、原有审核及草稿、历次输出。`origin=preserved_legacy` 表示沿用旧视频，`origin=generated` 表示按新范围生成，`origin=imported_generated` 表示接入其他机器按当前源及范围生成并通过检查的结果；`visual_review.required=false` 说明不强制逐视频确认，`status=not_recorded` 不应解释为已被人工看过。`batch-errors.json` 仅在批处理遇到错误时写入；之后成功运行不会自动清除它，不能单凭文件存在判断最近一次运行失败。

## 整理现有 ROI 视频

工作清单中的视频均已提供结果后，可把当前采用的结果统一复制到 `data/roi/videos/<视频ID>.mp4`：

```bash
.venv/bin/python script/roi/organize_videos.py
```

此命令以当前清单的输出路径为准，逐项核对源与输出摘要，再复制文件并统一更新当前引用；不会编码视频。已有同名同内容文件可重复核验，已有不同内容则停止且不覆盖。复制中断时原清单仍保留，重跑可继续利用已核验的文件。所有结果复制并核对完成后才切换清单，之后刷新仍读取 `videos/` 中已关联的结果。

整理操作不会删除已有的 `imports/` 和 `media/` 文件，也保留历史引用、当前决定、草稿及标签审查记录。不要把 `--existing-media-dir` 改指 `videos/`：该参数表示可选的历史导入来源，同名历史视频与当前采用版本可能不同。整理不会凭文件名把历史结果当成当前结果。

### 清理前核查引用与重复文件

当前结果已统一放入 `data/roi/videos/` 后，先运行默认只读预览：

```bash
.venv/bin/python script/roi/prepare_cleanup.py
```

输出 JSON 中，`reference_updates` 列出可以安全改指 `videos/` 的当前或历史输出引用，`duplicate_media` 列出与当前结果摘要相同的历史副本及大小，`retained_media` 列出内容不同或需要核实的文件。只有来源摘要仍匹配、统一结果实际摘要正确，而且引用记录的输出摘要与几何信息均一致，引用才可更新。同名文件本身不构成证据；如存在内容不同的历史版本，会列为保留项。

预览不改工作清单、媒体、决定或标签记录；命令仍使用工作区并发锁，必要时会建立输出目录和 `.roi.lock` 运行锁文件。锁文件不承载裁剪结果，保留它可避免不同进程同时写入。

确认预览后，可仅更新工作清单中的引用：

```bash
.venv/bin/python script/roi/prepare_cleanup.py --apply
```

`--apply` 只写 `manifest.json`，不会删除、移动或重新编码媒体，也不改决定、选框草稿、原始标签或标签审查记录。原路径保留在输出记录的 `historical_locations` 中，标明 `role=historical_provenance`；已有 `organized_from` 也只是历史来源说明，不要求该路径今后仍存在。再次执行时已更新引用不重复添加。

删除文件应在核查这份预览后另行进行，本脚本不提供删除入口。删除同内容副本后，已关联的当前结果仍从 `videos/` 读取；旧导入文件缺失时，只有当前来源、旧决定、旧清单摘要及统一结果实际内容全部对应，才可恢复沿用。缺少这些证据时保留待核实状态，不能靠视频 ID 自动接入。原始输入 `data/videos/` 与 ROI 结果 `data/roi/videos/` 是不同用途的目录。

未来调整范围生成的新版本仍写入 `media/<视频ID>/<处理摘要>.mp4`，以保留原有版本与不覆盖策略；需要再次统一摆放时显式运行整理命令。如果 `videos/` 中已有该 ID 的旧版本而内容不同，命令会拒绝覆盖，应先确定旧版本的归档方式。目录整理和 ROI 媒体可用状态均不表示人工画面审核。

| 状态 | 含义 |
| --- | --- |
| `success` | ROI 媒体可用，可以直接查看 |
| `ready` | 已有画面范围，等待生成 |
| `needs_decision` | 尚无适用范围，或旧范围绑定其他源视频 |
| `needs_verification` | 方向或划分存在待核实问题 |
| `failed` | 输入缺失、摘要不符或处理失败，原因保留 |

划分只读继承 `test.json`、`fold_N_train.json` 和 `fold_N_val.json` 的 `video_ids`；开发集逐折记录 train/val，新视频没有划分不阻塞。测试集产物仍遵守其访问约束。每个源视频只保留一份对应结果，不因三折重复处理。

## 无界面使用

核对输入、连接可用旧结果并写工作清单，不生成视频：

```bash
.venv/bin/python script/roi/roi.py --scan
```

生成所有已保存画面范围、状态为 `ready` 的条目：

```bash
.venv/bin/python script/roi/roi.py --batch
```

扫描会更新 `manifest.json`，不是只读操作。退出码 `0` 表示扫描完成（即使清单仍有待处理项），或批处理后全部 ROI 可用；`2` 表示批处理后仍有待处理项；`1` 表示配置、读取或生成错误。`complete` 不表示人工复核完成，也不表示源标签已被重新评价。

首次列表扫描计算来源和旧结果摘要并读取媒体头信息，后续未变化文件使用状态缓存；处理前针对当前视频重新核对摘要。旧结果沿用不会自动执行整批完整解码，清单如实记录 `full_decode=not_performed`。新生成时针对当前源与输出实际计帧，并缓存与源摘要绑定的计数，避免误用不可靠的文件头帧数。新输出还执行完整解码检查。

新生成采用 H.264、`fast`、CRF 23、`yuv420p`、去音频。固定框使用精确坐标，全画面补边先转 4:4:4 后居中补边，以保证实际位置与记录相同。媒体检查不能证明画面细节无损，查看时发现问题再调整。完整批量编码及长视频处理应在训练机运行。

测试命令：

```bash
.venv/bin/python -m pytest -q script/roi/tests
```

**失效条件：**入口、默认路径、记录格式、结果采用方式、裁剪或媒体验收发生变化时更新本说明；规则或处理身份变化后重新判定受影响结果，不覆盖原视频、标注或旧结果。
