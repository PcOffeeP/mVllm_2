# 第二轮微调回调结果分析报告

## 1. 概述

### 1.1 测试目的

本轮测试用于对比基座模型与第二轮微调模型在视频理解任务上的实际表现，重点验证：

- 微调是否带来格式合规性、分类与定位能力的提升；
- 时间/帧间索引预测是否得到改善；
- 若存在明显问题，定位训练-测试不一致或数据构造层面的根因。

### 1.2 模型说明

| 模型 | 路径/名称 | 说明 |
|------|-----------|------|
| 基座模型（Base） | `models/minicpm-v-4.5` | 未经过微调 |
| 微调版 2（V2） | `sft_interval_3k0_v2_merged` | 基于 Base 进行 SFT 微调 |
| 微调版 1（V1） | — | 已排除；训练时发生过拟合，测试结果不具参考价值 |

### 1.3 测试数据

- **Base 结果文件**：
  - `finetune/results/base_test_results.jsonl`
  - `finetune/results/base_test.jsonl`
- **V2 结果文件**：
  - `finetune/results/test_joint_v2_results.jsonl`
  - `finetune/results/test_joint_v2.jsonl`
- **测试规模**：22 个视频

## 2. Base vs V2 测试结果对比

### 2.1 整体表现（22 视频完整测试集）

| 指标 | Base | V2 |
|------|------|-----|
| schema 合法率 | 12/22 (54.5%) | 21/22 (95.5%) |
| 类型完全正确 | 2/22 (9.1%) | 3/22 (13.6%) |
| `has_fracture` 正确 | 3/22 | 8/22 |
| joint success rate | 0% | 9.09% (2/22) |
| interval hit rate | 0% | 0% |
| midpoint MAE | 17.94s | 15.59s |

### 2.2 解读

- **格式与基础分类**：V2 在 schema 合法率、`has_fracture` 判断等基础维度上相对 Base 有明显提升，说明 SFT 改善了输出结构和部分二分类能力。
- **完全类型正确率**：V2 仍仅 13.6%，说明多分类/组合类任务仍有较大改进空间。
- **时间/帧间索引**：joint success rate、interval hit rate 均未改善，midpoint MAE 虽从 17.94s 降至 15.59s，但绝对值仍高，且 Base 与 V2 的核心错误模式一致。

## 3. 关键发现

### 3.1 V2 有提升的方面

- schema 合法率从 54.5% 提升至 95.5%；
- `has_fracture` 正确数从 3 个提升至 8 个；
- 在格式合规性、是否存在断裂、`location` 等 5 个基本输出维度上均有不同程度改善。

### 3.2 时间/帧间索引未提升的现象

- **interval hit rate 为 0**：Base 与 V2 均未命中真实时间区间；
- **joint success rate 极低**：Base 为 0%，V2 仅 9.09%；
- **系统负偏差**：所有有效样本的预测中点均早于 Ground Truth；
- **预测集中在中段默认值**：V2 有 71.4% 的断裂预测输出 `[4,5]`，Base 也有 66.7%；
- **误差与视频属性高度相关**：误差与 GT 时间、视频长度呈强正相关（r ≈ +0.99）。

## 4. 根因分析（按优先级排序）

### 4.1 训练-测试预处理不一致（主因）

- **训练输入**：子视频（完整视频拷贝 + 3/5/10/20s 聚焦/负样本裁剪片段）。
- **测试输入**：直接读取原始完整视频。
- **采样器不一致**：
  - 训练使用 `MiniCPMVideoPreprocessor`（LLaMA-Factory 路径）采样；
  - 测试使用 `video_loader.py` 独立 pyav 解码采样。
- **证据**：22 条测试日志中，`preprocessing.frames` 与 `preprocessing.actual_timestamps` 均不一致。
- **指纹校验缺失**：测试侧 `processor_fingerprint` 被硬编码为占位字符串 `"subvideos_meta_full"`，未与训练指纹比对。

### 4.2 `fracture_between` 语义错位

- 训练时 `fracture_between: [i, i+1]` 是**子视频局部索引**；
- 测试时却将其直接当成**完整视频索引**映射到秒级时间；
- 导致预测时间区间完全不包含 GT，interval hit rate 为 0。

### 4.3 模型学到的是中间位置默认值

- V2 与 Base 均高度倾向于输出 `[4,5]`，说明模型并未真正学到事件位置，而是依赖中间位置的先验；
- 系统负偏差（预测中点早于 GT）与视频长度、GT 时间高度正相关，进一步说明输出受采样/输入结构影响，而非内容理解。

### 4.4 训练 prompt 与测试 prompt 不一致（次要原因）

- 训练 prompt 仅要求“哪两帧之间”，未明确要求 `[i, i+1]` 格式；
- 训练 prompt 未枚举 `type`/`location` 取值，也未给出合法组合规则；
- 训练使用 `<video>` 占位符，测试使用 `(<image>./</image>)` 重复格式；
- system prompt 处理也可能存在不一致。

### 4.5 评估指标与 prompt 不匹配

- joint 任务以 `pred_time_sec is None` 判为 `time_unparseable`；
- 但 strict_interval prompt 根本不输出 `time` 字段；
- 应改为基于 `pred_time_range_sec` / `pred_time_midpoint_sec` 判断。

## 5. 训练数据质量评估

### 5.1 原始标注质量

- 原始标注与 `video_meta` 时间/帧号一致，标注本身无显著错误。

### 5.2 数据构造瑕疵

- **类别冲突**：`未夹紧` 类别在训练-评估中存在目标冲突；
- **区间分布偏后**：正样本区间分布不均，`[5,6]` 有 341 条，而 `[0,1]` 仅 55 条；
- **边界偏差风险**：53 条样本事件帧恰好落在采样帧上，可能引入边界偏差。

## 6. Prompt 与预处理一致性分析

| 维度 | 训练侧 | 测试侧 | 问题 |
|------|--------|--------|------|
| 视频输入 | 子视频片段 | 原始完整视频 | 不一致 |
| 采样器 | `MiniCPMVideoPreprocessor` | `video_loader.py` pyav | 不一致 |
| 视频占位符 | `<video>` | `(<image>./</image>)` 重复 | 不一致 |
| 索引语义 | 子视频局部 `[i, i+1]` | 完整视频秒级映射 | 不一致 |
| 指纹校验 | 真实 fingerprint | 硬编码 `"subvideos_meta_full"` | 缺失 |
| prompt 枚举 | 未枚举 type/location 合法值 | 可能有更严格要求 | 不一致 |

## 7. 结论

1. V2 在格式合规性和部分基础分类任务上优于 Base，SFT 起到了一定作用。
2. 时间/帧间索引任务未改善，核心问题不在模型容量或标注质量，而在于**训练-测试输入/预处理不一致**以及**索引语义错位**。
3. 模型实际学到了“中间位置默认值”这一虚假先验，导致预测中点系统性地早于 GT，且误差与视频长度/真实时间强相关。
4. prompt、采样器、视频输入格式、评估指标均需与训练侧严格对齐，才能准确评估微调效果。

## 8. 后续修复建议

1. **统一训练-测试采样器**：测试侧使用与训练相同的 `MiniCPMVideoPreprocessor`。
2. **启用真实指纹校验**：测试时计算并比对真实 `processor_fingerprint`，替换硬编码占位字符串。
3. **对齐输入视频**：测试输入视频与训练输入视频一致，或重新生成完整视频到子视频的映射。
4. **对齐训练与测试 prompt**：统一格式要求、占位符、system prompt 与字段枚举。
5. **修复 `未夹紧` 训练-评估冲突**：明确该类别的训练目标与评估标准。
6. **平衡正样本区间分布**：对 `[0,1]` 等少数区间进行过采样或加权。
7. **修正 joint 任务时间失败判定逻辑**：基于 `pred_time_range_sec` / `pred_time_midpoint_sec` 判断，而非缺失的 `time` 字段。
